MongoDB en LAMP

Guía completa para PHP 8.3 en Ubuntu usando PIE y Podman

PHP 8.3 Ubuntu Podman

Esta guía te muestra cómo instalar la extensión oficial de MongoDB para PHP 8.3 en un servidor LAMP (Linux, Apache, MySQL, PHP) sobre Ubuntu, utilizando la nueva herramienta PIE (PHP Installer for Extensions).

Además, incluimos la recomendación de usar MongoDB 7 por compatibilidad con el kernel de Linux, y cómo desplegar MongoDB con Podman para que se inicie automáticamente con el sistema.

1 Instalar PIE (PHP Installer for Extensions)

PIE es el reemplazo oficial de PECL para gestionar extensiones de PHP. Funciona como Composer, pero para extensiones.

Requisitos previos
  • PHP 8.1 o superior (esta guía usa PHP 8.3).
  • Herramientas de compilación (PIE las instalará automáticamente si faltan).
Instalación de PIE

Ejecuta este comando para descargar e instalar PIE en /usr/local/bin/pie:

curl -fL --output /tmp/pie.phar https://github.com/php/pie/releases/latest/download/pie.phar \
  && sudo mv /tmp/pie.phar /usr/local/bin/pie \
  && sudo chmod +x /usr/local/bin/pie
Nota: El comando original incluía una verificación con gh attestation verify, pero si no tienes GitHub CLI instalado, puedes omitirla como se muestra arriba.
Verificar instalación
pie --version

2 Instalar la Extensión de MongoDB con PIE

Una vez que PIE esté instalado, puedes instalar la extensión oficial de MongoDB directamente desde Packagist. 

sudo pie install mongodb/mongodb-extension

Este comando automáticamente:

  • Descarga el código fuente de la extensión
  • La compila para tu versión de PHP
  • La instala en el directorio de extensiones de PHP
Verificar que la extensión se cargó
php -m | grep mongodb

Deberías ver mongodb en la salida. Si no aparece, puede que necesites agregar manualmente extension=mongodb.so a tu php.ini.

Reiniciar PHP-FPM y Apache
sudo systemctl restart php8.3-fpm
sudo systemctl restart apache2

3 Recomendación: Usar MongoDB 7

⚠️ Importante: Compatibilidad con el Kernel

No uses MongoDB 8.x en kernels de Linux 6.19 o superiores. Existe un problema conocido con tcmalloc que impide que MongoDB 8.x arranque correctamente en estos kernels.

Estado de Compatibilidad
Versión de MongoDB Kernel 6.19+ Recomendación
MongoDB 7.0 ✅ Compatible Usar esta versión
MongoDB 8.0.4 ✅ Compatible (excepción) Alternativa válida
MongoDB 8.x (otros) ❌ Incompatible Evitar

Conclusión: Para tu Raspberry Pi con kernel moderno, MongoDB 7.0 es la opción más estable y recomendada. Evitarás caídas y problemas de arranque.

4 Instalar MongoDB 7 con Podman

Podman es una alternativa a Docker que no requiere un daemon y funciona muy bien en Raspberry Pi. Usaremos la imagen oficial mongo:7.0.

Crear un volumen persistente

Esto asegura que los datos no se pierdan al eliminar el contenedor:

podman volume create mongodb_data
Levantar el contenedor de MongoDB 7
podman run -d \
  --name mongodb \
  -p 27017:27017 \
  -v mongodb_data:/data/db \
  docker.io/library/mongo:7.0
Verificar que está corriendo
podman ps

Deberías ver un contenedor llamado mongodb en estado Up.

Conectar con mongosh
mongosh

5 Hacer que MongoDB se Inicie Automáticamente

Tienes dos opciones para que MongoDB arranque con el sistema y se reinicie si falla.

Opción A: Política de Reinicio de Podman (Más Simple)

Si vuelves a crear el contenedor con la política --restart=unless-stopped, Podman lo reiniciará automáticamente incluso después de un reinicio, a menos que lo detengas manualmente. 

# Elimina el contenedor actual si existe
podman rm -f mongodb

# Créalo con la política de reinicio
podman run -d \
  --name mongodb \
  --restart=unless-stopped \
  -p 27017:27017 \
  -v mongodb_data:/data/db \
  docker.io/library/mongo:7.0
Nota: Esta opción funciona bien, pero no ofrece la gestión completa de systemd (logs, dependencias, etc.).
Opción B: Quadlet (Integración con systemd - Recomendado)

Quadlet es la forma moderna de integrar contenedores Podman con systemd. Creas un archivo .container y systemd lo gestiona como un servicio nativo.

Paso 1: Crea el directorio para Quadlets (si no existe):

mkdir -p ~/.config/containers/systemd/

Paso 2: Crea el archivo ~/.config/containers/systemd/mongodb.container con este contenido:

[Unit]
Description=MongoDB 7 Container
After=network-online.target

[Container]
Image=docker.io/library/mongo:7.0
ContainerName=mongodb
PublishPort=27017:27017
Volume=mongodb_data:/data/db

[Service]
Restart=on-failure
RestartSec=5

[Install]
WantedBy=default.target

Paso 3: Recarga systemd e inicia el servicio:

systemctl --user daemon-reload
systemctl --user start mongodb.service

Paso 4: Habilita el inicio automático (importante para que arranque al iniciar sesión):

systemctl --user enable mongodb.service

Paso 5: Si quieres que arranque incluso sin que inicies sesión (para servidores), habilita "lingering":

sudo loginctl enable-linger $USER
Comandos de Gestión con Quadlet
Acción Comando
Iniciar systemctl --user start mongodb
Detener systemctl --user stop mongodb
Reiniciar systemctl --user restart mongodb
Ver estado systemctl --user status mongodb
Ver logs journalctl --user -u mongodb -f
Deshabilitar auto-inicio systemctl --user disable mongodb
Importante: Con Quadlet, el contenedor se llama systemd-mongodb en Podman, pero lo gestionas con systemctl --user. No uses podman stop directamente; usa los comandos de systemctl para evitar conflictos.

6 Verificación Final

Para confirmar que todo funciona:

  1. Verifica que la extensión PHP esté cargada: 
    php -m | grep mongodb
  2. Verifica que MongoDB esté corriendo (con Podman): 
    podman ps
    O si usas Quadlet: 
    systemctl --user status mongodb
  3. Conéctate con mongosh: 
    mongosh
  4. Prueba desde PHP: 
    php -r "var_dump(extension_loaded('mongodb'));"
    Debe devolver bool(true).
