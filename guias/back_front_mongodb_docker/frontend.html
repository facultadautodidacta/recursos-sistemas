Consume una API con Angular

Conecta una aplicación Angular con Laravel, representa los datos de libros y construye una interfaz CRUD con formularios reactivos y Bootstrap 5.

Angular 22.2.3 Bootstrap 5.3.8 HttpClient Docker Compose
Punto de partida: Docker, Angular, Laravel y MongoDB ya están funcionando. La API ya ofrece las operaciones para libros. Este manual se enfoca en cómo Angular consume esa API; no vuelve a explicar cómo construir el backend.

1Entorno y versiones

Este proyecto usa Angular 22.2.3 según el lockfile y Bootstrap 5.3.8. Los paquetes se administran con npm. Desde la raíz del repositorio puedes iniciar los contenedores y revisar que estén activos: 

docker compose up -d
docker compose ps

La aplicación Angular está disponible en http://localhost:4201. Cuando necesites ejecutar npm dentro del contenedor, usa docker compose exec angular.

2Conectar Angular con Laravel

El navegador pide rutas que comienzan con /api. Durante el desarrollo, Angular usa proxy.conf.json para reenviar esas solicitudes al servicio Laravel dentro de la red Docker: 

{
  "/api": {
    "target": "http://laravel:8000",
    "secure": false,
    "changeOrigin": true
  }
}

El flujo es: navegador → servidor de desarrollo Angular → proxy → Laravel. El navegador usa el mismo origen de Angular y el servidor hace la comunicación entre contenedores. Por eso, para este flujo local, no necesitamos poner una URL absoluta de Laravel en el código ni configurar CORS para la llamada del navegador.

Dos contextos de red: el navegador abre Angular por localhost:4201, pero el proxy corre dentro del contenedor Angular y puede llegar a Laravel con el hostname laravel. En producción se configuraría el origen de API según el despliegue; el proxy de desarrollo no es una configuración de producción.

3Instalar y configurar Bootstrap 5

Bootstrap aporta estilos y utilidades de diseño listos para usar. En un esqueleto Angular que aún no lo tenga, instálalo con npm desde el contenedor: 

docker compose exec angular npm install bootstrap

Después registra el CSS en angular.json, dentro de las opciones del build: 

"styles": [
  "node_modules/bootstrap/dist/css/bootstrap.min.css",
  "src/styles.css"
]

La aplicación Angular de este proyecto usa Bootstrap instalado con npm y registrado en angular.json, no mediante CDN. Las clases usadas a continuación son las clases estándar de Bootstrap 5, como las que aparecen en su documentación: container, row, form-control, btn, card y table-responsive.

Esta página del manual es un HTML independiente y carga su propio Bootstrap por CDN para poder mostrarse sin compilar Angular. Eso no cambia cómo la aplicación carga Bootstrap. Para los formularios y tablas del proyecto usamos principalmente sus estilos CSS; no hace falta añadir su JavaScript.

4Definir el modelo TypeScript

Angular CLI también puede crear interfaces. Desde el esqueleto, ejecuta: 

docker compose exec angular npx ng generate interface models/libro model

El comando crea src/app/models/libro.model.ts: el primer argumento indica la carpeta y el nombre, y model agrega ese sufijo al archivo. En este proyecto la interfaz ya está creada; edita ese archivo para que describa los datos que devuelve la API: 

export interface Libro {
  id?: string;
  titulo: string;
  autor: string;
  genero?: string | null;
  anio_publicacion?: number | null;
}
  • id es texto y opcional porque todavía no existe antes de crear el documento.
  • ? indica que una propiedad puede omitirse.
  • | null permite representar un valor vacío que llega como null.
  • interface ayuda a TypeScript durante el desarrollo; no valida el JSON en tiempo de ejecución. La validación real sigue correspondiendo al backend.

5Habilitar HttpClient

Angular ofrece HttpClient para enviar solicitudes HTTP y convertir las respuestas JSON a los tipos que use la aplicación. En una app standalone se habilita con provideHttpClient() en src/app/app.config.ts: 

import { provideHttpClient } from '@angular/common/http';

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes),
    provideHttpClient(),
  ],
};

Este proveedor registra el cliente para que los servicios puedan recibirlo por inyección de dependencias. En este proyecto ya está configurado.

6Generar y programar el servicio HTTP

El servicio centraliza las llamadas al backend para que el componente se enfoque en la interfaz y el estado. Créalo con Angular CLI desde el contenedor: 

docker compose exec angular npx ng generate service services/libro --type=service --injectable --skip-tests

En la versión de Angular de este proyecto, --type=service genera el archivo src/app/services/libro.service.ts y --injectable crea un servicio que puede recibir dependencias mediante inyección de Angular. Se usa --skip-tests porque este recorrido se concentra en conectar la interfaz con la API; el CLI puede generar una especificación de prueba si omites esa opción. En el proyecto actual el servicio ya existe.

La base de la API es relativa: /api/libros. El proxy del paso anterior la reenvía a Laravel. El servicio implementa una función por operación: 

import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable, timeout } from 'rxjs';
import { Libro } from '../models/libro.model';

@Injectable({
  providedIn: 'root'
})
export class LibroService {
  // Esta ruta /api se redirige a Laravel gracias al proxy
  private apiUrl = '/api/libros';

  constructor(private http: HttpClient) {}

  getLibros(): Observable<Libro[]> {
    return this.http.get<Libro[]>(this.apiUrl).pipe(timeout({ first: 10000 }));
  }

  createLibro(libro: Libro): Observable<Libro> {
    return this.http.post<Libro>(this.apiUrl, libro);
  }

  updateLibro(id: string, libro: Libro): Observable<Libro> {
    return this.http.put<Libro>(`${this.apiUrl}/${id}`, libro);
  }

  deleteLibro(id: string): Observable<void> {
    return this.http.delete<void>(`${this.apiUrl}/${id}`);
  }
}

Los genéricos, por ejemplo get<Libro[]>, ayudan a TypeScript a tratar la respuesta como una lista de libros. No convierten ni validan por sí mismos el JSON recibido.

Observable: cada método devuelve un Observable de RxJS. La solicitud HTTP se ejecuta cuando el consumidor se suscribe; por eso el componente usa subscribe() para recibir éxito o error. El GET además tiene un límite de 10 segundos para no dejar la pantalla esperando indefinidamente.

Las llamadas reflejan el contrato de la API: GET obtiene, POST crea, PUT actualiza y DELETE elimina. El identificador de MongoDB se pasa como texto en la ruta.

7Crear el componente CRUD

Primero genera el componente con Angular CLI desde el contenedor: 

docker compose exec angular npx ng generate component components/libro-crud

El CLI crea la carpeta src/app/components/libro-crud y los archivos del componente: TypeScript, plantilla HTML, estilos CSS y una especificación inicial. En Angular 22 la convención del proyecto usa nombres como libro-crud.ts y libro-crud.html, sin el sufijo .component. A partir de esos archivos agregamos la lógica CRUD y el diseño Bootstrap que vemos en los siguientes pasos.

El CLI puede crear también libro-crud.spec.ts. Ese archivo es solo un punto de partida: sus pruebas deben actualizarse para la implementación real del componente. No afecta la ejecución de la aplicación.

Ahora sustituye el contenido de libro-crud.ts por la implementación. El componente standalone declara los módulos que usa su plantilla y recibe el servicio por inyección de dependencias: 

import { Component, OnInit, signal } from '@angular/core';
import { FormBuilder, FormGroup, ReactiveFormsModule, Validators } from '@angular/forms';
import { CommonModule } from '@angular/common';
import { HttpErrorResponse } from '@angular/common/http';
import { TimeoutError } from 'rxjs';
import { Libro } from '../../models/libro.model';
import { LibroService } from '../../services/libro.service';

@Component({
  selector: 'app-libro-crud',
  standalone: true,
  imports: [CommonModule, ReactiveFormsModule],
  templateUrl: './libro-crud.html',
  styleUrls: ['./libro-crud.css']
})
export class LibroCrudComponent implements OnInit {
  libros = signal<Libro[]>([]);
  libroForm: FormGroup;
  editingId = signal<string | null>(null);
  loading = signal(false);
  saving = signal(false);
  errorMessage = signal('');

  constructor(
    private fb: FormBuilder,
    private libroService: LibroService
  ) {
    this.libroForm = this.fb.group({
      titulo: ['', Validators.required],
      autor: ['', Validators.required],
      genero: [''],
      anio_publicacion: [null]
    });
  }

  ngOnInit(): void {
    this.loadLibros();
  }

  loadLibros(): void {
    this.loading.set(true);
    this.errorMessage.set('');
    this.libroService.getLibros().subscribe({
      next: (data) => {
        this.libros.set(data);
        this.loading.set(false);
      },
      error: (err: unknown) => {
        this.errorMessage.set(err instanceof TimeoutError
          ? 'La solicitud tardó más de 10 segundos. Verifica la conexión con el servidor e inténtalo de nuevo.'
          : err instanceof Error
            ? err.message
            : 'No se pudieron cargar los libros.');
        this.loading.set(false);
      }
    });
  }

  onSubmit(): void {
    if (this.libroForm.invalid || this.saving()) {
      this.libroForm.markAllAsTouched();
      return;
    }

    const libroData: Libro = this.libroForm.value;
    const editingId = this.editingId();
    const isEditing = editingId !== null;
    const request = isEditing
      ? this.libroService.updateLibro(editingId, libroData)
      : this.libroService.createLibro(libroData);

    this.saving.set(true);
    this.errorMessage.set('');
    request.subscribe({
      next: (savedLibro) => {
        this.libros.update((libros) => isEditing
          ? libros.map((libro) => libro.id === savedLibro.id ? savedLibro : libro)
          : [...libros, savedLibro]);
        this.resetForm();
        this.saving.set(false);
      },
      error: (err: HttpErrorResponse) => {
        this.errorMessage.set(err.error?.message || err.message || 'No se pudo guardar el libro.');
        this.saving.set(false);
      }
    });
  }

  editLibro(libro: Libro): void {
    this.editingId.set(libro.id!);
    this.libroForm.patchValue({
      titulo: libro.titulo,
      autor: libro.autor,
      genero: libro.genero,
      anio_publicacion: libro.anio_publicacion
    });
  }

  deleteLibro(id: string): void {
    if (confirm('¿Eliminar este libro?')) {
      this.errorMessage.set('');
      this.libroService.deleteLibro(id).subscribe({
        next: () => {
          this.libros.update((libros) => libros.filter((libro) => libro.id !== id));
        },
        error: (err: HttpErrorResponse) => {
          this.errorMessage.set(err.error?.message || err.message || 'No se pudo eliminar el libro.');
        }
      });
    }
  }

  resetForm(): void {
    this.libroForm.reset();
    this.editingId.set(null);
  }
}

loading y saving evitan confundir la carga inicial con el envío del formulario. errorMessage lleva los errores a la plantilla; cuando falla el GET, el código distingue el timeout del resto de errores, mientras que guardar y eliminar muestran el mensaje recibido del servidor si está disponible. Las validaciones del formulario mejoran la experiencia, pero Laravel sigue siendo quien valida de forma definitiva los datos.

8Construir la vista con Bootstrap

La plantilla completa src/app/components/libro-crud/libro-crud.html combina clases Bootstrap con bindings y directivas de Angular: 

<main class="container py-4 py-lg-5">
  <header class="mb-4">
    <h1 class="h2 mb-1">Gestión de Libros</h1>
    <p class="text-body-secondary mb-0">Administra el catálogo de libros.</p>
  </header>

  <div *ngIf="errorMessage()" class="alert alert-danger d-flex align-items-center justify-content-between gap-3" role="alert">
    <span>{{ errorMessage() }}</span>
    <button type="button" class="btn btn-outline-danger btn-sm flex-shrink-0" (click)="loadLibros()" [disabled]="loading()">
      Reintentar
    </button>
  </div>

  <section class="card shadow-sm mb-4" aria-labelledby="form-title">
    <div class="card-body p-3 p-md-4">
      <h2 id="form-title" class="h5 mb-3">{{ editingId() ? 'Editar libro' : 'Agregar libro' }}</h2>
      <form [formGroup]="libroForm" (ngSubmit)="onSubmit()">
        <div class="row g-3">
          <div class="col-12 col-md-6 col-lg-3">
            <label for="titulo" class="form-label">Título <span class="text-danger">*</span></label>
            <input id="titulo" class="form-control" formControlName="titulo" placeholder="Título del libro" required>
          </div>
          <div class="col-12 col-md-6 col-lg-3">
            <label for="autor" class="form-label">Autor <span class="text-danger">*</span></label>
            <input id="autor" class="form-control" formControlName="autor" placeholder="Nombre del autor" required>
          </div>
          <div class="col-12 col-md-6 col-lg-2">
            <label for="genero" class="form-label">Género</label>
            <input id="genero" class="form-control" formControlName="genero" placeholder="Género">
          </div>
          <div class="col-12 col-md-6 col-lg-2">
            <label for="anio_publicacion" class="form-label">Año</label>
            <input id="anio_publicacion" class="form-control" type="number" formControlName="anio_publicacion" placeholder="Año">
          </div>
          <div class="col-12 col-lg-2 d-flex align-items-end gap-2">
            <button type="submit" class="btn flex-grow-1" [class.btn-primary]="!editingId()" [class.btn-warning]="editingId()" [disabled]="saving()">
              {{ saving() ? 'Guardando...' : editingId() ? 'Actualizar' : 'Crear' }}
            </button>
            <button *ngIf="editingId()" type="button" class="btn btn-outline-secondary" (click)="resetForm()">
              Cancelar
            </button>
          </div>
        </div>
      </form>
    </div>
  </section>

  <section class="card shadow-sm" aria-labelledby="catalog-title">
    <div class="card-header bg-body d-flex align-items-center justify-content-between">
      <h2 id="catalog-title" class="h5 mb-0">Catálogo</h2>
      <span class="badge text-bg-secondary">{{ libros().length }}</span>
    </div>
    <div class="table-responsive">
      <table class="table table-striped table-hover align-middle mb-0">
        <thead class="table-light">
          <tr>
            <th scope="col">ID</th>
            <th scope="col">Título</th>
            <th scope="col">Autor</th>
            <th scope="col">Género</th>
            <th scope="col">Año</th>
            <th scope="col" class="text-end">Acciones</th>
          </tr>
        </thead>
        <tbody>
          <tr *ngIf="loading()">
            <td colspan="6" class="text-center text-body-secondary py-4">Cargando libros...</td>
          </tr>
          <tr *ngIf="!loading() && libros().length === 0">
            <td colspan="6" class="text-center text-body-secondary py-4">No hay libros registrados.</td>
          </tr>
          <tr *ngFor="let libro of libros()">
            <td><span class="font-monospace small">{{ libro.id }}</span></td>
            <td class="fw-medium">{{ libro.titulo }}</td>
            <td>{{ libro.autor }}</td>
            <td>{{ libro.genero || '-' }}</td>
            <td>{{ libro.anio_publicacion || '-' }}</td>
            <td>
              <div class="d-flex justify-content-end gap-2">
                <button type="button" class="btn btn-outline-warning btn-sm" (click)="editLibro(libro)">Editar</button>
                <button type="button" class="btn btn-outline-danger btn-sm" (click)="deleteLibro(libro.id!)">Eliminar</button>
              </div>
            </td>
          </tr>
        </tbody>
      </table>
    </div>
  </section>
</main>

La tabla usa *ngFor para mostrar cada libro y estados condicionales para indicar carga o lista vacía. Las clases row, col-12 y col-md-6 ajustan el formulario al ancho de pantalla; table-responsive permite desplazar la tabla horizontalmente en dispositivos pequeños.

El color del botón principal cambia durante la edición con binding de clases: primario al crear y amarillo al actualizar. Mensajes de error aparecen como alertas para que el usuario entienda si falló una solicitud.

Buena práctica: usa etiquetas label asociadas a sus inputs y botones con texto descriptivo. Bootstrap da estilo; las directivas y bindings de Angular conectan la vista con el estado y las acciones.

9Mostrar el componente

La aplicación principal importa el componente standalone y lo monta en la plantilla raíz. En app.ts se declara: 

imports: [RouterOutlet, LibroCrudComponent]

Y app.html lo muestra usando el selector definido en el componente: 

<app-libro-crud></app-libro-crud>

Así Angular crea el CRUD al cargar la aplicación; no se necesita una ruta adicional para esta única pantalla.

10Probar el flujo completo

Abre http://localhost:4201 y recorre las operaciones desde la interfaz:

  1. Comprueba que la lista cargue y que desaparezca el indicador de carga.
  2. Crea un libro con título y autor; verifica que aparezca en la tabla.
  3. Intenta enviar el formulario sin título o autor y observa la validación.
  4. Selecciona Editar, cambia un campo, guarda y confirma el cambio en la tabla.
  5. Elimina un libro y confirma que desaparezca.
  6. Revisa la pestaña Network del navegador para ver la URL, el método HTTP, el estado y el JSON de cada petición.

Si las peticiones fallan, revisa que Laravel y MongoDB estén activos, que el proxy tenga como destino http://laravel:8000 y que las rutas API respondan. Para identificar el problema, compara el mensaje de la interfaz con el estado y la respuesta de red.

Idea clave: Angular presenta y recoge datos; el servicio HTTP los transporta; Laravel valida y aplica las reglas del negocio; MongoDB los persiste. Cada capa tiene una responsabilidad diferente.
