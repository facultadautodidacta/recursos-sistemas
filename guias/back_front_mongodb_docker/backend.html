Construye una API de libros

Desde un esqueleto Laravel que corre en Docker hasta una API REST con MongoDB, validación separada y documentación interactiva con Scramble.

Laravel 13 MongoDB Docker Compose Scramble
Supuesto del tutorial: Docker Compose ya está configurado y los servicios Laravel, Angular y MongoDB arrancan. Aquí nos enfocamos en el backend; no vamos a crear el proyecto ni a explicar la configuración inicial de Angular.

1Preparar el entorno Docker

Los comandos de Laravel se ejecutan dentro del servicio laravel. Desde la raíz del repositorio, levanta los servicios y confirma sus nombres: 

docker compose up -d
docker compose ps

Para ejecutar Artisan, Composer o PHP dentro del contenedor, usamos docker compose exec: 

docker compose exec laravel php artisan --version
docker compose exec laravel composer --version
¿Por qué no usar localhost para MongoDB? Dentro del contenedor Laravel, localhost apunta al propio contenedor. Docker Compose provee DNS interno, por lo que el host de MongoDB es el nombre del servicio: mongo.

2Habilitar las rutas de API

Desde la raíz del proyecto, ejecuta el instalador de Laravel dentro del contenedor: 

docker compose exec laravel php artisan install:api

Este comando instala el soporte API de Laravel y crea routes/api.php. Las rutas que agregues ahí quedan bajo el prefijo /api. En el proyecto actual este paso ya está hecho; se muestra para documentar cómo partir desde el esqueleto.

3Conectar Laravel con MongoDB

Laravel necesita el driver de MongoDB para PHP y el paquete de integración con Eloquent. En un proyecto que aún no los tenga, instala el paquete dentro del contenedor: 

docker compose exec laravel composer require mongodb/laravel-mongodb

La imagen PHP también debe tener habilitada la extensión mongodb. Si se agrega o modifica en backend/Dockerfile, reconstruye el servicio: 

docker compose build laravel
docker compose up -d laravel

Variables de entorno

En backend/.env, configura Laravel para usar la conexión MongoDB. Sustituye los marcadores de usuario y contraseña por los valores configurados para el servicio Mongo de tu Compose: 

DB_CONNECTION=mongodb
MONGODB_URI=mongodb://USUARIO_MONGO:CONTRASENA_MONGO@mongo:27017/laravel_app?authSource=admin
MONGODB_DATABASE=laravel_app

Si la contraseña contiene caracteres reservados para una URL, codifícala antes de incluirla en la URI.

En config/database.php, define la conexión que consume esas variables: 

'default' => env('DB_CONNECTION', 'mongodb'),

'connections' => [
    // Otras conexiones...
    'mongodb' => [
        'driver' => 'mongodb',
        'dsn' => env('MONGODB_URI', 'mongodb://localhost:27017'),
        'database' => env('MONGODB_DATABASE', 'laravel_app'),
    ],
],
Importante sobre Docker Compose: el Compose actual también declara MONGODB_URI y MONGODB_DATABASE en environment. Las variables inyectadas por Compose tienen prioridad sobre las del .env de Laravel. Mantén ambos valores sincronizados o elimina esas entradas de environment para que Laravel lea backend/.env. No uses localhost como host de Mongo desde Laravel: usa mongo.
Las credenciales de ejemplo son únicamente para desarrollo local. No uses contraseñas reales en el manual ni subas secretos a Git.

4Crear el modelo y la migración

Genera ambos archivos desde el contenedor Laravel:

docker compose exec laravel php artisan make:model Libro -m

La opción -m es la abreviatura de --migration e indica que Artisan también debe crear el archivo de migración junto con el modelo.

El modelo usa la clase de Eloquent del paquete MongoDB, identifica la colección y permite asignar únicamente los campos incluidos en $fillable: 

<?php

namespace App\Models;

use MongoDB\Laravel\Eloquent\Model;

class Libro extends Model
{
    protected $connection = 'mongodb';
    protected $collection = 'libros';

    protected $fillable = [
        'titulo',
        'autor',
        'genero',
        'anio_publicacion',
    ];
}

En la migración, define los campos que la aplicación espera almacenar: 

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        Schema::create('libros', function (Blueprint $table) {
            $table->id();
            $table->string('titulo');
            $table->string('autor');
            $table->string('genero')->nullable();
            $table->integer('anio_publicacion')->nullable();
            $table->timestamps();
        });
    }

    public function down(): void
    {
        Schema::dropIfExists('libros');
    }
};

MongoDB no exige un esquema relacional rígido; aun así, las migraciones permiten versionar cambios de colecciones e índices y repetirlos en otros entornos. Ejecuta la migración con la conexión MongoDB configurada: 

docker compose exec laravel php artisan migrate

5Definir los endpoints

Cada ruta conecta un método HTTP y una URL con una acción del controlador. En routes/api.php, importa el controlador y declara las cinco operaciones: 

<?php

use App\Http\Controllers\Api\LibroController;
use Illuminate\Support\Facades\Route;

Route::get('/libros', [LibroController::class, 'index']);
Route::post('/libros', [LibroController::class, 'store']);
Route::get('/libros/{id}', [LibroController::class, 'show']);
Route::put('/libros/{id}', [LibroController::class, 'update']);
Route::delete('/libros/{id}', [LibroController::class, 'destroy']);
Método y rutaAcciónPropósito
GET /api/librosindexListar libros.
POST /api/librosstoreCrear un libro.
GET /api/libros/{id}showConsultar un libro.
PUT /api/libros/{id}updateActualizar un libro.
DELETE /api/libros/{id}destroyEliminar un libro.
PUT o PATCH: en este tutorial las reglas de actualización permiten enviar solo algunos campos, lo que es una actualización parcial. Semánticamente, PATCH suele expresar mejor ese comportamiento. Si eliges PATCH, cambia la ruta a Route::patch y usa PATCH también en Scramble y en las peticiones de prueba. Si mantienes la ruta existente, el ejemplo usa PUT y conserva las reglas actuales.

6Separar validaciones con Form Requests

Los Form Requests agrupan reglas de entrada fuera del controlador. Laravel valida antes de ejecutar la acción y Scramble puede leer las reglas para describir el cuerpo esperado y los errores de validación.

Request para crear

docker compose exec laravel php artisan make:request StoreLibroRequest
<?php

namespace App\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;

class StoreLibroRequest extends FormRequest
{
    public function authorize(): bool
    {
        return true;
    }

    public function rules(): array
    {
        return [
            'titulo' => 'required|string|max:255',
            'autor' => 'required|string|max:255',
            'genero' => 'nullable|string|max:255',
            'anio_publicacion' => 'nullable|integer',
        ];
    }
}

Request para actualizar

docker compose exec laravel php artisan make:request UpdateLibroRequest
<?php

namespace App\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;

class UpdateLibroRequest extends FormRequest
{
    public function authorize(): bool
    {
        return true;
    }

    public function rules(): array
    {
        return [
            'titulo' => 'string|max:255',
            'autor' => 'string|max:255',
            'genero' => 'nullable|string|max:255',
            'anio_publicacion' => 'nullable|integer',
        ];
    }
}
  • required: el campo debe venir al crear.
  • nullable: puede enviarse como null.
  • Sin required: al actualizar, el campo puede omitirse.
  • authorize() devuelve true porque este tutorial no añade autenticación ni autorización.

7Implementar el controlador

Crea app/Http/Controllers/Api/LibroController.php. Cada acción cumple una sola operación, toma entradas validadas cuando corresponde y responde con un código HTTP apropiado. 

docker compose exec laravel php artisan make:controller Api/LibroController
<?php

namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use App\Http\Requests\StoreLibroRequest;
use App\Http\Requests\UpdateLibroRequest;
use App\Models\Libro;

class LibroController extends Controller
{
    public function index()
    {
        return response()->json(Libro::all(), 200);
    }

    public function store(StoreLibroRequest $request)
    {
        $libro = Libro::create($request->validated());

        return response()->json($libro, 201);
    }

    public function show(string $id)
    {
        return response()->json(Libro::findOrFail($id), 200);
    }

    public function update(UpdateLibroRequest $request, string $id)
    {
        $libro = Libro::findOrFail($id);
        $libro->update($request->validated());

        return response()->json($libro, 200);
    }

    public function destroy(string $id)
    {
        $libro = Libro::findOrFail($id);
        $libro->delete();

        return response()->json(null, 204);
    }
}
Respuestas comunes: 200 indica una consulta o actualización exitosa; 201, una creación; 204, una eliminación sin cuerpo; 404, un ID que no encuentra un documento; 422, datos que no pasan la validación. findOrFail hace que Laravel genere el 404 cuando no encuentra el libro.

Los IDs de MongoDB se documentan como cadenas. No los tipamos como enteros porque no son IDs autoincrementales SQL.

8Documentar con Scramble

Scramble genera documentación OpenAPI leyendo las rutas, el código y las reglas de validación. Instálalo dentro del servicio Laravel: 

docker compose exec laravel composer require dedoc/scramble
docker compose exec laravel php artisan vendor:publish --tag=scramble-config

No es obligatorio publicar la configuración si sus valores por defecto sirven. Añade al controlador títulos y descripciones cortas cuando quieras explicar el propósito de cada operación:

Importa el atributo y colócalo inmediatamente antes de cada método. Estas descripciones cortas reflejan lo que hacen las acciones: 

use Dedoc\Scramble\Attributes\Endpoint;

#[Endpoint(title: 'Listar libros', description: 'Devuelve todos los libros registrados.')]
public function index()

#[Endpoint(title: 'Crear libro', description: 'Crea un libro con los datos validados.')]
public function store(StoreLibroRequest $request)

#[Endpoint(title: 'Consultar libro', description: 'Devuelve el libro identificado por su ID.')]
public function show(string $id)

#[Endpoint(title: 'Actualizar libro', description: 'Actualiza el libro con los campos enviados.')]
public function update(UpdateLibroRequest $request, string $id)

#[Endpoint(title: 'Eliminar libro', description: 'Elimina el libro identificado por su ID.')]
public function destroy(string $id)

El bloque muestra solo los atributos y las firmas: conserva los cuerpos que ya implementaste en el controlador. No necesitas repetir en la descripción lo que Scramble ya infiere: ruta, método, parámetro id y campos que salen de los Form Requests. El tipo de $id puede expresarse como string; su descripción solo hace falta si quieres aclarar su significado.

Confirma que Scramble detecta las rutas y exporta el documento OpenAPI:

docker compose exec laravel php artisan route:list --path=docs
docker compose exec laravel php artisan scramble:export --stdout

En este proyecto, la interfaz está en http://localhost:8000/docs/api y el documento OpenAPI en http://localhost:8000/docs/api.json. Si cambias la configuración de Scramble, verifica de nuevo las rutas reales.

9Probar los endpoints

Abre la documentación interactiva de Scramble y usa Try it out para enviar solicitudes y ver las respuestas. Como alternativa reproducible desde una terminal del host, usa curl. El puerto publicado por Compose es el 8000.

Crear un libro · POST /api/libros

curl -i -X POST http://localhost:8000/api/libros \
  -H 'Accept: application/json' \
  -H 'Content-Type: application/json' \
  -d '{
    "titulo": "El principito",
    "autor": "Antoine de Saint-Exupéry",
    "genero": "Fábula",
    "anio_publicacion": 1943
  }'

Copia el id de la respuesta para las peticiones que consultan, actualizan o eliminan un libro.

Listar libros · GET /api/libros

curl -i -H 'Accept: application/json' \
  http://localhost:8000/api/libros

Consultar un libro · GET /api/libros/{id}

curl -i -H 'Accept: application/json' \
  http://localhost:8000/api/libros/PEGA_AQUI_EL_ID

Actualizar un libro · PUT /api/libros/{id}

curl -i -X PUT http://localhost:8000/api/libros/PEGA_AQUI_EL_ID \
  -H 'Accept: application/json' \
  -H 'Content-Type: application/json' \
  -d '{"genero":"Literatura infantil"}'

Eliminar un libro · DELETE /api/libros/{id}

curl -i -X DELETE \
  -H 'Accept: application/json' \
  http://localhost:8000/api/libros/PEGA_AQUI_EL_ID

Verificar la validación · POST /api/libros

curl -i -X POST http://localhost:8000/api/libros \
  -H 'Accept: application/json' \
  -H 'Content-Type: application/json' \
  -d '{"titulo":""}'

Como falta el autor y el título no es válido, Laravel debe responder con 422 Unprocessable Content y detalles de los campos que fallaron.

Qué revisar: estado HTTP, JSON recibido, persistencia del registro, validación y respuesta al consultar un ID inexistente. Scramble sirve para explorar y enviar peticiones, pero la documentación por sí sola no demuestra que todos los casos se comporten bien: ejecútalos en la interfaz o con curl.

10Qué dejar para una siguiente etapa

  • Autenticación y autorización: proteger operaciones si la API deja de ser pública.
  • Paginación: evitar devolver todos los libros cuando la colección crezca.
  • API Resources: controlar explícitamente el formato JSON de las respuestas.
  • Pruebas automatizadas: complementar las pruebas manuales con una verificación repetible.
  • Despliegue seguro: mover credenciales a secretos del entorno y desactivar el modo debug.
