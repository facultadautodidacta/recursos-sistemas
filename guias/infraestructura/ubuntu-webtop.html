Guía de Instalación de Ubuntu Webtop

Ejecuta un escritorio Ubuntu completo dentro de un contenedor Docker y accede a él desde tu navegador.

¿Qué es Ubuntu Webtop?

Webtop es una solución que permite ejecutar un entorno de escritorio completo de Ubuntu dentro de un contenedor Docker y acceder a él a través de un navegador web. La implementación más popular es la imagen mantenida por LinuxServer.io.

No necesitas instalar un entorno gráfico pesado en tu servidor: solo Docker y un navegador.

Requisitos previos

Sistema

Ubuntu 24.04 (u otra distro Linux compatible con Docker).

Docker

Docker Engine y Docker Compose Plugin (V2).

Recursos

Mínimo 2 GB de RAM (4 GB recomendado), 5 GB de disco y CPU de doble núcleo.

Puertos

Dos puertos libres (ej. 3000 HTTP y 3001 HTTPS).

Paso 0: Verificar e instalar Docker / Docker Compose

0.1
Verificar si Docker y Docker Compose ya están instalados

Ejecuta los siguientes comandos para comprobar. Si ambos muestran un número de versión, puedes omitir la sección 0.2.

terminalbash
docker --version
docker compose version

Salida esperada: Docker version 24.x.x y Docker Compose version v2.x.x.

0.2
Instalar Docker y Docker Compose (sistemas basados en Debian / Ubuntu)
Aplicable a Ubuntu, Debian y derivadas (Linux Mint, Pop!_OS, etc.). La instalación desde el repositorio oficial incluye automáticamente el plugin docker-compose-plugin.

Si la verificación falló, ejecuta los siguientes comandos en orden:

instalar-docker.shbash
# 1. Actualizar e instalar dependencias básicas
sudo apt update
sudo apt install ca-certificates curl

# 2. Añadir la clave GPG oficial de Docker
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# 3. Añadir el repositorio APT de Docker
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update

# 4. Instalar Docker Engine y Docker Compose plugin
sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Después de la instalación, verifica nuevamente:

verificar.shbash
sudo systemctl status docker
docker compose version

Si aparece active (running), Docker se inició correctamente.

Pasos de instalación de Webtop (Docker Compose)

1
Crear el directorio de trabajo
terminalbash
mkdir -p ~/webtop/config
cd ~/webtop
2
Crear el archivo docker-compose.yml

Crea el archivo y pega el siguiente contenido (ejemplo con escritorio ubuntu-xfce):

docker-compose.ymlyaml
services:
  webtop:
    image: lscr.io/linuxserver/webtop:ubuntu-xfce
    container_name: webtop
    security_opt:
      - seccomp:unconfined
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=Asia/Shanghai
      - CUSTOM_USER=tu_nombre_de_usuario
      - PASSWORD=tu_contraseña
    volumes:
      - ./config:/config
    ports:
      - 3000:3000
      - 3001:3001
    shm_size: "1gb"
    restart: unless-stopped
Importante: Modifica PUID / PGID (consulta con id -u / id -g) y establece una contraseña segura.
3
Iniciar el contenedor
terminalbash
docker compose up -d

La primera ejecución descargará la imagen, puede tardar varios minutos.

4
Acceder al escritorio

Abre el navegador y visita:

url.txttext
https://<IP_de_tu_servidor_Ubuntu>:3001
Es HTTPS. Acepta la advertencia del certificado e ingresa el usuario y contraseña configurados.

Gestión del contenedor Webtop

Una vez desplegado, es posible que necesites revisar su estado, detenerlo para liberar recursos, reiniciarlo tras un cambio de configuración o eliminarlo por completo. Aquí tienes los comandos esenciales, todos ejecutados desde el directorio donde está el docker-compose.yml (es decir, ~/webtop).

Ver el estado del contenedor

Comprueba si está en ejecución, su salud, puertos y uso de recursos.

estado.shbash
# Estado resumido de los servicios del compose
docker compose ps

# Estado detallado del contenedor "webtop"
docker inspect --format='{{.State.Status}}' webtop

# Uso de recursos en tiempo real (CPU, RAM, red)
docker stats webtop
Ver los logs

Útil para diagnosticar errores de arranque o problemas de acceso.

logs.shbash
# Ver logs en tiempo real
docker compose logs -f webtop

# Ver las últimas 100 líneas y salir
docker compose logs --tail=100 webtop
Detener el contenedor

Detiene el servicio sin eliminarlo. Los datos en ./config se conservan.

detener.shbash
docker compose stop
Reiniciar o volver a arrancar

Reinicia el servicio (por ejemplo, tras editar el docker-compose.yml).

reiniciar.shbash
# Reiniciar el servicio
docker compose restart webtop

# O simplemente volver a arrancarlo si estaba detenido
docker compose start
Eliminar el contenedor

Detiene y elimina el contenedor y la red creada por Compose. Los datos en ./config no se borran.

eliminar.shbash
docker compose down
Eliminación completa (con imagen)

Además de eliminar el contenedor, borra la imagen descargada (útil para liberar espacio o forzar una actualización limpia).

eliminar-todo.shbash
docker compose down --rmi all

# Si además quieres borrar los datos persistidos manualmente:
# rm -rf ~/webtop/config
La segunda línea es irreversible: elimina toda la configuración y archivos del escritorio guardados en ./config.
Consejo: si solo quieres actualizar la imagen a la última versión, ejecuta docker compose pull y luego docker compose up -d. Docker recreará el contenedor con la nueva imagen manteniendo tus datos en ./config.

¿Es multiplataforma?

Sí.

  • Lado del servidor: Cualquier dispositivo que pueda ejecutar Docker (Ubuntu, Debian, VPS, NAS ARM, etc.) puede ejecutar Webtop. La imagen oficial soporta amd64 y arm64.
  • Lado del cliente: No requiere instalar software cliente. Windows, macOS, Linux, ChromeOS, iPad o tablet Android, cualquier dispositivo con un navegador moderno puede conectarse.
Recordatorio de seguridad

Por defecto el contenedor no tiene contraseña. Asegúrate de configurar CUSTOM_USER y PASSWORD, y no lo expongas directamente a Internet pública sin protección. Se recomienda usar solo en red local o a través de VPN.
