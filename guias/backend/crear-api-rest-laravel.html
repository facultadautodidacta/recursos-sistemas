0. Crear el proyecto Laravel (Si es nuevo)

Paso 0.1: Crear proyecto con Composer

composer create-project laravel/laravel nombre-proyecto
  • Para qué: Crea un nuevo proyecto Laravel desde cero
  • nombre-proyecto: Cambia esto por el nombre de tu proyecto
  • Ejemplo: composer create-project laravel/laravel api1

Paso 0.2: Entrar al directorio del proyecto

cd nombre-proyecto

Paso 0.3: Configurar base de datos

Abrir el archivo .env y configurar conexión a base de datos:

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=nombre_de_tu_base_de_datos
DB_USERNAME=tu_usuario
DB_PASSWORD=tu_contraseña

Paso 0.4: Crear la migración de libros

php artisan make:migration create_libros_table

Abrir database/migrations/XXXX_XX_XX_XXXXXX_create_libros_table.php y definir los campos:

public function up(): void
{
    Schema::create('libros', function (Blueprint $table) {
        $table->id();
        $table->string('titulo');
        $table->string('autor');
        $table->string('genero')->nullable();
        $table->integer('anio_publicacion')->nullable();
        $table->timestamps();
    });
}

Paso 0.5: Ejecutar las migraciones

php artisan migrate
  • Para qué: Crea las tablas en la base de datos

1. Diferencia entre routes/web.php y routes/api.php

routes/web.php

  • Para qué: Rutas para páginas web (HTML)
  • Usa: Sesiones, cookies, CSRF protection
  • Retorna: Vistas (Blade templates)
  • Ejemplo: Rutas para tu sitio web tradicional
  • URL: http://localhost:8000/ruta

routes/api.php

  • Para qué: Rutas para APIs (JSON)
  • Usa: Sin sesiones, sin cookies, sin CSRF
  • Retorna: JSON (datos)
  • Ejemplo: Endpoints para aplicaciones móviles, frontend separado (React, Vue, Angular)
  • URL: http://localhost:8000/api/ruta (prefijo /api automático)

Crear soporte para API en Laravel 11

⚠️ Importante: Laravel 11 ya NO incluye routes/api.php por defecto. Debes instalarlo:

php artisan install:api
  • Para qué: Crea el archivo routes/api.php y configura todo automáticamente
  • Qué hace:
    • Crea routes/api.php
    • Agrega el prefijo /api a todas las rutas de API
    • Configura middleware para APIs
    • Instala Laravel Sanctum (autenticación de APIs)

2. Crear el Modelo Libro

php artisan make:model Libro

Abrir app/Models/Libro.php y definir $fillable con los campos que se pueden llenar masivamente:

<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class Libro extends Model
{
    // Campos que se pueden llenar masivamente
    protected $fillable = [
        'titulo',
        'autor',
        'genero',
        'anio_publicacion'
    ];
}
  • Para qué: Permite usar Libro::create() sin errores de asignación masiva

3. Crear el Controlador API

php artisan make:controller Api/LibroController
  • Para qué: Crea el controlador en app/Http/Controllers/Api/LibroController.php
  • Api/: Crea una carpeta Api para organizar los controladores de la API

4. Definir rutas en routes/api.php

⚠️ IMPORTANTE: Agregar el use del controlador al inicio del archivo:

<?php

use Illuminate\Support\Facades\Route;
use App\Http\Controllers\Api\LibroController;

Luego agregar las rutas:

GET Ruta 1 - Listar todos los libros

Route::get('/libros', [LibroController::class, 'index']);
  • URL: GET /api/libros
  • Para qué: Obtener listado completo de libros

POST Ruta 2 - Crear un libro

Route::post('/libros', [LibroController::class, 'store']);
  • URL: POST /api/libros
  • Para qué: Crear un nuevo libro en la base de datos

GET Ruta 3 - Mostrar un libro específico

Route::get('/libros/{id}', [LibroController::class, 'show']);
  • URL: GET /api/libros/1
  • Para qué: Obtener detalles de un libro específico

PUT Ruta 4 - Actualizar un libro

Route::put('/libros/{id}', [LibroController::class, 'update']);
  • URL: PUT /api/libros/1
  • Para qué: Modificar datos de un libro existente

DELETE Ruta 5 - Eliminar un libro

Route::delete('/libros/{id}', [LibroController::class, 'destroy']);
  • URL: DELETE /api/libros/1
  • Para qué: Eliminar un libro de la base de datos

📝 Nota: Todas las URLs tienen el prefijo /api porque están en routes/api.php

5. Implementar métodos en el controlador

Archivo completo: app/Http/Controllers/Api/LibroController.php

<?php

namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use App\Models\Libro;
use Illuminate\Http\Request;

class LibroController extends Controller
{
    // Aquí van todos los métodos
}

Método index() - Listar todos

/**
 * Obtiene todos los libros de la base de datos
 * 
 * Para qué: Mostrar listado completo de libros
 * 
 * @return \Illuminate\Http\JsonResponse
 * 
 * Libro::all() → Trae todos los registros de la tabla libros
 * response()->json() → Convierte los datos a formato JSON
 * 200 → Código de estado HTTP que significa "OK - Todo bien, solicitud exitosa"
 *       Se usa cuando la operación de consulta fue exitosa
 */
public function index()
{
    $libros = Libro::all(); // Obtiene todos los libros
    return response()->json($libros, 200); // Retorna JSON con código 200 (OK)
}

Método store() - Crear nuevo

/**
 * Crea un nuevo libro en la base de datos
 * 
 * Para qué: Guardar un libro nuevo cuando el usuario envía datos
 * 
 * @param \Illuminate\Http\Request $request
 * @return \Illuminate\Http\JsonResponse
 * 
 * $request->validate() → Valida que los datos cumplan las reglas
 * 'required' → Campo obligatorio, debe venir en la petición
 * 'string' → Debe ser texto
 * 'integer' → Debe ser número entero
 * 'nullable' → Campo opcional, puede venir vacío
 * 'max:255' → Máximo 255 caracteres
 * Libro::create() → Inserta el nuevo registro en la base de datos
 * 201 → Código de estado HTTP que significa "Created - Recurso creado con éxito"
 *       Se usa cuando se crea algo nuevo en la base de datos
 */
public function store(Request $request)
{
    // Valida los datos recibidos (según tu migración)
    $validated = $request->validate([
        'titulo' => 'required|string|max:255',      // Título obligatorio
        'autor' => 'required|string|max:255',       // Autor obligatorio
        'genero' => 'nullable|string|max:255',      // Género opcional
        'anio_publicacion' => 'nullable|integer',   // Año opcional, debe ser número
    ]);
    
    // Crea el libro en la base de datos
    $libro = Libro::create($validated);
    
    // Retorna el libro creado con código 201 (Created)
    return response()->json($libro, 201);
}

Método show() - Mostrar uno

/**
 * Muestra un libro específico por su ID
 * 
 * Para qué: Ver los detalles completos de un libro en particular
 * 
 * @param int $id
 * @return \Illuminate\Http\JsonResponse
 * 
 * findOrFail($id) → "Encuentra o falla"
 *   - Busca el registro por ID
 *   - Si lo encuentra: lo retorna
 *   - Si NO existe: lanza automáticamente error 404
 * 200 → Código de estado HTTP que significa "OK - Todo bien"
 *       Se usa cuando encontramos y retornamos el recurso correctamente
 */
public function show($id)
{
    // Busca el libro por ID, si no existe retorna error 404 automáticamente
    $libro = Libro::findOrFail($id);
    
    // Retorna el libro encontrado con código 200 (OK)
    return response()->json($libro, 200);
}

Método update() - Actualizar

/**
 * Actualiza un libro existente
 * 
 * Para qué: Modificar los datos de un libro que ya existe
 * 
 * @param \Illuminate\Http\Request $request
 * @param int $id
 * @return \Illuminate\Http\JsonResponse
 * 
 * findOrFail($id) → Busca el libro, si no existe retorna 404
 * $libro->update() → Actualiza los campos en la base de datos
 * Validaciones sin 'required' → Los campos son opcionales al actualizar
 *   (puedes actualizar solo el título sin enviar el autor, por ejemplo)
 * 200 → Código de estado HTTP que significa "OK - Actualización exitosa"
 *       Se usa cuando modificamos un recurso correctamente
 */
public function update(Request $request, $id)
{
    // Busca el libro, si no existe retorna 404
    $libro = Libro::findOrFail($id);
    
    // Valida los datos (todos opcionales porque puedes actualizar solo algunos campos)
    $validated = $request->validate([
        'titulo' => 'string|max:255',           // Título opcional
        'autor' => 'string|max:255',            // Autor opcional
        'genero' => 'nullable|string|max:255',  // Género opcional
        'anio_publicacion' => 'nullable|integer', // Año opcional
    ]);
    
    // Actualiza el libro con los nuevos datos
    $libro->update($validated);
    
    // Retorna el libro actualizado con código 200 (OK)
    return response()->json($libro, 200);
}

Método destroy() - Eliminar

/**
 * Elimina un libro de la base de datos
 * 
 * Para qué: Borrar permanentemente un libro
 * 
 * @param int $id
 * @return \Illuminate\Http\JsonResponse
 * 
 * findOrFail($id) → Busca el libro, si no existe retorna 404
 * $libro->delete() → Elimina el registro de la base de datos
 * 204 → Código de estado HTTP que significa "No Content - Sin contenido"
 *       Se usa cuando eliminamos algo exitosamente
 *       No hay contenido que retornar porque el recurso ya no existe
 */
public function destroy($id)
{
    // Busca el libro, si no existe retorna 404
    $libro = Libro::findOrFail($id);
    
    // Elimina el libro de la base de datos
    $libro->delete();
    
    // Retorna respuesta vacía con código 204 (No Content)
    return response()->json(null, 204);
}

6. Códigos HTTP explicados - Para qué sirve cada uno

200 (OK)

  • Para qué: Decir "todo salió bien"
  • Cuándo: Al consultar o actualizar datos exitosamente
  • Ejemplo: GET libros, GET libro/1, PUT libro/1

201 (Created)

  • Para qué: Decir "se creó algo nuevo correctamente"
  • Cuándo: Al crear un nuevo registro en la base de datos
  • Ejemplo: POST libros (crear libro nuevo)

204 (No Content)

  • Para qué: Decir "se eliminó correctamente, no hay nada que mostrar"
  • Cuándo: Al eliminar un registro
  • Ejemplo: DELETE libro/1

404 (Not Found)

  • Para qué: Decir "no encontré lo que buscas"
  • Cuándo: Cuando buscas un libro que no existe
  • Ejemplo: GET libro/999 (si no existe ese ID)
  • Nota: Lo genera findOrFail() automáticamente

422 (Unprocessable Entity)

  • Para qué: Decir "los datos que enviaste están mal"
  • Cuándo: Cuando falla la validación
  • Ejemplo: POST sin título o con año en texto
  • Nota: Lo genera validate() automáticamente

Libro::all()

8. ¿Qué es un API RESTful?

Esto es un API RESTful (también llamado REST API).

REST y RESTful son lo mismo:

  • REST = Representational State Transfer (el concepto/arquitectura)
  • RESTful = Un API que sigue los principios REST

¿Por qué tu API de libros es RESTful?

Cumple con los principios REST:

  1. Usa verbos HTTP correctamente:
    • GET → Para leer/consultar
    • POST → Para crear
    • PUT → Para actualizar
    • DELETE → Para eliminar
  2. Usa recursos (sustantivos en plural):
    • /api/libros (no /api/obtenerLibros o /api/getBooks)
    • Los recursos se identifican por URL
  3. Sin estado (Stateless):
    • Cada petición es independiente
    • No guarda información de sesión entre peticiones
  4. Retorna códigos HTTP estándar:
    • 200, 201, 204, 404, 422
  5. Usa JSON para intercambiar datos:
    • Formato estándar para APIs modernas

✅ Resumen:

  • REST = Los principios/reglas
  • RESTful = Un API que sigue esas reglas
  • Tu API de libros es RESTful porque sigue los principios REST

Algunas personas dicen "API REST" y otras "API RESTful", pero significan exactamente lo mismo. ✓

9. Probar cada ruta

Para probar la API puedes usar:

  • Postman (aplicación de escritorio)
  • Thunder Client (extensión de VS Code)
  • Insomnia (aplicación de escritorio)
  • curl (desde la terminal)

Iniciar servidor de desarrollo

php artisan serve
  • URL base: http://localhost:8000

Ejemplos de peticiones:

GET 1. Ver todos los libros

curl http://localhost:8000/api/libros

POST 2. Crear un libro

curl -X POST http://localhost:8000/api/libros \
  -H "Content-Type: application/json" \
  -d '{"titulo":"Don Quijote","autor":"Miguel de Cervantes","genero":"Novela","anio_publicacion":1605}'

GET 3. Ver un libro específico

curl http://localhost:8000/api/libros/1

PUT 4. Actualizar un libro

curl -X PUT http://localhost:8000/api/libros/1 \
  -H "Content-Type: application/json" \
  -d '{"titulo":"Don Quijote de la Mancha"}'

DELETE 5. Eliminar un libro

curl -X DELETE http://localhost:8000/api/libros/1

Resumen de rutas:

  • GET /api/libros → Ver todos
  • POST /api/libros → Crear uno nuevo
  • GET /api/libros/1 → Ver uno específico
  • PUT /api/libros/1 → Actualizar
  • DELETE /api/libros/1 → Eliminar
