Scanner y parseo

Bloque 5 — Leer datos del usuario

Hasta ahora tu programa ya sabía sus datos. Aquí empieza a preguntarlos.

Bienvenida al Bloque 5

Hasta este punto del manual, todos los programas ya sabían sus datos. Cuando escribiste int edad = 20; o String nombre = "Ana";, el programa no le preguntó nada a nadie: el valor estaba escrito directamente en el código. Eso sirve para aprender, pero no es cómo funcionan los programas reales.

Un programa real casi nunca conoce sus datos de antemano. Un cajero no sabe cuánto dinero vas a retirar. Un juego no sabe qué nombre le vas a poner al personaje. Una calculadora no sabe qué números vas a operar. Los programas reales preguntan.

Este bloque introduce la pieza que permite eso: Scanner. Es la clase de Java que sirve para leer datos que el usuario escribe por teclado, uno por uno, en el orden en que los escribe. Y también introduce algo relacionado pero distinto: el parseo, que es convertir texto a números (o a otros tipos) cuando ya tienes el texto guardado y quieres tratarlo como dato.

Vas a aprender:

  • Cómo crear un Scanner y leer los tipos más comunes: int, double, String, boolean.
  • El obstáculo más famoso de Java para principiantes: combinar nextInt() con nextLine() y que la segunda lectura "se salte".
  • Qué es el buffer de entrada y por qué causa esos comportamientos raros.
  • Cómo validar antes de leer, con hasNextInt(), para evitar errores cuando el usuario escribe algo distinto a lo esperado.
  • Cómo parsear texto a números, y en qué casos es mejor opción que leer directamente con Scanner.

Este bloque es más largo que los anteriores porque Scanner tiene muchos detalles. Pero casi todos esos detalles están agrupados alrededor de dos problemas concretos: el buffer sucio, y la validación de la entrada. Si entiendes esos dos, el resto es mecánico.

¿Qué problema resuelve Scanner?

Antes de tocar sintaxis, quiero que la idea quede clara.

Hasta ahora, un programa que sumaba dos números se veía así:

int a = 5;
int b = 3;
int suma = a + b;
System.out.println("Suma: " + suma);

Los valores 5 y 3 están escritos en el código. Si quieres sumar otros números, tienes que abrir el archivo, cambiar los valores, recompilar y volver a ejecutar. Eso no es cómo se usan los programas: nadie va a abrir el código fuente para cambiar la edad que quiere calcular.

Lo que quieres es esto:

Ingresa el primer número: _ Ingresa el segundo número: _ Suma: _

El programa pregunta los datos, y tú los escribes en la consola mientras el programa corre. Eso es lo que resuelve Scanner: leer datos que llegan por teclado mientras el programa está en ejecución, y guardarlos en variables para usarlos después.

Un Scanner es, entonces, la pieza que le permite a tu programa escuchar. Antes tenía los datos escritos en el archivo; ahora los recibe de afuera. Es la pieza que separa a un programa de práctica de un programa que hace algo útil.

La idea a recordar: Scanner es la pieza que le permite al programa escuchar al usuario. No es un adorno, no es una formalidad: es lo que convierte un cálculo fijo en un programa interactivo.

Importar y crear el Scanner

Para usar Scanner hay que hacer dos cosas antes de leer nada:

  1. Importar la clase Scanner desde el paquete java.util.
  2. Crear un objeto Scanner que lea desde la entrada estándar (el teclado).

Vamos con la pieza mínima:

import java.util.Scanner;

public class Saludo {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        // aquí leeremos datos
    }
}

Vamos parte por parte:

  • import java.util.Scanner; — va arriba del todo, antes de la declaración de la clase. Le dice a Java: "voy a usar la clase Scanner que vive en el paquete java.util". Sin esta línea, Java no sabe qué es Scanner y no compila.
  • Scanner scanner = new Scanner(System.in); — crea el objeto. Scanner (con mayúscula) es el tipo. scanner (minúscula) es el nombre de la variable, y tú eliges cómo llamarla (podría ser leer, entrada, sc, etc.). new es la palabra que se usa para crear objetos en Java. System.in significa "lee desde la entrada estándar", que es el teclado.

La línea de creación se pone una sola vez, al principio del main, y a partir de ahí el mismo scanner sirve para leer todos los datos que necesites. No se crea uno nuevo por cada lectura.

Errores comunes con el import y la creación

  • Olvidar el import: si no pones import java.util.Scanner;, Java te dice "cannot find symbol: class Scanner". Es un error muy común y fácil de arreglar: solo hay que agregar la línea.
  • Usar scanner con mayúscula cuando declaras: si escribes Scanner Scanner = new Scanner(...), Java se confunde porque ya existe una clase llamada Scanner. Usa minúsculas para el nombre.
  • Poner System.in con mayúscula al inicio: es System.in, con la S mayúscula, la i minúscula. Es de las cosas que se te va a olvidar una vez y vas a aprender para siempre.
  • Crear el Scanner antes del main: tiene que ir dentro del main, no afuera de la clase.

Un detalle de estilo: si vas a leer desde el teclado, se llama a la variable scanner (o teclado, entrada). Si vas a leer desde un archivo, se llama al constructor con el archivo, pero eso no lo vamos a usar en este manual. Aquí siempre vamos a leer del teclado.

Leer un entero: nextInt()

Una vez que tienes el Scanner creado, leer un entero es simple:

System.out.print("Ingresa tu edad: ");
int edad = scanner.nextInt();
System.out.println("Tu edad es: " + edad);

Vamos parte por parte:

  • System.out.print("Ingresa tu edad: "); — muestra un mensaje sin salto de línea, para que el cursor quede en la misma línea y el usuario escriba justo después del mensaje. Esto es convención: se llama "prompt". Con println también funciona, solo que el cursor queda en la línea siguiente.
  • scanner.nextInt() — lee el siguiente int de la entrada. Se queda esperando hasta que el usuario escribe un número y presiona Enter. Cuando eso pasa, devuelve el número y el programa continúa.
  • int edad = ... — guarda el valor devuelto por nextInt() en una variable.

La ejecución real se ve así en la consola:

Ingresa tu edad: 20 Tu edad es: 20

El "20" después de los dos puntos lo escribió el usuario. Todo lo demás lo imprimió el programa. Y fíjate: el cursor se queda esperando al lado del mensaje "Ingresa tu edad: " porque usamos print (sin "ln"). Eso hace que la experiencia se sienta natural.

El patrón de pedir + leer

Vas a repetir esto muchísimas veces. Se llama el patrón pedir + leer:

  1. Mostrar un mensaje claro de qué se está pidiendo.
  2. Leer el valor con el método que corresponda al tipo.
  3. Guardarlo en una variable.
System.out.print("¿Cómo te llamas? ");
String nombre = scanner.nextLine();

System.out.print("¿Cuántos años tienes? ");
int edad = scanner.nextInt();

System.out.println("Hola " + nombre + ", tienes " + edad + " años.");

Ojo: este ejemplo tiene un problema que no se ve a simple vista, y es exactamente el obstáculo del que hablamos en este bloque. Pero antes de entrar en eso, necesito que veas cada método por separado. Después entenderás por qué este orden (nextLine primero, nextInt después) funciona, mientras que el orden inverso da problemas.

Leer un decimal: nextDouble()

Para leer un número con decimales, el método es nextDouble():

System.out.print("Ingresa el precio: ");
double precio = scanner.nextDouble();
System.out.println("El precio es: " + precio);

La ejecución en consola:

Ingresa el precio: 19.99 El precio es: 19.99

Hay dos detalles que sorprenden al principio:

  • El separador decimal puede ser punto o coma, según la configuración regional de tu Java. En la mayoría de las configuraciones de español (México, España, Argentina, etc.), nextDouble() espera el punto como separador decimal (19.99), no la coma (19,99). Si escribes 19,99, Java puede interpretar que escribiste el número 19 seguido de algo que no entiende, y lanzar un error. Esta es una fuente de confusión enorme, porque en matemáticas en español se usa la coma. Regla práctica: en el código y en la consola de Java, usa punto.
  • Si el usuario escribe un número sin decimales (por ejemplo, 20), funciona igual. Java convierte el 20 a 20.0 automáticamente, porque es un valor válido como double. No hay que escribir "20.0" obligatoriamente.

Precisión: el punto flotante no es exacto

Un detalle que vale la pena saber: double no puede representar todos los decimales con exactitud. 0.1 + 0.2 en Java no da exactamente 0.3, da 0.30000000000000004. Esto no es un error de Java: es cómo funcionan los números de punto flotante en cualquier lenguaje. No vas a necesitar profundizar en esto por ahora, pero cuando hagas cuentas con dinero y los resultados no den exactos, ya sabrás por qué.

Para evitar la mayoría de estos problemas en cuentas de dinero, se suele usar int con centavos (500 = 5.00), o la clase BigDecimal (que no vemos en este manual). Por ahora, vive con la imprecisión: es pequeña y no afecta la mayoría de los ejercicios.

Leer texto completo: nextLine()

Para leer una línea entera de texto (todo lo que el usuario escriba hasta presionar Enter), el método es nextLine():

System.out.print("Escribe tu nombre completo: ");
String nombre = scanner.nextLine();
System.out.println("Hola, " + nombre);

La ejecución:

Escribe tu nombre completo: Ana López García Hola, Ana López García

nextLine() lee toda la línea, incluyendo los espacios. Esto es lo que lo distingue de next(), que lee solo una palabra. Si el usuario escribe "Ana López García", nextLine() devuelve el texto completo, mientras que next() devolvería solo "Ana".

Un detalle importante: nextLine() consume el Enter

Cada vez que el usuario escribe algo y presiona Enter, se envían dos cosas al programa: el texto que escribió, y un carácter invisible de "fin de línea" (que en la práctica es un "\n").

Los métodos como nextInt(), nextDouble() y next() leen el valor y dejan el "\n" en el buffer. Es decir, no se comen el Enter: lo dejan ahí, esperando a que alguien más lo lea.

nextLine(), en cambio, lee todo hasta el Enter, incluyendo el Enter mismo. Si el buffer tiene un "\n" esperando, nextLine() lo consume y devuelve una cadena vacía "".

Esa diferencia es la causa del error más famoso de Scanner. Lo vas a ver en detalle en la sección siguiente, pero ya lo puedes ir intuyendo: si lees un int con nextInt() y después quieres leer un texto con nextLine(), el nextLine() se encuentra con el "\n" que dejó el nextInt(), y devuelve vacío en lugar de esperar a que el usuario escriba.

Leer una sola palabra: next()

next() lee la siguiente palabra, es decir, todo hasta el primer espacio en blanco (o hasta el fin de línea). No incluye el espacio ni el salto de línea en el resultado, y no consume el Enter.

System.out.print("Escribe dos palabras: ");
String primera = scanner.next();
String segunda = scanner.next();

System.out.println("Primera: " + primera);
System.out.println("Segunda: " + segunda);

Si el usuario escribe hola mundo y presiona Enter, este programa imprime:

Primera: hola Segunda: mundo

El primer next() lee "hola", el segundo lee "mundo". Si el usuario hubiera escrito tres palabras, el tercer next() leería la tercera. Y si el usuario hubiera escrito una sola palabra, el segundo next() se quedaría esperando una segunda palabra del usuario antes de continuar.

Cuándo usar next() en lugar de nextLine(): cuando quieres leer una sola palabra (un nombre de usuario sin espacios, una contraseña, una palabra clave). next() tiene la ventaja de que no se traga el Enter, así que no causa el problema del buffer sucio que sí causa nextLine() después de otros métodos.

Cuándo NO usar next(): cuando el dato puede tener espacios. Un nombre completo, una dirección, una frase. Ahí va nextLine().

Leer un booleano: nextBoolean()

Para leer un valor verdadero/falso, existe nextBoolean():

System.out.print("¿Estás registrado? (true/false): ");
boolean registrado = scanner.nextBoolean();
System.out.println("Registrado: " + registrado);

nextBoolean() espera que el usuario escriba exactamente true o false, en minúsculas, sin comillas. Cualquier otra cosa (por ejemplo, "si", "no", "sí", "1", "0") genera un InputMismatchException y el programa termina con error.

Esto es incómodo en la práctica. Los usuarios no escriben "true" o "false" naturalmente. Por eso nextBoolean() casi no se usa en programas reales: en su lugar, se pide un int (1 o 0), o un String ("si" o "no"), y se convierte con un if:

System.out.print("¿Estás registrado? (si/no): ");
String respuesta = scanner.nextLine();
boolean registrado = respuesta.equalsIgnoreCase("si");

Este patrón —leer texto y convertirlo a lo que necesitas— es más cercano al parseo, que vas a ver más adelante en este bloque. Lo menciono aquí solo para que veas que nextBoolean() existe, pero rara vez lo vas a usar.

El buffer de entrada: cómo funciona por dentro

Antes de ver el error más famoso de Scanner, necesito que entiendas una idea. Es simple, pero sin ella el error parece magia.

Cuando el usuario escribe algo y presiona Enter, todos esos caracteres no llegan directamente al programa. Van a un buffer de entrada, que es como una fila temporal donde se van acumulando. El programa, cuando pide un dato con nextAlgo(), va a esa fila, toma lo que necesita, y deja el resto ahí para la siguiente lectura.

Piensa en un tubo de entrada. El usuario escribe "20" y presiona Enter. En el tubo quedan estos caracteres:

2 0 \n

El carácter \n es invisible: representa el Enter. Cuando el programa llama a nextInt(), Java mira el tubo, lee "2" y "0" hasta el primer espacio en blanco, los convierte al número 20, y deja el \n en el tubo. El método nextInt() no consume el Enter: solo lee los dígitos.

Ahora, si el programa llama a nextLine(), va al tubo y encuentra... un \n. Y como nextLine() "lee todo hasta el primer Enter, inclusive", lee ese \n, devuelve la cadena vacía "", y sigue. No espera a que el usuario escriba nada, porque ya encontró el Enter que dejó nextInt() antes.

Eso es todo. Ese es el mecanismo. Es simple, pero sorprende la primera vez porque el programa compila bien, corre, y muestra un comportamiento que "no tiene sentido" si no sabes qué pasa por dentro.

La idea del buffer, en una línea: cada vez que el usuario presiona Enter, se mete un \n en el buffer. Los métodos como nextInt() leen su valor pero no se comen el \n. Solo nextLine() se come el \n. Si mezclas un nextInt() con un nextLine() inmediatamente después, el nextLine() va a leer el \n del nextInt(), no lo que el usuario escriba.

El error universal: nextInt() seguido de nextLine()

Este es el punto más importante de todo el bloque. Y es el error que comete casi todo el mundo que aprende Java por primera vez, en cualquier país, con cualquier profesor. Tiene hasta nombre en foros: "Scanner skip" o "Scanner no me lee el nextLine". Si te pasa, no estás haciendo nada mal que no le pase a los demás. Estás topándote con el mismo obstáculo que se topa todo el mundo.

Veamos el error en concreto:

System.out.print("Ingresa tu edad: ");
int edad = scanner.nextInt();

System.out.print("Ingresa tu nombre: ");
String nombre = scanner.nextLine();

System.out.println("Hola " + nombre + ", tienes " + edad + " años.");

Cuando lo ejecutas, pasa esto:

Ingresa tu edad: 20 Ingresa tu nombre: Hola , tienes 20 años.

El programa no le pide el nombre al usuario. Salta directo al mensaje final, y muestra el nombre vacío. Al usuario le hubiera gustado escribir "Ana", pero el programa nunca le dio la oportunidad.

¿Por qué pasa esto? (con el buffer en la mano)

Apliquemos lo que aprendimos del buffer, paso por paso:

  1. El programa imprime "Ingresa tu edad: ".
  2. El usuario escribe 20 y presiona Enter.
  3. El buffer ahora contiene: 2 0 \n
  4. El programa llama a nextInt(). Lee "20", lo convierte a 20, y guarda 20 en edad. El buffer ahora contiene: \n
  5. El programa imprime "Ingresa tu nombre: ".
  6. El programa llama a nextLine(). Va al buffer, encuentra \n, lo lee, y devuelve una cadena vacía "". El buffer queda vacío.
  7. El programa sigue. nombre es "", la cadena vacía.

Por eso el usuario nunca llega a escribir nada: el nextLine() encontró el \n que dejó el nextInt() antes, y no esperó.

La causa de todo es que nextInt() no consume el Enter. Y nextLine() sí espera consumir un Enter. Cuando los pones juntos en ese orden, el nextLine() se "come" el Enter del nextInt(), y no llega a leer nada nuevo.

Antes de seguir con la solución: quiero que sepas algo

Este error es tan común que cualquier persona con experiencia en Java lo ha tenido. No revela falta de atención ni de capacidad. Es una particularidad del lenguaje que hay que conocer y ya. Cuando lo hayas visto dos o tres veces, lo vas a reconocer al instante. Mientras tanto, es solo un obstáculo más de la lista.

Las tres soluciones al error del buffer

Ya sabes por qué pasa. Ahora, cómo arreglarlo. Hay tres formas estándar. Las tres funcionan; cada una tiene su contexto:

Solución 1: limpiar el buffer con un nextLine() extra

Después del nextInt() (o cualquier otro método que no consuma el Enter), haces un nextLine() vacío. Ese nextLine() consume el \n que quedó pendiente, y deja el buffer limpio para la siguiente lectura.

System.out.print("Ingresa tu edad: ");
int edad = scanner.nextInt();
scanner.nextLine();   // ← limpia el buffer, tira el \n

System.out.print("Ingresa tu nombre: ");
String nombre = scanner.nextLine();

Ahora funciona como se espera:

Ingresa tu edad: 20 Ingresa tu nombre: Ana Hola Ana, tienes 20 años.

El primer nextLine() (el "extra") lee el \n pendiente y lo descarta. El segundo nextLine() (el que guardamos en nombre) lee lo que el usuario escriba.

Algo a tener presente: el nextLine() extra se usa solo después de un método que no consume el Enter. Si lo pones después de otro nextLine(), no hace falta: el primer nextLine() ya limpió.

Solución 2: leer todo con nextLine() y parsear

Otra forma: en lugar de mezclar nextInt() con nextLine(), lees todo como texto con nextLine(), y después conviertes a número cuando lo necesites. Esto evita el problema del buffer por completo, porque nextLine() siempre limpia.

System.out.print("Ingresa tu edad: ");
String edadTexto = scanner.nextLine();
int edad = Integer.parseInt(edadTexto);

System.out.print("Ingresa tu nombre: ");
String nombre = scanner.nextLine();

Esta es la solución que muchos programadores con experiencia prefieren, porque es consistente: siempre usas nextLine() y después parseas al tipo que necesites. Nunca tienes que preocuparte por el orden de los métodos ni por dejar el buffer sucio.

La desventaja: si el usuario escribe algo que no es un número, Integer.parseInt lanza una excepción y el programa falla (a menos que la captures, cosa que verás más adelante). Por eso, cuando uses esta forma, conviene validar antes, o estar dispuesto a manejar el error. Volveremos a esto en la sección de parseo.

Solución 3: usar next() en lugar de nextLine() para datos sin espacios

Si el dato que vas a leer después del nextInt() no tiene espacios (un nombre de usuario, una contraseña, una sola palabra), puedes usar next() en lugar de nextLine(). next() no se come el Enter, así que no se topa con el \n pendiente.

System.out.print("Ingresa tu edad: ");
int edad = scanner.nextInt();

System.out.print("Ingresa tu nombre de usuario: ");
String usuario = scanner.next();   // ← next en lugar de nextLine

Esto funciona porque next() salta los espacios en blanco (incluyendo el \n) y lee la siguiente palabra. No se "come" el \n del nextInt() como basura: lo salta, y espera al siguiente token real. Es limpio.

La limitación: si el usuario escribe "Ana López", next() solo lee "Ana", y "López" queda en el buffer para la siguiente lectura (o se pierde si no hay siguiente lectura). Para nombres completos, no sirve.

¿Cuál usar?

  • Si el dato siguiente es una sola palabra sin espacios: usa next(). Es la más limpia.
  • Si el dato siguiente puede tener espacios (nombre completo, dirección, frase): usa nextLine() con el "extra" antes para limpiar el buffer. Es el patrón más común.
  • Si quieres consistencia y evitar todo el problema: lee todo con nextLine() y parsea. Es la que menos sorpresas da una vez que la dominas.

No hay una respuesta "correcta" universal. Cualquiera de las tres funciona. Con práctica, vas a ir reconociendo cuál te conviene en cada situación. Y si en algún momento no sabes qué pasó, imprime lo que leíste para ver qué es lo que llegó:

System.out.println("[DEBUG] Leí: '" + nombre + "'");

Ese truco —imprimir entre comillas simples lo que leíste— es la mejor forma de descubrir si un nextLine() está leyendo vacío. Si te sale [DEBUG] Leí: '', es que el buffer estaba sucio.

El otro error: InputMismatchException

Hay un segundo error con Scanner que también es muy común. Se llama InputMismatchException, y ocurre cuando pides un tipo y el usuario escribe otro.

System.out.print("Ingresa tu edad: ");
int edad = scanner.nextInt();

Si el usuario escribe 20, todo bien. Pero si escribe veinte, o 20 años, o simplemente presiona Enter sin escribir nada, Java lanza una excepción:

Ingresa tu edad: veinte Exception in thread "main" java.util.InputMismatchException at java.base/java.util.Scanner.throwFor(Scanner.java:939) at java.base/java.util.Scanner.next(Scanner.java:1594) ... at Saludo.main(Saludo.java:5)

El programa termina abruptamente. No muestra el resto del código. No se recupera. Simplemente se detiene.

Por qué ocurre

nextInt() espera encontrar un entero. Cuando encuentra algo que no puede interpretar como entero, no adivina, no convierte: lanza una excepción. Java es muy estricto con los tipos.

Esto es en realidad bueno en términos de seguridad: te avisa que algo salió mal, en lugar de usar un valor incorrecto silenciosamente. Pero es molesto para los usuarios, que pueden equivocarse al escribir. Un programa robusto debería poder manejar esto sin reventar.

Cómo evitarlo: validar con hasNextInt()

La clase Scanner tiene métodos hasNextAlgo() que verifican si el siguiente dato es del tipo esperado, sin intentar leerlo. Si el resultado es true, entonces sí puedes leerlo con seguridad. Si es false, sabes que no hay un entero esperando, y puedes pedir de nuevo o mostrar un mensaje.

System.out.print("Ingresa tu edad: ");

if (scanner.hasNextInt()) {
    int edad = scanner.nextInt();
    System.out.println("Edad: " + edad);
} else {
    System.out.println("Eso no es un número entero");
    scanner.nextLine();   // limpia el valor inválido del buffer
}

Con hasNextInt(), verificas primero y solo lees si estás seguro. Si el usuario escribió "veinte", el else maneja el caso sin que el programa reviente.

Nota el scanner.nextLine() en el else: es necesario para limpiar la entrada inválida. Si no lo haces, el valor inválido sigue en el buffer, y la próxima lectura también va a fallar. Es el mismo concepto de "buffer sucio" que viste antes.

Los hasNext más usados

  • hasNextInt() — ¿hay un int disponible?
  • hasNextDouble() — ¿hay un double disponible?
  • hasNextBoolean() — ¿hay un boolean disponible?
  • hasNext() — ¿hay otra palabra disponible?
  • hasNextLine() — ¿hay otra línea disponible?

Todos devuelven boolean. Ninguno consume nada del buffer. Son la forma segura de leer sin riesgo de excepción.

En la siguiente sección vas a ver el patrón completo de validación, que combina hasNextInt() con un while para pedir hasta que el usuario escriba algo válido. Es uno de los patrones más útiles que vas a aprender en este bloque.

¿Qué es parsear?

Parsear es convertir un valor de un tipo a otro, típicamente desde texto hacia un tipo numérico o lógico. Es una operación muy común, y tiene sus propios métodos, separados de Scanner.

Antes de ver los métodos, piensa en la situación:

Cuando usas scanner.nextInt(), el programa ya sabe que el usuario va a escribir un entero, y directamente convierte. Pero hay casos donde tienes el texto guardado como String y necesitas convertirlo después:

  • Tienes un String edad = "20" y quieres sumarle 1. No puedes: "20" es texto, no número. Primero hay que convertirlo a int.
  • Tienes un String precio = "19.99" que vino de un archivo o de la red, y quieres calcular con él. Hay que convertirlo a double.
  • Tienes un String respuesta = "true" y quieres usarlo como boolean en un if. Hay que convertirlo.

Parsear es hacer esa conversión. Los métodos de parseo son métodos estáticos de las clases envoltorio (Integer, Double, etc.), y se llaman así: Integer.parseInt(texto).

Diferencia clave entre Scanner y parseo: Scanner lee de la entrada (teclado, archivo). El parseo convierte algo que ya tienes. Si ya tienes el texto en una variable, no necesitas Scanner: usas parseo. Si necesitas leer algo nuevo del usuario, usas Scanner (y a veces parseas lo que leíste).

Convertir a entero: Integer.parseInt()

El método más común de parseo. Convierte un String en un int:

String texto = "42";
int numero = Integer.parseInt(texto);

System.out.println(numero + 1);   // 43

Fíjate: "42" es texto, pero después del parseInt es un número. Por eso numero + 1 da 43, no "421". Sin el parseo, texto + 1 daría "421" (concatenación).

El caso típico: leer con nextLine() y parsear

System.out.print("Ingresa tu edad: ");
String edadTexto = scanner.nextLine();
int edad = Integer.parseInt(edadTexto);

Este es el patrón que mencioné en la solución 2 del buffer sucio: leer todo con nextLine(), y convertir al tipo que necesites. Es consistente y evita el problema del \n pendiente.

Qué pasa si el texto no es un número

Si el String no representa un entero válido, parseInt lanza una excepción NumberFormatException, y el programa termina con error. Igual que con nextInt():

Integer.parseInt("hola");       // ← NumberFormatException
Integer.parseInt("20 años");    // ← NumberFormatException
Integer.parseInt("");           // ← NumberFormatException
Integer.parseInt("20");         // ✓ esto sí funciona, devuelve 20
Integer.parseInt("-7");         // ✓ esto también, devuelve -7
Integer.parseInt(" 20");        // ✓ los espacios al inicio se ignoran

Por eso, si vas a parsear algo que viene de la entrada del usuario, conviene validar antes (o manejar la excepción, cosa que verás más adelante). O simplemente pedir al usuario que escriba solo dígitos, y estar preparado para que se equivoque.

Convertir a decimal: Double.parseDouble()

Equivalente al anterior, pero para double:

String texto = "19.99";
double precio = Double.parseDouble(texto);

System.out.println(precio * 2);   // 39.98

Igual que con parseInt, si el texto no representa un número válido, lanza NumberFormatException. Y ojo con el punto decimal: Double.parseDouble("19,99") lanza excepción. Tiene que ser punto.

El caso típico: leer un precio con nextLine() y parsear

System.out.print("Ingresa el precio: ");
String precioTexto = scanner.nextLine();
double precio = Double.parseDouble(precioTexto);

Este patrón es muy útil, porque el usuario a veces escribe 19.99 y a veces 19. Los dos funcionan con parseDouble (el segundo se convierte a 19.0 automáticamente).

Parseo desde nextLine(): el detalle de la coma decimal

En algunos países, el separador decimal que se usa naturalmente es la coma, no el punto. Si estás enseñando a estudiantes hispanohablantes, es posible que escriban 19,99 y el parseo falle. Hay dos enfoques:

  • Enseñar a usar punto: explicar que en el código y en la consola de Java el separador es el punto, aunque en matemáticas se use coma. Es la opción simple y funciona.
  • Reemplazar la coma por punto antes de parsear: Double.parseDouble(texto.replace(",", ".")). Esto maneja el caso en el que el usuario escribe con coma. Es más robusto, pero agrega complejidad.

Para los ejercicios del manual, la primera opción es suficiente. Menciono la segunda para que sepas que existe.

Otros parseos útiles

Long.parseLong()

Igual que Integer.parseInt, pero devuelve un long (entero de 64 bits, hasta aproximadamente 9.2 × 10^18). Útil cuando el número puede ser muy grande para un int.

String texto = "9000000000";   // no cabe en int, sí en long
long grande = Long.parseLong(texto);

Boolean.parseBoolean()

Convierte un String a boolean. Es peculiar, y vale la pena entender su comportamiento: devuelve true solo si el texto (ignorando mayúsculas) es exactamente "true". Cualquier otro texto devuelve false. No lanza excepción.

Boolean.parseBoolean("true");       // true
Boolean.parseBoolean("TRUE");       // true
Boolean.parseBoolean("TrUe");       // true
Boolean.parseBoolean("false");      // false
Boolean.parseBoolean("si");         // false ← ojo, no es "true"
Boolean.parseBoolean("hola");       // false
Boolean.parseBoolean("");           // false

Esto es útil y peligroso a la vez. Útil porque nunca falla con excepción. Peligroso porque "si" devuelve false silenciosamente, y probablemente no era lo que querías. Si el usuario va a responder "si" o "no", mejor hazlo a mano:

String respuesta = scanner.nextLine().trim().toLowerCase();
boolean dijoSi = respuesta.equals("si") || respuesta.equals("sí") || respuesta.equals("s") || respuesta.equals("yes") || respuesta.equals("y");

Integer.parseInt(texto, base)

Hay una versión de parseInt que recibe la base numérica como segundo argumento. Útil para convertir binario, octal o hexadecimal:

Integer.parseInt("1010", 2);       // 10 (binario)
Integer.parseInt("FF", 16);         // 255 (hexadecimal)
Integer.parseInt("777", 8);        // 511 (octal)

Poco común en programas de principiante, pero útil saber que existe. Si en algún momento necesitas leer un número binario o hexadecimal, ya tienes la pieza.

Lo contrario: convertir un número a texto

La conversión inversa (número → texto) es automática cuando concatenas con un String. Si necesitas forzarla, tienes String.valueOf(numero):

int numero = 42;
String texto1 = String.valueOf(numero);   // "42"
String texto2 = "" + numero;                  // "42" (concatenación)
String texto3 = Integer.toString(numero);   // "42"

Las tres formas funcionan. La concatenación ("" + numero) es la más común, y la vas a ver en todos lados.

Parseo vs Scanner: cuándo usar cada uno

Ya tienes las dos piezas. La pregunta natural es: ¿cuándo usar una y cuándo la otra?

La respuesta corta: Scanner cuando lees del usuario, parseo cuando ya tienes el dato como String. Pero hay más matices.

SituaciónQué usarPor qué
Leer un número del usuario directamente nextInt() o nextDouble() Lee y convierte en un solo paso
Leer un texto del usuario y después usarlo como número nextLine() + Integer.parseInt() Evita el problema del buffer sucio
Tienes un String (de un archivo, de otro método) y quieres convertirlo Integer.parseInt() o similar No hay nada que leer, solo convertir
Leer varias cosas mezcladas en una sola línea nextLine() + split() + parseo Más flexible para entradas complejas
Leer un dato que puede ser de varios tipos nextLine() + hasNextInt() o parseo con try/catch Permite manejar la conversión con gracia

La recomendación práctica

Si estás empezando, la forma más simple y menos problemática es esta:

Leer todo con nextLine(), y parsear cuando necesites un número.

System.out.print("Ingresa tu edad: ");
int edad = Integer.parseInt(scanner.nextLine());

System.out.print("Ingresa tu nombre completo: ");
String nombre = scanner.nextLine();

System.out.print("Ingresa tu estatura (en metros): ");
double estatura = Double.parseDouble(scanner.nextLine());

Este patrón tiene varias ventajas:

  • No tienes que preocuparte por el orden de los métodos ni por el buffer sucio. nextLine() siempre limpia.
  • Es consistente: siempre usas nextLine, y después decides cómo interpretar.
  • Si más adelante quieres cambiar de tipo (por ejemplo, permitir decimales donde antes eran enteros), solo cambias el parseo, no la lectura.

La desventaja es que no manejas la excepción si el usuario escribe algo no numérico. Pero eso lo puedes resolver con validación previa (que ves en la siguiente sección) o con try/catch (que no vemos en este manual pero que vas a ver más adelante).

Si en algún momento del manual ves que mezclo nextInt() con nextLine() en un ejemplo, es porque quiero mostrar un patrón específico o porque el ejemplo lo requiere. Pero cuando yo escriba programas "en serio" o en los ejercicios, voy a usar preferentemente el patrón de leer con nextLine() y parsear. Es el que menos sorpresas da.

Errores comunes al parsear

1. Parsear un String vacío

Integer.parseInt("");   // ← NumberFormatException

Un String vacío no es un número, aunque a veces parezca que "no tiene nada de malo". Antes de parsear, verifica que el texto no esté vacío:

String texto = scanner.nextLine().trim();   // trim() quita espacios sobrantes

if (texto.isEmpty()) {
    System.out.println("No escribiste nada");
} else {
    int numero = Integer.parseInt(texto);
    ...
}

2. Parsear texto con espacios al inicio o al final

Integer.parseInt(" 20 ") funciona, porque parseInt ignora los espacios. Pero Integer.parseInt("20 30") no funciona, porque el texto entero no es un número. trim() te ayuda a eliminar los espacios de los bordes:

String texto = "  20  ";
int numero = Integer.parseInt(texto.trim());   // 20

3. Olvidar el punto y coma decimal correcto

Double.parseDouble("19,99");   // ← NumberFormatException
Double.parseDouble("19.99");   // ✓ 19.99

El separador decimal en Java siempre es punto. Si quieres aceptar coma, tendrás que reemplazarla antes:

String texto = "19,99";
double precio = Double.parseDouble(texto.replace(",", "."));   // 19.99

4. Confundir parseInt con nextInt

Los dos convierten a entero, pero de fuentes distintas:

  • scanner.nextInt() — lee un entero del teclado.
  • Integer.parseInt(texto) — convierte un String a entero.

Si tienes un String y quieres un int, no puedes llamar scanner.nextInt(): eso leería otro dato del teclado. Tienes que usar Integer.parseInt.

5. Confundir Integer con int

En Java, int (minúscula) es el tipo primitivo. Integer (mayúscula) es la clase envoltorio, que tiene métodos útiles como parseInt. Cuando llamas al método, es Integer.parseInt (clase, mayúscula). Cuando declaras la variable, es int x (tipo, minúscula). Es un error fácil de cometer al principio.

int x = Integer.parseInt("5");   // ✓ correcto
Integer y = int.parseInt("5");   // ✗ error de sintaxis

Aunque ambos tipos existen y se comportan parecido, en el código que escribas usa int para declarar variables y Integer para llamar métodos estáticos. Es la convención.

6. No quitar el \n pendiente antes de parsear

Si haces esto:

int edad = scanner.nextInt();
String nombre = Integer.parseInt(scanner.nextLine());   // ← bug

El nextLine() va a leer el \n pendiente del nextInt(), y Integer.parseInt("") va a fallar con NumberFormatException. Es el mismo problema del buffer sucio, ahora manifestado como una excepción al parsear. La solución es la misma: limpiar el buffer antes, o usar el patrón de leer todo con nextLine() y parsear.

Validar antes de leer: hasNextInt() y variantes

Un programa robusto no asume que el usuario va a escribir lo correcto. Verifica antes de leer. Para eso existen los métodos hasNextAlgo().

La idea es simple: antes de llamar a nextInt(), pregúntale a hasNextInt() si hay un entero disponible. Si la respuesta es true, lee con seguridad. Si es false, maneja el caso (mensaje, o pedir de nuevo).

System.out.print("Ingresa tu edad: ");

if (scanner.hasNextInt()) {
    int edad = scanner.nextInt();
    System.out.println("Edad: " + edad);
} else {
    System.out.println("Eso no es un número");
    scanner.nextLine();   // limpia el valor inválido del buffer
}

Este patrón es la base de todo programa que lee datos y no quiere terminar abruptamente. Los hasNext...() no leen, solo preguntan.

Comportamiento particular: hasNextInt() no consume el Enter

Los métodos hasNextAlgo() no consumen nada del buffer. Solo miran qué hay. Si dicen true, después puedes leer con nextAlgo(). Si dicen false, tienes que limpiar el buffer tú mismo (con nextLine()), o el valor inválido se va a quedar ahí para la próxima lectura.

Ese detalle es importante: si no limpias el buffer cuando el dato no es válido, la siguiente lectura va a fallar también. Por eso en los ejemplos de hasNextInt, siempre verás un nextLine() dentro del else.

Patrón completo: pedir hasta que el usuario ingrese algo válido

Este es el patrón que combina todo lo anterior. Es uno de los más útiles que vas a aprender con Scanner, y probablemente lo uses en todos tus programas interactivos a partir de ahora.

La idea: pedir un dato, verificar si es válido, y si no lo es, pedir de nuevo. Repetir hasta que sea válido.

System.out.println("Ingresa un número entero (escribe 'q' para salir):");

while (!scanner.hasNextInt()) {
    String entrada = scanner.next();

    if (entrada.equalsIgnoreCase("q")) {
        System.out.println("Adiós");
        return;   // termina el programa
    }

    System.out.println("'" + entrada + "' no es un número válido. Intenta de nuevo:");
}

int numero = scanner.nextInt();
System.out.println("Número aceptado: " + numero);

Este programa pide un número. Mientras el usuario no escriba un entero válido, sigue pidiendo. Si el usuario escribe q, sale del programa. Cuando finalmente escribe un número, lo acepta y sigue.

Hay algo interesante aquí: la condición del while usa !scanner.hasNextInt(). Es decir: "mientras NO haya un entero disponible". Mientras esa condición sea verdadera, seguimos pidiendo. En cuanto el usuario escriba un número, hasNextInt() devuelve true, y !true es false, así que el ciclo termina.

Dentro del ciclo, leemos el valor inválido con scanner.next() (no nextLine(), porque next() es más adecuado para descartar tokens) y verificamos si el usuario quiere salir. Si no, mostramos un mensaje de error y volvemos a intentar.

Variante: máximo de intentos

A veces no quieres un ciclo infinito, sino un número limitado de intentos. Aquí está la variante:

int intentos = 0;
int maxIntentos = 3;
int numero = -1;
boolean valido = false;

while (intentos < maxIntentos && !valido) {
    System.out.print("Ingresa un número entero: ");

    if (scanner.hasNextInt()) {
        numero = scanner.nextInt();
        valido = true;
    } else {
        System.out.println("Eso no es un número.");
        scanner.nextLine();   // limpia el buffer
        intentos++;
    }
}

if (valido) {
    System.out.println("Número aceptado: " + numero);
} else {
    System.out.println("Se agotaron los intentos");
}

Este patrón aparece muchísimo en programas reales (login, validación de tarjetas, etc.). Fíjate en la estructura:

  • Un while que combina dos condiciones: intentos < maxIntentos y !valido. Sale cuando se acaban los intentos o cuando se ingresa un valor válido.
  • Un hasNextInt() que verifica antes de leer.
  • Un else que limpia el buffer y suma un intento.
  • Después del ciclo, se consulta valido para saber qué pasó.

Es un ejemplo completo de las piezas que has aprendido: while, if, bandera (valido), contador (intentos), y validación con hasNext.

Una alternativa con parseo: try/catch

Si prefieres el patrón de leer todo con nextLine() y parsear, puedes hacer la validación con try/catch. No hemos visto try/catch en este manual, pero lo menciono porque es la otra forma común:

while (true) {
    System.out.print("Ingresa un número: ");
    String entrada = scanner.nextLine();

    try {
        int numero = Integer.parseInt(entrada);
        System.out.println("Número aceptado: " + numero);
        break;
    } catch (NumberFormatException e) {
        System.out.println("Eso no es un número. Intenta de nuevo.");
    }
}

Este patrón intenta parsear, y si falla, captura el error y vuelve a pedir. Es más limpio en cierto sentido, pero requiere entender try/catch, que no es parte de este manual. Si te sientes cómodo con él, úsalo. Si no, quédate con la versión de hasNextInt().

Ejemplos progresivos con Scanner

Ejemplo 1 — Leer un número y mostrarlo

import java.util.Scanner;

public class Ejemplo1 {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        System.out.print("Ingresa un número: ");
        int numero = Integer.parseInt(scanner.nextLine());

        System.out.println("El doble es: " + (numero * 2));
    }
}

El ejemplo mínimo. Lee un número, lo usa. Fíjate en el patrón: nextLine() para leer, parseInt para convertir. Es la versión segura.

Ejemplo 2 — Leer nombre y edad, saludar

import java.util.Scanner;

public class Ejemplo2 {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        System.out.print("¿Cómo te llamas? ");
        String nombre = scanner.nextLine();

        System.out.print("¿Cuántos años tienes? ");
        int edad = Integer.parseInt(scanner.nextLine());

        System.out.println("Hola " + nombre + ", tienes " + edad + " años.");
    }
}

Aquí lees texto primero (nextLine) y después un número (nextLine + parseInt). Fíjate en el orden: el texto va primero, y el número después. Ese orden es natural y no tiene el problema del buffer, porque nextLine() limpia el buffer después de cada lectura.

Ejemplo 3 — Leer dos números y sumarlos

import java.util.Scanner;

public class Ejemplo3 {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        System.out.print("Primer número: ");
        double a = Double.parseDouble(scanner.nextLine());

        System.out.print("Segundo número: ");
        double b = Double.parseDouble(scanner.nextLine());

        System.out.println("Suma: " + (a + b));
        System.out.println("Resta: " + (a - b));
        System.out.println("Producto: " + (a * b));

        if (b != 0) {
            System.out.println("División: " + (a / b));
        } else {
            System.out.println("No se puede dividir entre cero");
        }
    }
}

Una calculadora simple. Combina Scanner con lo que ya sabes de operadores y decisiones. Fíjate en el if (b != 0) antes de dividir: sin él, el programa lanzaría una excepción. Validar las entradas siempre es buena idea.

Ejemplo 4 — Calcular descuento según el monto

import java.util.Scanner;

public class Ejemplo4 {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        System.out.print("Total de la compra: ");
        double total = Double.parseDouble(scanner.nextLine());

        double descuento = 0.0;

        if (total >= 500) {
            descuento = 0.20;
        } else if (total >= 200) {
            descuento = 0.10;
        } else if (total >= 100) {
            descuento = 0.05;
        }

        double totalFinal = total - (total * descuento);

        System.out.println("Descuento aplicado: " + (descuento * 100) + "%");
        System.out.println("Total a pagar: " + totalFinal);
    }
}

Aquí se combinan Scanner con if/else if. Es la primera vez que ves un ejemplo donde el flujo del programa depende completamente del dato que ingresa el usuario. Eso es lo que hace que los programas interactivos sean útiles: el mismo código se comporta distinto según la entrada.

Ejemplo 5 — Programa con menú y varias lecturas

import java.util.Scanner;

public class Ejemplo5 {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        int opcion = 0;

        do {
            System.out.println("--- CALCULADORA ---");
            System.out.println("1. Sumar");
            System.out.println("2. Restar");
            System.out.println("3. Salir");
            System.out.print("Elige: ");

            opcion = Integer.parseInt(scanner.nextLine());

            switch (opcion) {
                case 1:
                    System.out.print("Primer número: ");
                    double a = Double.parseDouble(scanner.nextLine());
                    System.out.print("Segundo número: ");
                    double b = Double.parseDouble(scanner.nextLine());
                    System.out.println("Resultado: " + (a + b));
                    break;
                case 2:
                    System.out.print("Primer número: ");
                    a = Double.parseDouble(scanner.nextLine());
                    System.out.print("Segundo número: ");
                    b = Double.parseDouble(scanner.nextLine());
                    System.out.println("Resultado: " + (a - b));
                    break;
                case 3:
                    System.out.println("Adiós");
                    break;
                default:
                    System.out.println("Opción no válida");
            }
        } while (opcion != 3);
    }
}

Este es el ejemplo más cercano a un programa real. Combina todo: do while para el menú, switch para las opciones, Scanner con parseo para cada lectura, y las piezas de los bloques anteriores. Si lo puedes escribir por tu cuenta después de verlo, ya tienes el manual casi dominado.

Nota: hay un problema con este ejemplo si intentas compilarlo tal cual, porque a y b están declaradas dentro del case 1 y usadas también en el case 2. En Java, las variables declaradas dentro de un case tienen alcance limitado y no se pueden usar en otro case. Habría que declararlas afuera del switch. Lo menciono porque es un error clásico, y vale la pena que lo tengas en mente cuando escribas switch con lógica dentro.

Ejercicios de Scanner y parseo

Reconocer

Mira este fragmento y predice qué imprime, considerando que el usuario escribe 25 y presiona Enter, y después escribe Ana y presiona Enter.

System.out.print("Edad: ");
int edad = scanner.nextInt();

System.out.print("Nombre: ");
String nombre = scanner.nextLine();

System.out.println("Hola " + nombre + " (" + edad + ")");
Ver solución

Imprime: Edad: Nombre: Hola (25). El nombre queda vacío.

El nextInt() lee el 25 pero deja el \n en el buffer. Cuando el programa pide el nombre con nextLine(), este lee el \n pendiente y devuelve "". Es exactamente el error del buffer sucio. La solución: agregar un scanner.nextLine(); después del nextInt(), o usar el patrón de leer con nextLine() y parsear.

Completar

Completa el código para leer un número decimal del usuario y calcular su raíz cuadrada (asumiendo que existe el método Math.sqrt).

System.out.print("Ingresa un número: ");
double numero = ____________;

System.out.println("Raíz cuadrada: " + Math.sqrt(numero));
Ver solución

Double.parseDouble(scanner.nextLine()). Este es el patrón recomendado: leer con nextLine() y convertir con parseo. También funcionaría scanner.nextDouble(), pero el patrón de parseo es más consistente.

Modificar

Este programa debería pedir primero un número, después una palabra, pero solo lee el número. Encuentra y corrige el error.

System.out.print("Número: ");
int n = scanner.nextInt();

System.out.print("Palabra: ");
String palabra = scanner.nextLine();

System.out.println("Leí: " + n + " y '" + palabra + "'");
Ver solución

Hay dos formas de corregirlo. La más directa:

System.out.print("Número: ");
int n = scanner.nextInt();
scanner.nextLine();   // limpia el buffer

System.out.print("Palabra: ");
String palabra = scanner.nextLine();

Otra forma, más consistente:

System.out.print("Número: ");
int n = Integer.parseInt(scanner.nextLine());

System.out.print("Palabra: ");
String palabra = scanner.nextLine();

Cualquiera de las dos funciona. La primera es más pequeña; la segunda es más consistente y menos propensa a errores.

Construir

Escribe un programa que le pida al usuario su nombre completo y su año de nacimiento, y calcule aproximadamente cuántos años tiene.

Ver solución 
import java.util.Scanner;

public class EdadAprox {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        System.out.print("Nombre completo: ");
        String nombre = scanner.nextLine();

        System.out.print("Año de nacimiento: ");
        int añoNac = Integer.parseInt(scanner.nextLine());

        int añoActual = 2025;
        int edad = añoActual - añoNac;

        System.out.println("Hola " + nombre + ", tienes aproximadamente " + edad + " años.");
    }
}

Nota cómo el nombre se lee con nextLine() (permite espacios) y el año con nextLine() + parseInt. Nunca mezclamos nextInt() con nextLine(), evitando el problema del buffer.

Combinar

Escribe un programa que lea tres notas, calcule el promedio, y muestre si el estudiante aprobó (promedio ≥ 6) o reprobó. Usa el patrón de validación con hasNextDouble() para asegurarte de que el usuario escribe números válidos.

Ver solución 
import java.util.Scanner;

public class Promedio {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        double suma = 0;

        for (int i = 1; i <= 3; i++) {
            System.out.print("Nota " + i + ": ");

            while (!scanner.hasNextDouble()) {
                String invalido = scanner.next();
                System.out.println("'" + invalido + "' no es válido. Intenta de nuevo: ");
            }

            suma += scanner.nextDouble();
        }

        double promedio = suma / 3;

        System.out.println("Promedio: " + promedio);

        if (promedio >= 6) {
            System.out.println("Aprobado");
        } else {
            System.out.println("Reprobado");
        }
    }
}

Este ejemplo combina for, while con hasNextDouble, if/else, y Scanner. Fíjate en el patrón de validación dentro del for: mientras el usuario no escriba un decimal válido, el while sigue pidiendo. Cuando lo escribe, sale del while y sigue con el for.

Crear

Escribe un programa que simule un cajero automático interactivo. Debe:

  • Pedir una contraseña de 4 dígitos (asume que la contraseña correcta es "1234").
  • Si la contraseña es incorrecta, dar hasta 3 intentos. Si se agotan, mostrar "Cuenta bloqueada".
  • Si la contraseña es correcta, mostrar un menú con: 1) Consultar saldo, 2) Retirar, 3) Salir.
  • El saldo inicial es 1000. Para retirar, pedir un monto, verificar que sea múltiplo de 100 y que no exceda el saldo. Si no cumple, mostrar error sin modificar el saldo.
  • Repetir el menú hasta que el usuario elija salir.
Ver solución 
import java.util.Scanner;

public class Cajero {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        String contraseñaCorrecta = "1234";
        boolean autenticado = false;
        int intentos = 0;

        // Autenticación
        while (intentos < 3 && !autenticado) {
            System.out.print("Contraseña (4 dígitos): ");
            String intento = scanner.nextLine();

            if (intento.equals(contraseñaCorrecta)) {
                autenticado = true;
            } else {
                intentos++;
                System.out.println("Contraseña incorrecta. Intentos restantes: " + (3 - intentos));
            }
        }

        if (!autenticado) {
            System.out.println("Cuenta bloqueada");
            return;   // termina el programa
        }

        // Menú principal
        int saldo = 1000;
        int opcion;

        do {
            System.out.println("--- CAJERO ---");
            System.out.println("1) Consultar saldo");
            System.out.println("2) Retirar");
            System.out.println("3) Salir");
            System.out.print("Elige: ");

            while (!scanner.hasNextInt()) {
                scanner.nextLine();
                System.out.print("Elige (1-3): ");
            }
            opcion = scanner.nextInt();
            scanner.nextLine();   // limpia el buffer

            switch (opcion) {
                case 1:
                    System.out.println("Tu saldo es: $" + saldo);
                    break;
                case 2:
                    System.out.print("Monto a retirar: ");

                    while (!scanner.hasNextInt()) {
                        scanner.nextLine();
                        System.out.print("Monto a retirar (número): ");
                    }
                    int monto = scanner.nextInt();
                    scanner.nextLine();

                    if (monto % 100 != 0) {
                        System.out.println("El monto debe ser múltiplo de 100");
                    } else if (monto > saldo) {
                        System.out.println("Saldo insuficiente");
                    } else {
                        saldo -= monto;
                        System.out.println("Retiro exitoso. Nuevo saldo: $" + saldo);
                    }
                    break;
                case 3:
                    System.out.println("Gracias por usar el cajero");
                    break;
                default:
                    System.out.println("Opción no válida");
            }
            System.out.println();
        } while (opcion != 3);
    }
}

Este reto es el más completo del manual hasta ahora. Combina:

  • while con dos condiciones (intentos y autenticado) para el login.
  • Bandera (autenticado), contador (intentos).
  • do while con switch para el menú.
  • Validación con hasNextInt + nextLine() para limpiar el buffer.
  • if/else if/else para la lógica de retiro.
  • Uso de return para salir del main si la autenticación falla.

Si puedes escribir esto por tu cuenta, ya tienes todas las piezas del manual (excepto arreglos) integradas. Es la prueba concreta de cuánto has construido.

Reto: registro de usuarios

Escribe un programa que simule un registro simple de usuarios. El programa debe:

  1. Pedir cuántos usuarios se van a registrar (un número entre 1 y 10).
  2. Para cada usuario, pedir:
    • Nombre completo (puede tener espacios).
    • Edad (entero entre 1 y 120).
    • Estatura en metros (decimal, entre 0.5 y 2.5).
    • Si está registrado como "premium" (sí/no).
  3. Al final, mostrar un resumen con:
    • Cantidad total de usuarios.
    • Edad promedio.
    • Estatura promedio.
    • Cantidad de usuarios premium.
    • Nombre del usuario de mayor edad.

Requisitos técnicos:

  • Usa el patrón de leer con nextLine() y parsear para evitar el buffer sucio.
  • Valida cada dato antes de aceptarlo: la edad debe estar en rango, la estatura también, la respuesta premium debe ser interpretable como sí o no.
  • Si algún dato no es válido, pide de nuevo (sin salir del programa).
  • Usa un for para recorrer los usuarios.
  • Combina lo aprendido: if, else if, while para validación, contadores, acumuladores, etc.

Antes de escribir el código, haz el análisis en español: ¿qué datos vas a guardar? ¿Cómo validas cada uno? ¿Cómo calculas los promedios? ¿Cómo encuentras el mayor? Escribe cada paso. Después tradúcelo a Java.

Ver solución 
import java.util.Scanner;

public class RegistroUsuarios {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        // Cuántos usuarios (entre 1 y 10)
        int cantidad = 0;
        while (cantidad < 1 || cantidad > 10) {
            System.out.print("¿Cuántos usuarios (1-10)? ");

            while (!scanner.hasNextInt()) {
                scanner.nextLine();
                System.out.print("Ingresa un número (1-10): ");
            }
            cantidad = scanner.nextInt();
            scanner.nextLine();   // limpiar buffer

            if (cantidad < 1 || cantidad > 10) {
                System.out.println("Debe estar entre 1 y 10");
            }
        }

        // Acumuladores
        int sumaEdades = 0;
        double sumaEstaturas = 0;
        int premium = 0;
        int mayorEdad = -1;
        String nombreMayor = "";

        // Registro
        for (int i = 1; i <= cantidad; i++) {
            System.out.println("\n--- Usuario " + i + " ---");

            System.out.print("Nombre completo: ");
            String nombre = scanner.nextLine().trim();

            int edad = 0;
            while (edad < 1 || edad > 120) {
                System.out.print("Edad (1-120): ");

                while (!scanner.hasNextInt()) {
                    scanner.nextLine();
                    System.out.print("Ingresa un número: ");
                }
                edad = scanner.nextInt();
                scanner.nextLine();

                if (edad < 1 || edad > 120) {
                    System.out.println("Edad fuera de rango");
                }
            }

            double estatura = 0;
            while (estatura < 0.5 || estatura > 2.5) {
                System.out.print("Estatura en metros (0.5-2.5): ");

                while (!scanner.hasNextDouble()) {
                    scanner.nextLine();
                    System.out.print("Ingresa un decimal: ");
                }
                estatura = scanner.nextDouble();
                scanner.nextLine();

                if (estatura < 0.5 || estatura > 2.5) {
                    System.out.println("Estatura fuera de rango");
                }
            }

            System.out.print("¿Es premium? (si/no): ");
            String resp = scanner.nextLine().trim().toLowerCase();
            boolean esPremium = resp.equals("si") || resp.equals("sí") || resp.equals("s");

            // Acumular
            sumaEdades += edad;
            sumaEstaturas += estatura;
            if (esPremium) premium++;
            if (edad > mayorEdad) {
                mayorEdad = edad;
                nombreMayor = nombre;
            }
        }

        // Reporte
        System.out.println("\n--- RESUMEN ---");
        System.out.println("Total de usuarios: " + cantidad);
        System.out.println("Edad promedio: " + ((double) sumaEdades / cantidad));
        System.out.println("Estatura promedio: " + (sumaEstaturas / cantidad));
        System.out.println("Usuarios premium: " + premium);
        System.out.println("Usuario de mayor edad: " + nombreMayor + " (" + mayorEdad + " años)");
    }
}

Este programa combina todo lo del manual hasta ahora. Fíjate en cómo cada lectura crítica tiene su while de validación adentro (con hasNextInt o hasNextDouble), y cómo cada nextAlgo() va seguido de un nextLine() para limpiar el buffer. Es el patrón más robusto, y aunque parezca repetitivo, es el que menos sorpresas da cuando el usuario se equivoca.

Lo que llevas construido

Al terminar este bloque, tienes estas piezas nuevas:

  • Scanner — la pieza que le permite a tu programa leer datos del usuario.
  • Crear un Scanner — import, new Scanner(System.in).
  • Métodos de lectura — nextInt(), nextDouble(), nextLine(), next(), nextBoolean().
  • El buffer de entrada — cómo funciona por dentro, y por qué nextInt() + nextLine() falla.
  • Las tres soluciones al buffer sucio — nextLine() extra, leer todo con nextLine() + parsear, o usar next().
  • InputMismatchException — qué es, por qué ocurre, cómo evitarla.
  • Parseo — Integer.parseInt, Double.parseDouble, Boolean.parseBoolean, y sus variantes.
  • Scanner vs parseo — cuándo usar cada uno.
  • Validación con hasNext — hasNextInt(), hasNextDouble(), y el patrón de pedir hasta que sea válido.

Y estas son las piezas que ya tenías y ahora usas con la entrada del usuario:

  • Variables, tipos, operadores (Bloque 1).
  • if, else, else if, operadores lógicos (Bloque 2).
  • switch, while, do while (Bloque 3).
  • for, break, continue, ciclos anidados (Bloque 4).

Con Scanner, tus programas ya no son solo cálculos fijos: son interactivos. Pueden responder a lo que el usuario escribe. Eso es un cambio enorme: es la diferencia entre un ejercicio de clase y una herramienta que alguien podría usar.

Un punto que quiero mencionar antes de cerrar el bloque: el error del buffer sucio (y todo lo que viste sobre cómo funciona) es el obstáculo más universal de Java. Prácticamente todo el que aprende Java se topa con él. La primera vez, parece magia negra. La segunda, lo reconoces. La tercera, lo esquivas sin pensar. Es un ejemplo perfecto de cómo las piezas se construyen con la práctica, no vienen de fábrica.

El siguiente bloque (y último) introduce arreglos. Es la pieza que te permite guardar muchos valores del mismo tipo en una sola variable, y combinarlos con los ciclos que ya sabes. Con arreglos, tu repertorio queda casi completo, y vas a poder escribir programas que manejan datos de verdad.

Antes de pasar al Bloque 6, asegúrate de resolver al menos un ejercicio de cada nivel. Y si el error del buffer sucio te sigue pareciendo raro, escríbelo tú mismo varias veces hasta que se vuelva obvio. Es una pieza que vas a usar siempre, y vale la pena dominarla.
