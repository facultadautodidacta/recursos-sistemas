Repetición en Java

Bloque 3 — switch, while, do while

Hasta ahora tu programa decidía. Aquí empieza a repetir.

Bienvenida al Bloque 3

En el Bloque 2 aprendiste a hacer que tu programa tomara decisiones. Un if ejecuta algo si se cumple una condición. Un else if elige entre varios caminos. Con eso ya puedes escribir programas que responden a distintas situaciones, no siempre lo mismo.

Pero hay algo que todavía no puedes hacer: repetir. Si quisieras mostrar los números del 1 al 100, hasta ahora tendrías que escribir cien println. Si quisieras preguntarle al usuario si quiere seguir, tendrías que repetir la misma pregunta una y otra vez a mano. Si quisieras sumar los primeros N números, no habría forma de hacerlo sin saber N de antemano.

Este bloque cambia eso. Vas a aprender tres piezas nuevas:

  • switch — una forma alternativa y a veces más clara de elegir entre muchas opciones cuando todas comparan el mismo dato contra un valor exacto.
  • while — repetir algo mientras se cumpla una condición, evaluándola antes de cada vuelta.
  • do while — repetir algo al menos una vez, y después seguir mientras se cumpla la condición.

Los ciclos (while y do while) son probablemente la pieza que más va a cambiar tu forma de escribir programas. Con ellos, una sola línea de código puede hacer que algo se repita mil veces. Y con ellos llega, por primera vez en el manual, la sensación de que un programa trabaja solo. Es una de las cosas más satisfactorias de programar.

Pero también es donde muchas personas se atoran, porque aparece una nueva dificultad: hay que imaginar el paso del tiempo. Un if lo ves y ya sabes qué pasa. Un while tenés que imaginarlo ejecutándose varias veces, y eso cuesta al principio. Es normal. Vamos a ir despacio.

Vas a combinar decisiones y repetición (léelo antes de que pase)

En el Bloque 2 te anticipé un bajón específico: el de combinar variables con decisiones. En este bloque viene uno más grande, y quiero que llegues preparado.

El momento más difícil del manual no es while solo. Tampoco es if solo. Es cuando empiezas a meter decisiones dentro de ciclos: un if adentro de un while, o un while adentro de un if. Ahí las dos piezas que ya sabías por separado se tienen que reorganizar para funcionar juntas, y el cerebro tiene que empezar a simular un proceso que se repite, no solo un camino que se recorre una vez.

Cuando llegues a esa parte del bloque, es probable que sientas una de estas cosas:

  • "No entiendo cuándo se ejecuta esto y cuándo no".
  • "Sé lo que hace cada pieza sola, pero juntas me pierdo".
  • "Pensé que ya sabía if, pero ahora no sé si entendí bien".

Ninguna de esas sensaciones significa que hayas retrocedido. Significan que tu mente está tratando de sostener al mismo tiempo la idea de decisión y la idea de repetición, y eso no es algo que el cerebro haga naturalmente: hay que construirlo. A nadie le sale de fábrica.

Anticipa esto antes de que pase

Cuando sientas que "se te olvidó if" al meter un if dentro de un while, no se te olvidó. Lo estás poniendo a trabajar en un contexto más complejo. Dale tiempo. Haz simulaciones a mano, escribe las vueltas en papel, marca los valores de las variables en cada paso. En dos o tres días, se va a sentir claro. Esa es la señal de que aprendiste algo que antes no sabías.

Este manual vuelve a hablar de esto en el cierre del bloque, cuando ya hayas pasado por la experiencia. Aquí lo lees antes, para que cuando aparezca lo reconozcas en lugar de pensar que estás fallando.

El switch: elegir entre muchas opciones

Antes de Java (situación cotidiana)

Piensa en un menú de restaurante con opciones numeradas. El mesero dice "opción 1, 2 o 3". Si el cliente dice "1", se sirve sopa. Si dice "2", se sirve ensalada. Si dice "3", se sirve pasta. Si dice cualquier otra cosa, se avisa que la opción no existe.

Cada opción es un caso específico del mismo dato (el número del menú). El cliente no dice "quiero algo entre el 1 y el 3", dice un número exacto. Y el mesero reacciona a ese número exacto. No evalúa rangos, ni condiciones compuestas: mira el número y actúa.

Esa estructura —un dato contra varios valores exactos— es exactamente la que resuelve el switch.

La idea en español

Un switch significa: "según el valor de esto, haz una de estas varias cosas específicas". Se parece a una cadena de else if, pero solo se usa cuando cada caso compara el mismo dato contra un valor exacto. No sirve para rangos. No sirve para condiciones compuestas. Si tu condición es "nota >= 7 && nota <= 9", el switch no es la pieza correcta: ahí va if / else if. Si tu condición es "el día es el 3", el switch sí.

La nueva pieza

switch (variable) {
    case valor1:
        // hacer algo
        break;
    case valor2:
        // hacer otra cosa
        break;
    default:
        // hacer algo si no coincide con ningún caso
}

Un ejemplo concreto con el número del día:

int dia = 3;

switch (dia) {
    case 1:
        System.out.println("Lunes");
        break;
    case 2:
        System.out.println("Martes");
        break;
    case 3:
        System.out.println("Miércoles");
        break;
    default:
        System.out.println("Día no válido");
}

Lee eso en español: "según el valor de dia: si es 1, muestra Lunes; si es 2, Martes; si es 3, Miércoles; en cualquier otro caso, muestra Día no válido". Con dia = 3, imprime "Miércoles".

Anatomía de un switch

  • switch (variable) — la variable o expresión cuyo valor se va a comparar. En Java moderno puede ser int, char, String, o tipos enum. No puede ser double ni boolean.
  • case valor: — cada caso. Compara el valor de arriba con este valor exacto. Si coincide, empieza a ejecutar desde aquí.
  • break; — termina el switch. Sin esto, Java sigue ejecutando los siguientes casos también ("fall through"), que casi nunca es lo que quieres. Volvemos a esto en un momento.
  • default: — el caso por defecto. Se ejecuta si ningún otro coincidió. Es opcional, pero casi siempre conviene tenerlo.

El detalle que sorprende: switch en Java compara con ==, no con .equals()

Cuando uses un switch sobre un String, Java internamente usa .equals(), no ==. Es decir, compara contenido, no referencia. Esto es distinto a lo que pasa cuando tú escribes str1 == str2 a mano. Puedes confiar en que switch (nombre) { case "Ana": ... } va a funcionar bien con strings, porque Java lo maneja correctamente por dentro.

El break en switch (y qué pasa si lo olvidas)

Este es el error número uno con switch, y merece su propia sección. Cuando un case coincide, Java empieza a ejecutar desde ahí y sigue ejecutando todo lo que venga después, hasta encontrar un break o hasta el final del switch. A esto se le llama fall through.

int dia = 2;

switch (dia) {
    case 1:
        System.out.println("Lunes");
    case 2:
        System.out.println("Martes");
    case 3:
        System.out.println("Miércoles");
    default:
        System.out.println("Día no válido");
}

Con dia = 2 y sin ningún break, la salida es:

Martes Miércoles Día no válido

Java entra en el case 2, ejecuta "Martes", y como no hay break, sigue con el case 3 y con el default. No los compara: los ejecuta directamente, porque ya entró al switch y solo va a salir cuando encuentre un break o llegue al final.

Esto confunde mucho al principio, pero tiene una razón de ser: a veces quieres que varios case compartan el mismo bloque de código. Por ejemplo:

switch (dia) {
    case 1:
    case 2:
    case 3:
    case 4:
    case 5:
        System.out.println("Día laborable");
        break;
    case 6:
    case 7:
        System.out.println("Fin de semana");
        break;
    default:
        System.out.println("Día no válido");
}

Aquí los case 1, 2, 3, 4, 5 están "vacíos" (sin código propio) y caen al mismo bloque, que imprime "Día laborable". Si dia vale 1, 2, 3, 4 o 5, todos imprimen lo mismo. Esto se llama fall through intencional, y es una de las razones por las que switch existe: agrupa casos sin repetir el código.

Lo que no quieres es fall through accidental. Regla práctica: pon un break al final de cada caso, salvo cuando estés agrupando deliberadamente. Si no estás seguro, pon el break. Si el código se comporta raro, sospecha de un break olvidado.

Si un switch imprime más de lo que esperabas

Es casi siempre esto. Revisa cada caso y pregúntate: "¿este caso debería seguir ejecutándose si entra?". Si la respuesta es no, ponle break. Es el mismo tipo de bloqueo que un ; olvidado después de un if: el código compila, pero hace algo distinto a lo que querías.

¿switch o else if?

Los dos pueden expresar la misma idea muchas veces, pero no son intercambiables en todos los casos. La regla es simple:

  • switch: cuando comparas el mismo dato contra varios valores exactos. Por ejemplo, un int dia contra 1, 2, 3, 4, 5, 6, 7. Un String contra "rojo", "verde", "azul".
  • else if: cuando las condiciones son rangos, combinaciones lógicas, o comparan cosas distintas. Por ejemplo, nota >= 9, nota >= 7 && nota < 9, edad >= 18 && tieneIdentificacion.

Veamos la misma lógica escrita de dos formas para notar la diferencia:

// Con else if (funciona, pero es más largo)
if (dia == 1) {
    System.out.println("Lunes");
} else if (dia == 2) {
    System.out.println("Martes");
} else if (dia == 3) {
    System.out.println("Miércoles");
} else {
    System.out.println("Día no válido");
}

// Con switch (más claro cuando hay muchos casos)
switch (dia) {
    case 1: System.out.println("Lunes"); break;
    case 2: System.out.println("Martes"); break;
    case 3: System.out.println("Miércoles"); break;
    default: System.out.println("Día no válido");
}

Los dos hacen lo mismo. Pero cuando tienes cinco, ocho, quince casos que comparan el mismo dato contra valores exactos, el switch se lee mucho mejor: se ve de un vistazo cuántos casos hay y qué hace cada uno. El else if se vuelve una torre de líneas que cuesta seguir.

Ninguno de los dos es "el correcto". Son herramientas distintas para problemas ligeramente distintos. Cuando dudes, pregúntate: ¿estoy comparando el mismo dato contra valores exactos? Si sí, switch. Si no, else if.

Ejemplos progresivos con switch

Ejemplo 1 — Muy simple: vocal o consonante

char letra = 'a';

switch (letra) {
    case 'a':
    case 'e':
    case 'i':
    case 'o':
    case 'u':
        System.out.println("Es vocal");
        break;
    default:
        System.out.println("Es consonante o símbolo");
}

Fíjate en que los primeros cuatro case no tienen código propio: caen al bloque que dice "Es vocal". Esto es fall through intencional, y es una de las formas más elegantes que tiene switch.

Ejemplo 2 — Días de la semana, con agrupación

int dia = 6;

switch (dia) {
    case 1:
    case 2:
    case 3:
    case 4:
    case 5:
        System.out.println("Día laborable");
        break;
    case 6:
    case 7:
        System.out.println("Fin de semana");
        break;
    default:
        System.out.println("Día no válido");
}

Con dia = 6, imprime "Fin de semana". Con dia = 3, "Día laborable". Con dia = 10, "Día no válido". Ahora sí, cada grupo de casos tiene un break al final, así que no hay fall through accidental.

Ejemplo 3 — switch sobre un String

String color = "amarillo";

switch (color) {
    case "rojo":
        System.out.println("Alto");
        break;
    case "amarillo":
        System.out.println("Precaución");
        break;
    case "verde":
        System.out.println("Siga");
        break;
    default:
        System.out.println("Color no reconocido");
}

Con switch sobre String, cada case lleva el texto entre comillas dobles. Java compara por contenido, así que funciona bien. Y algo importante: en Java, los textos son sensibles a mayúsculas. "Rojo" no coincide con case "rojo". Si quisieras ignorar mayúsculas, tendrías que normalizar el texto antes (con toLowerCase(), por ejemplo).

Ejemplo 4 — Calculadora simple

double a = 10;
double b = 3;
char operacion = '/';
double resultado;

switch (operacion) {
    case '+':
        resultado = a + b;
        System.out.println("Suma: " + resultado);
        break;
    case '-':
        resultado = a - b;
        System.out.println("Resta: " + resultado);
        break;
    case '*':
        resultado = a * b;
        System.out.println("Multiplicación: " + resultado);
        break;
    case '/':
        if (b != 0) {
            resultado = a / b;
            System.out.println("División: " + resultado);
        } else {
            System.out.println("Error: división entre cero");
        }
        break;
    default:
        System.out.println("Operación no válida");
}

Este ejemplo combina switch con if dentro del caso de la división. Es muy común: cada caso del switch puede tener lógica propia, incluso decisiones. Aquí, el caso '/' verifica que b no sea cero antes de dividir. Si fuera cero, muestra un error. Estás usando las piezas de bloques anteriores junto con la nueva.

Ejemplo 5 — Menú de opciones con varios niveles

int opcion = 2;

switch (opcion) {
    case 1:
        System.out.println("Consulta de saldo");
        System.out.println("Tu saldo es: $1500");
        break;
    case 2:
        System.out.println("Retiro de efectivo");
        System.out.println("Selecciona el monto deseado");
        System.out.println("1) $100  2) $500  3) $1000");
        break;
    case 3:
        System.out.println("Depósito");
        System.out.println("Ingresa el monto a depositar");
        break;
    case 4:
        System.out.println("Saliendo del sistema...");
        break;
    default:
        System.out.println("Opción no válida");
}

Este es el tipo de programa donde switch brilla: un menú de opciones numeradas. Con else if también funcionaría, pero con switch se ve de inmediato cuántas opciones hay y qué hace cada una. Fíjate además en que cada caso puede tener varias instrucciones, no solo una.

Errores comunes con switch

1. Olvidar break y caer en fall through accidental

Ya lo cubrimos arriba, pero es tan frecuente que conviene repetirlo: si un switch imprime más de lo que esperabas, casi siempre es esto. Pon break al final de cada caso que no agrupe deliberadamente con el siguiente.

2. Usar switch con rangos

// ESTO NO ES POSIBLE:
switch (edad) {
    case edad >= 18:   // ← error de sintaxis
        ...
}

// Los case solo pueden comparar valores exactos:
case 18:   // ✓ esto sí
case 19:   // ✓ esto también

Si tu caso es "mayor o igual a 18", switch no es la herramienta. Usa if. El switch es solo para valores exactos.

3. Usar double o boolean en switch

Java no permite switch sobre double ni boolean. Solo sobre tipos "discretos": int, char, String, enum. Si tienes un double o un boolean y quieres ramificar, usa if / else if.

4. Olvidar los dos puntos después del case

case 1    // ← falta el ":"
    System.out.println("Lunes");
    break;

Cada case y el default llevan dos puntos al final. Si te falta, Java te da error de sintaxis y no compila. Es una de esas cosas que uno olvida por costumbre de no ponerlos en otro sitio.

5. Asumir que default es obligatorio

Técnicamente puedes omitir el default. El programa compila y corre. Pero entonces, si el valor no coincide con ningún caso, el switch simplemente se salta y sigue con la siguiente instrucción. Eso es válido a veces, pero muchas veces esconde un bug: te olvidaste de manejar un caso que sí debería tener una respuesta. Como regla general, pon siempre un default, aunque sea con un mensaje de "no reconocido". Te obliga a pensar si tu lógica cubre todo.

6. Confundir switch con if anidados

El switch no reemplaza al if. Son herramientas distintas. Si te encuentras escribiendo un switch con case que hacen cosas muy distintas y con condiciones internas, probablemente estás forzando la pieza donde no corresponde. Vuelve al análisis en español: ¿estás eligiendo entre varios valores exactos del mismo dato? Si sí, switch. Si estás tomando decisiones encadenadas, if / else if.

Ejercicios de switch

Reconocer

¿Qué imprime este programa con x = 2?

int x = 2;

switch (x) {
    case 1:
        System.out.println("uno");
    case 2:
        System.out.println("dos");
    case 3:
        System.out.println("tres");
    default:
        System.out.println("otro");
}
Ver solución

Imprime dos, tres y otro, cada uno en su propia línea. Esto es fall through: una vez que entra en case 2, sigue ejecutando hacia abajo porque no hay break. Es exactamente el error que acabamos de estudiar.

Completar

Completa el switch para que, dado opcion, muestre el nombre de la operación correspondiente: 1 → sumar, 2 → restar, 3 → multiplicar, cualquier otro → "opción no válida".

int opcion = 2;

switch (opcion) {
    // tu código aquí
}
Ver solución 
switch (opcion) {
    case 1:
        System.out.println("Sumar");
        break;
    case 2:
        System.out.println("Restar");
        break;
    case 3:
        System.out.println("Multiplicar");
        break;
    default:
        System.out.println("Opción no válida");
}

Cada caso tiene break al final. El default cubre lo que no coincide con ninguno. Nota: los break aquí no tienen punto y coma al final del bloque en todas las versiones de Java, pero es común escribirlo break; con punto y coma. Los dos son válidos según la versión.

Modificar

Este programa debería mostrar "Verano" si el mes es junio, julio o agosto, pero no funciona bien. Encuentra y corrige el error.

int mes = 7;

switch (mes) {
    case 6:
        System.out.println("Verano");
        break;
    case 7:
        System.out.println("Verano");
    case 8:
        System.out.println("Verano");
}
Ver solución

Hay dos problemas: repetir el mismo mensaje en tres case es innecesario, y falta un break después del case 7 (lo cual, en este caso, no rompe el programa porque imprimiría tres veces "Verano" con mes = 7, pero confunde). Una forma más limpia:

switch (mes) {
    case 6:
    case 7:
    case 8:
        System.out.println("Verano");
        break;
    default:
        System.out.println("Otra estación");
}

Aquí los tres case están vacíos y caen al mismo bloque. Es un ejemplo de fall through intencional: tres casos distintos, mismo comportamiento.

Construir

Escribe un programa que, dada una variable char categoria con valor 'A', 'B' o 'C', muestre el sueldo correspondiente:

  • 'A' → 2500
  • 'B' → 1800
  • 'C' → 1200
  • Cualquier otro → "Categoría no válida"
Ver solución 
char categoria = 'B';

switch (categoria) {
    case 'A':
        System.out.println("Sueldo: 2500");
        break;
    case 'B':
        System.out.println("Sueldo: 1800");
        break;
    case 'C':
        System.out.println("Sueldo: 1200");
        break;
    default:
        System.out.println("Categoría no válida");
}

Con char, los valores de cada case van entre comillas simples ('A'), no dobles. Las comillas dobles son para String. Este es un detalle que a veces se confunde cuando se alterna entre tipos.

Combinar

Escribe un programa que simule una calculadora simple. Tienes tres variables: double a, double b, char operacion. Según el valor de operacion ('+', '-', '*', '/'), muestra el resultado. Si la operación es '/' y b es 0, muestra un error. Si la operación no es ninguna de las cuatro, muestra "Operación no válida".

Ver solución 
double a = 20.0;
double b = 4.0;
char operacion = '/';

switch (operacion) {
    case '+':
        System.out.println("Resultado: " + (a + b));
        break;
    case '-':
        System.out.println("Resultado: " + (a - b));
        break;
    case '*':
        System.out.println("Resultado: " + (a * b));
        break;
    case '/':
        if (b == 0) {
            System.out.println("Error: no se puede dividir entre cero");
        } else {
            System.out.println("Resultado: " + (a / b));
        }
        break;
    default:
        System.out.println("Operación no válida");
}

Cada caso tiene una sola instrucción, salvo el de la división, que tiene un if adentro. Este es el primer ejemplo del bloque donde combinas switch con if anidado. No es una combinación complicada, pero es la primera señal de que las piezas empiezan a usarse juntas.

Crear

Escribe un programa que, dado un mes (1 a 12), muestre la estación del año correspondiente (en el hemisferio norte):

  • diciembre, enero, febrero → Invierno
  • marzo, abril, mayo → Primavera
  • junio, julio, agosto → Verano
  • septiembre, octubre, noviembre → Otoño
  • cualquier otro → "Mes no válido"

Usa switch aprovechando el fall through intencional para agrupar los meses de cada estación.

Ver solución 
int mes = 4;

switch (mes) {
    case 12:
    case 1:
    case 2:
        System.out.println("Invierno");
        break;
    case 3:
    case 4:
    case 5:
        System.out.println("Primavera");
        break;
    case 6:
    case 7:
    case 8:
        System.out.println("Verano");
        break;
    case 9:
    case 10:
    case 11:
        System.out.println("Otoño");
        break;
    default:
        System.out.println("Mes no válido");
}

Con mes = 4, imprime "Primavera". Los tres primeros case del bloque de invierno están vacíos: solo el último tiene el código y el break. Si mes fuera 1, Java entraría en case 1, no haría nada, y caería al case 2, tampoco nada, y llegaría al bloque con código. Es exactamente el fall through intencional.

El while: repetir mientras se cumpla algo

Antes de Java (situación cotidiana)

Piensa en un lavaplatos automático. Le pones los trastes, presionas "start", y el aparato hace algo parecido a esto: mientras haya agua en el depósito, sigue lavando. Cuando ya no hay agua, se detiene. No lava una cantidad fija de veces: lava mientras se cumpla una condición. Si hay mucha agua, lava más tiempo. Si hay poca, lava menos. La cantidad de vueltas no la decides tú de antemano: la decide la condición.

O piensa en un ascensor: mientras la puerta esté abierta, sigue sonando una alarma. Cuando la puerta se cierra, la alarma se detiene. Otra vez: repetición que depende de una condición, no de un número fijo.

Esta es exactamente la estructura del while: repetir algo mientras se cumpla una condición, y detenerse cuando deje de cumplirse.

La idea en español

Un while significa: "mientras esta condición sea verdadera, repite esto". La condición se evalúa antes de cada vuelta. Si es verdadera, se ejecuta el cuerpo. Si es falsa, el cuerpo no se ejecuta (ni siquiera una vez) y se sale del ciclo.

Tres cosas importantes para tener claras desde el principio:

  • La condición se evalúa antes de cada vuelta, no después. Esto significa que si la condición ya es falsa al llegar, el cuerpo del while no se ejecuta ni una vez.
  • El cuerpo tiene que cambiar algo, o la condición nunca va a dejar de ser verdadera. Este es el error más común: olvidar cambiar la variable que controla el ciclo, y quedarse con un ciclo infinito.
  • La variable de control (la que aparece en la condición) generalmente se declara antes del while y se modifica dentro del ciclo. Ese patrón lo vas a ver una y otra vez.

La nueva pieza

while (condición) {
    // esto se repite mientras la condición sea true
}

Un ejemplo concreto: contar del 1 al 5.

int i = 1;

while (i <= 5) {
    System.out.println(i);
    i = i + 1;
}

Antes de mirar la simulación de la siguiente sección, trata de adivinar qué hace. La variable i empieza en 1. La condición i <= 5 se evalúa. Mientras se cumpla, se imprime i y se aumenta en 1. Cuando i llegue a 6, la condición 6 <= 5 es falsa y el ciclo termina.

El diagrama del flujo

┌─────────────────────────┐ │ evaluar la condición │ │ (i <= 5) │ └───────────┬─────────────┘ │ ┌────────┴────────┐ │ │ true │ │ false ▼ ▼ ┌────────────────┐ ┌────────────────┐ │ ejecutar el │ │ salir del │ │ cuerpo del │ │ ciclo y │ │ while │ │ seguir │ │ │ │ │ │ ──────── │ └────────────────┘ │ │i = i+1│ │ │ ──────── │ └────────┬───────┘ │ │ (vuelve a evaluar la condición) │ └──────► (regresa al inicio)

La flecha que vuelve al inicio es lo que hace que el while sea un ciclo. No es una línea recta: es un camino que se recorre varias veces hasta que la condición deja de cumplirse.

Con i > 5: la condición es falsa desde el principio (1 > 5 es falso). El cuerpo del while no se ejecuta ni una sola vez. El programa salta directamente a println("Fin"). Este es un caso muy importante: un while puede no ejecutarse nunca, y hay que tenerlo en cuenta al razonar sobre un programa.

Contadores y acumuladores (los dos patrones que vas a usar siempre)

Antes de ver más ejemplos, quiero presentarte dos patrones que vas a usar una y otra vez con ciclos. Tienen nombre y todo.

Contador

Un contador es una variable que empieza en algún valor (usualmente 0) y se incrementa dentro del ciclo. Sirve para contar cuántas veces pasó algo.

int i = 0;
int contador = 0;

while (i < 10) {
    contador = contador + 1;
    i = i + 1;
}

System.out.println("Iteraciones: " + contador);

Este programa imprime "Iteraciones: 10". El contador empezó en 0 y se incrementó una vez por cada vuelta. Fíjate en que hay dos variables aquí: i controla el ciclo, y contador registra cuántas vueltas se dieron. A veces son la misma variable (si solo necesitas contar), pero a menudo son distintas.

Acumulador

Un acumulador es una variable que empieza en un valor neutral (0 para sumas, 1 para productos) y va acumulando resultados dentro del ciclo. Sirve para sumar, multiplicar, o combinar los valores que aparecen en cada vuelta.

int i = 1;
int suma = 0;

while (i <= 5) {
    suma = suma + i;
    i = i + 1;
}

System.out.println("Suma total: " + suma);

Aquí suma acumula 1+2+3+4+5 = 15. Cada vuelta, suma se actualiza con el valor actual de i. El resultado final es 15. Estos dos patrones —contador y acumulador— son probablemente el 80% de lo que vas a hacer con ciclos durante mucho tiempo.

Regla del pulgar: antes de escribir un ciclo, pregúntate si necesitas contar algo (contador) o acumular algo (acumulador). Casi siempre la respuesta a qué variable extra necesitas está ahí. Y no olvides declararla antes del ciclo con el valor inicial correcto: 0 para contar o sumar, 1 para multiplicar.

Bucles infinitos (el error más frustrante)

El error más común con while, y también el más frustrante al principio, es el bucle infinito: un ciclo cuya condición nunca deja de ser verdadera, así que el programa se queda trabado ejecutando el mismo bloque para siempre. VSCode se queda "colgado", el programa no termina, y muchas veces tienes que detenerlo a la fuerza.

Veamos el ejemplo más clásico:

int i = 1;

while (i <= 5) {
    System.out.println(i);
}

Este programa imprime 1 infinitas veces. Porque la variable i nunca cambia: empieza en 1, siempre vale 1, y 1 <= 5 siempre es verdadero. La condición no se va a hacer falsa sola: alguien tiene que cambiarla. Si el cuerpo no modifica i (o cualquier cosa de la que dependa la condición), el ciclo nunca termina.

Esta es la primera regla de todo ciclo: algo tiene que cambiar dentro del cuerpo, y ese algo tiene que afectar la condición. Si no hay cambio, hay bucle infinito.

Por qué esto confunde tanto (y por qué no es solo "un error tonto")

Un bucle infinito confunde más de lo que parece, por una razón concreta: tú escribiste lo que querías, y el programa no te dice nada. No hay un mensaje de error. No hay una línea roja en VSCode. Solo hay un programa que se queda ejecutando y no responde. Es una de las primeras veces en que sientes que la computadora "no coopera", y eso desespera.

Aquí conviene aplicar el protocolo que viste en el Bloque 1. Antes de asumir "no entiendo ciclos", detente y pregúntate: ¿qué variable aparece en la condición? ¿qué la cambia dentro del ciclo? Casi siempre, la respuesta a esas dos preguntas te muestra el problema en segundos.

Cuando tu programa se queda trabado
  1. Detén el programa (en VSCode: el botón rojo de stop, o el atajo que uses).
  2. Lee la condición del while. ¿Qué variable decide si se sigue ejecutando?
  3. Busca en el cuerpo del ciclo: ¿esa variable se modifica en algún lado? Si no, ese es el problema.
  4. Si sí se modifica, ¿se modifica de forma que la condición eventualmente sea falsa? Por ejemplo, si la condición es i <= 5 y dentro haces i = i - 1, va a seguir siendo verdadera para siempre. El cambio tiene que ir en la dirección correcta.

Cómo evitarlos desde que escribes

Un hábito que vale la pena cultivar: cada vez que escribas un while, antes de ejecutarlo, hazte estas tres preguntas:

  1. ¿Qué condición controla el ciclo? Escríbela en papel.
  2. ¿Qué hace que esa condición se vuelva falsa? Deberías poder señalar una línea dentro del cuerpo que cambia algo.
  3. ¿Cuántas vueltas esperas que dé? Si puedes estimarlo, mucho mejor. Te va a permitir comparar con la realidad.

Si puedes contestar las tres, el ciclo va a funcionar. Si te falta la respuesta a la segunda, hay bucle infinito esperándote.

Otro truco, útil durante el desarrollo: poner un println con la variable de control dentro del ciclo. Así, si el programa se queda trabado, ves qué está pasando. Pero ojo: si el ciclo imprime mucho, la consola se llena de texto y no ayuda. Ponlo solo al principio, y quítalo cuando el ciclo funcione.

int i = 1;

while (i <= 5) {
    System.out.println("Iteración i=" + i);   // depuración
    // ... resto del cuerpo ...
    i = i + 1;
}

Cuando el programa funcione, borra la línea de depuración. Ese truco lo vas a usar toda tu vida programando. Es simple, pero es una de las técnicas más efectivas que existen.

Ejemplos progresivos con while

Ejemplo 1 — Contar hacia atrás

int i = 10;

while (i >= 1) {
    System.out.println(i);
    i = i - 1;
}

System.out.println("¡Despegue!");

Cuenta 10, 9, 8, ..., 1, y luego imprime "¡Despegue!". Fíjate en que aquí i decrece, no crece. La condición también cambió de dirección (i >= 1 en vez de i <= 5). El patrón es el mismo, solo cambió el sentido.

Ejemplo 2 — Sumar números hasta un límite

int i = 1;
int suma = 0;

while (i <= 100) {
    suma = suma + i;
    i = i + 1;
}

System.out.println("Suma de 1 a 100: " + suma);

Imprime 5050. Nota cómo se combinan un contador (i) y un acumulador (suma). Ambos se declaran antes del while, ambos se actualizan dentro. Este es el patrón más común con ciclos, y conviene que lo reconozcas de un vistazo.

Ejemplo 3 — Encontrar el primer múltiplo

int n = 13;
int i = 1;

while (n * i % 7 != 0) {
    i = i + 1;
}

System.out.println("El primer múltiplo de 13 que es divisible por 7: " + (n * i));

Con n = 13 y multiplicando por i sucesivamente, el ciclo busca el primer i tal que 13 * i sea divisible por 7. Cuando lo encuentre, sale del ciclo. Este ejemplo no tiene un contador claro (no sabemos cuántas vueltas va a dar), pero funciona porque i crece y eventualmente se cumple. Fíjate en la condición negada: seguimos mientras NO sea divisible. Cuando lo sea, la condición es falsa y salimos.

Ejemplo 4 — Contar los dígitos de un número

int n = 12345;
int contador = 0;

while (n > 0) {
    n = n / 10;
    contador = contador + 1;
}

System.out.println("Cantidad de dígitos: " + contador);

Con n = 12345, imprime 5. La idea es ir dividiendo n entre 10 (con división entera, que descarta decimales) para "quitarle" el último dígito. Después de 5 divisiones, n queda en 0 y el ciclo termina. Ojo con este tipo de programas: modifican n dentro del ciclo, así que si necesitas n original después, tienes que guardarlo en otra variable antes.

Ejemplo 5 — Simular una condición de fin externa

int temperatura = 95;

while (temperatura > 40) {
    System.out.println("Temperatura actual: " + temperatura);
    temperatura = temperatura - 10;
}

System.out.println("Temperatura estable: " + temperatura);

Este ejemplo simula un enfriamiento: mientras la temperatura sea mayor a 40, se sigue "enfriando" (reduciendo de 10 en 10). Fíjate en que la condición del ciclo tiene una interpretación del mundo real: "mientras aún esté demasiado caliente". Ese tipo de lectura en español es la que te va a ayudar a diseñar ciclos en tus propios programas.

Errores comunes con while

1. Olvidar cambiar la variable del ciclo (bucle infinito)

Ya lo cubrimos en detalle. Es el error. Si tu programa se queda colgado, sospecha de esto primero.

2. Cambiar la variable en dirección contraria

int i = 1;

while (i <= 5) {
    System.out.println(i);
    i = i - 1;   // ← ¡está decreciendo!
}

Si i empieza en 1 y decrece, la condición i <= 5 va a ser verdadera siempre (incluso para i = -100, que sigue siendo menor o igual a 5). Bucle infinito por otra vía. La dirección del cambio tiene que coincidir con la dirección que la condición necesita para volverse falsa.

3. Condición mal escrita (que nunca se vuelve falsa)

int i = 1;

while (i != 10) {   // si i salta por encima de 10, nunca se detiene
    i = i + 2;
}

Si i empieza en 1 y se incrementa de 2 en 2, va a pasar por 1, 3, 5, 7, 9, 11, 13... y nunca va a valer exactamente 10. La condición i != 10 siempre es verdadera. Como regla general, prefiere < o <= sobre != en las condiciones de un ciclo, porque así es imposible "saltarse" el valor de salida.

4. Usar while cuando un contador sería más claro

Si vas a repetir algo una cantidad exacta de veces, el while funciona, pero muchas veces vas a preferir un for (que verás en el Bloque 4). El for empaqueta en una sola línea las tres cosas que siempre necesitas: la inicialización, la condición, y el incremento. Para ciclos con un número fijo de vueltas, el for es más legible. El while brilla cuando el número de vueltas no se sabe de antemano.

5. Modificar la variable en varios lugares del cuerpo

Un error sutil: cambiar i en dos lugares distintos dentro del mismo cuerpo del while. El código compila y corre, pero es muy difícil de razonar y de depurar. Como regla, modifica la variable de control en un solo lugar, preferiblemente al final del cuerpo. Así, cuando leas el ciclo, sabes exactamente dónde ocurre el cambio.

6. Olvidarse de las llaves

int i = 1;

while (i <= 5)
    System.out.println(i);
    i = i + 1;   // ← ¡este NO está dentro del while!

Sin llaves, solo la primera instrucción después del while está dentro del ciclo. La segunda (i = i + 1) se ejecuta después del ciclo, que nunca termina porque i no cambia dentro. Bucle infinito por falta de llaves. Es exactamente el mismo tipo de error que con los if, y la solución es la misma: pon siempre las llaves. Es una regla simple que te ahorra horas de frustración.

Si tu programa se queda colgado y no sabes por qué

Aplica el protocolo. Detén el programa, identifica la variable del ciclo, y busca dónde (y si) se modifica. En el 95% de los casos el problema es una de las seis cosas que acabas de leer. Aísla esa pieza —como dice el protocolo del Bloque 1— y verifícala sola.

Este es un error que compila bien y corre, pero hace algo distinto a lo que querías. Es un error de lógica, no de sintaxis. Los errores de lógica solo se detectan comparando lo que el programa imprime con lo que tú esperabas. Por eso siempre hay que ejecutar y revisar la salida.

Construir

Escribe un programa que calcule el factorial de un número n. Por ejemplo, si n = 5, el resultado es 1×2×3×4×5 = 120.

Ver solución 
int n = 5;
int i = 1;
int factorial = 1;

while (i <= n) {
    factorial = factorial * i;
    i = i + 1;
}

System.out.println("Factorial de " + n + " es: " + factorial);

Dos cosas importantes: factorial empieza en 1, no en 0, porque si empezara en 0 la multiplicación daría 0 siempre. Eso es un acumulador para productos: valor inicial 1. Y no lo declares int si el número puede ser grande: los factoriales crecen rapidísimo. Con n = 13 ya se desborda un int. Para valores grandes, usarías long. Ese detalle lo verás en otro bloque, pero conviene que sepas que existe.

Combinar

Escribe un programa que lea un número y determine cuántas cifras tiene. Asume que el número siempre es positivo.

Ver solución 
int numero = 987654;
int original = numero;
int cifras = 0;

if (numero == 0) {
    cifras = 1;
} else {
    while (numero > 0) {
        numero = numero / 10;
        cifras = cifras + 1;
    }

System.out.println("El número " + original + " tiene " + cifras + " cifras");

Este es el primer ejercicio del bloque que combina if y while juntos. Fíjate en la estructura: si el número es 0, no entraría nunca al while (porque 0 > 0 es falso), así que lo manejamos como caso especial. Si es cualquier otro número, el while se encarga. Y ojo: guardé el valor original en original antes del ciclo, porque el ciclo modifica numero y después ya no lo tendríamos.

Escribe un programa que calcule cuántos números de la secuencia de Fibonacci son menores a un límite dado. La secuencia empieza con 0, 1, 1, 2, 3, 5, 8, 13, 21... y cada número es la suma de los dos anteriores.

Con un límite de 100, el contador termina en 12.

El do while: repetir al menos una vez

Antes de Java (situación cotidiana)

Piensa en una máquina expendedora. La persona mete monedas, la máquina verifica si alcanza. Si no alcanza, pide más. Y así hasta que el saldo alcance. Pero hay algo particular en esta máquina: siempre pide monedas al menos una vez. No hay un caso en el que no pida nada. La primera interacción está garantizada; las siguientes dependen de la condición.

Ese es el patrón del do while: hay algo que siempre se ejecuta al menos una vez, y después se repite mientras se cumpla una condición. A diferencia del while, donde el cuerpo puede no ejecutarse nunca si la condición es falsa desde el principio, en el do while el cuerpo se ejecuta una vez sin preguntar, y después se evalúa la condición.

La idea en español

Un do while significa: "haz esto, y después repítelo mientras se cumpla esta condición". La diferencia clave con while es dónde se evalúa la condición:

  • while: primero pregunta, después (si aplica) hace.
  • do while: primero hace, después pregunta si repetir.

La nueva pieza

do {
    // esto se ejecuta AL MENOS UNA VEZ
} while (condición);

Nota algo importante en la sintaxis: hay un punto y coma al final del while (condición);. A diferencia del while normal, el del do while lleva ;. Es la única parte del lenguaje en la que se te va a olvidar ponerlo, y Java te va a dar error de sintaxis hasta que lo agregues. Es un buen recordatorio.

Un ejemplo concreto:

int i = 1;

do {
    System.out.println(i);
    i = i + 1;
} while (i <= 5);

Este programa imprime 1, 2, 3, 4, 5. Igual que el while que viste antes. La diferencia se nota cuando la condición inicial es falsa.

// Con while: no imprime nada
int j = 10;
while (j < 5) {
    System.out.println(j);
    j = j + 1;
}

// Con do while: imprime el 10 UNA VEZ
int k = 10;
do {
    System.out.println(k);
    k = k + 1;
} while (k < 5);

En el primer caso, la condición 10 < 5 es falsa desde el principio, así que el while no ejecuta el cuerpo nunca. En el segundo caso, el do while ejecuta el cuerpo una vez (imprime 10), y después evalúa 11 < 5, que es falsa, así que no repite. Pero esa primera impresión ya ocurrió.

Esta es la diferencia central: si necesitas que algo ocurra al menos una vez sin importar la condición, usa do while.

while vs do while: ¿cuándo usar cada uno?

La diferencia técnica ya la tienes clara: while evalúa antes, do while evalúa después. Ahora la pregunta práctica: ¿cuándo elegir uno u otro?

Usa while cuando…

  • Puede que el cuerpo no se ejecute nunca. Por ejemplo, "mientras el archivo tenga líneas pendientes, léelas". Si el archivo está vacío, no hay nada que leer, y eso es correcto.
  • La condición es fácil de evaluar antes de entrar.
  • No tienes una razón específica para garantizar una primera ejecución.

Usa do while cuando…

  • El cuerpo debe ejecutarse al menos una vez. Por ejemplo: pedirle un dato al usuario, verificar si es válido, y si no, pedirlo de nuevo. La primera vez siempre se pide.
  • La condición para repetir solo tiene sentido después de haber hecho algo. Por ejemplo: "vuelve a preguntar mientras la respuesta sea inválida".
  • Quieres que la lógica del ciclo se lea como "haz algo, y sigue haciéndolo hasta que se cumpla X".

Un ejemplo donde do while es claramente mejor

Imagina que quieres pedir un número entre 1 y 10 al usuario. El patrón natural es:

1. Pedir el número. 2. Si no está entre 1 y 10, pedirlo otra vez. 3. Repetir hasta que esté bien.

Con do while, esto se escribe directo:

// Aquí leemos de Scanner, pero imagina que "numero" ya tiene un valor inicial
int numero;

do {
    System.out.println("Ingresa un número entre 1 y 10: ");
    numero = 5;   // simulado: en la práctica sería leer con Scanner
} while (numero < 1 || numero > 10);

System.out.println("Número aceptado: " + numero);

Con while tendrías que inicializar numero con un valor "trampa" (como -1) solo para forzar a que entre la primera vez, y eso es feo. Con do while queda natural: haz la pregunta, y repite mientras la respuesta sea mala.

Regla del pulgar: si te encuentras inicializando una variable con un valor "artificial" solo para que un while entre la primera vez, probablemente quieres un do while. Si el ciclo puede legítimamente no ejecutarse nunca, quieres un while. La diferencia es si la primera ejecución está garantizada o no.

Ejemplos progresivos con do while

Ejemplo 1 — Imprimir al menos una vez

int i = 100;

do {
    System.out.println("i vale: " + i);
    i = i + 1;
} while (i < 5);

Imprime "i vale: 100" una vez, y termina. Porque aunque 100 < 5 es falso, el do ya ejecutó el cuerpo antes de preguntar. Fíjate en el contraste: si esto fuera un while, no imprimiría nada.

Ejemplo 2 — Menú que se repite hasta salir

int opcion = 0;

do {
    System.out.println("--- MENÚ ---");
    System.out.println("1. Saludar");
    System.out.println("2. Despedirse");
    System.out.println("0. Salir");

    // simulado: opcion = leer del usuario
    opcion = 1;   // cambiar a 0 para salir

    switch (opcion) {
        case 1: System.out.println("¡Hola!"); break;
        case 2: System.out.println("¡Adiós!"); break;
        case 0: System.out.println("Saliendo..."); break;
        default: System.out.println("Opción no válida");

} while (opcion != 0);

Este ejemplo es un patrón clásico: un menú que se muestra al menos una vez, ejecuta una acción según la opción, y se repite si la opción no fue "salir". Es uno de los casos donde do while es naturalmente la mejor opción. Fíjate también en el switch dentro: do while + switch es una combinación muy común para menús interactivos.

    contraseña = "abc";   // cambiar a una válida para probar

System.out.println("Contraseña aceptada");

Se pide la contraseña, se verifica su longitud, y se repite mientras sea demasiado corta. La primera petición siempre ocurre, así que tiene sentido usar do while. Aquí aparece .length(), un método que devuelve la cantidad de caracteres de un String. No es central en este bloque, pero conviene que lo reconozcas.

Errores comunes con do while

1. Olvidar el ; después del while (condición)

do {
    ...
} while (condición)   // ← falta el ;

Es el error más específico de esta estructura. Java te va a dar un error de sintaxis si lo olvidas. Cada vez que escribas un do while, revisa el final.

2. Usar do while cuando el cuerpo no debería ejecutarse si la condición es falsa

Aquí hay un caso peligroso. A veces parece natural usar do while, pero el programa se comporta mal porque el cuerpo no debería ejecutarse en ciertos casos. Por ejemplo:

// Quieres: para cada estudiante, si está inscrito, mostrar su nota
boolean inscrito = false;
double nota = 8.5;

do {
    System.out.println("Nota: " + nota);
} while (inscrito);

Este programa muestra la nota incluso si no está inscrito, porque el do ejecuta el cuerpo antes de preguntar. Si la regla es "solo mostrar si está inscrito", do while es la elección incorrecta: aquí va un if, o un while.

La lección es esta: do while no es solo un while "al revés". Son herramientas para problemas distintos. Si dudas, pregúntate: ¿tiene sentido hacer esto aunque la condición sea falsa desde el principio? Si la respuesta es no, no uses do while.

3. Bucle infinito, igual que con while

El do while tiene los mismos problemas de bucle infinito que el while. Si dentro del cuerpo no cambias la variable que controla la condición, el ciclo se repite para siempre. Y hay un caso particular aquí: como el do while siempre ejecuta el cuerpo al menos una vez, si hay bucle infinito, se queda ejecutando desde el primer intento. No hay "una evaluación inicial que te salve".

4. Inicializar mal la variable antes del do

A veces, dentro del do, la condición se refiere a una variable que todavía no tiene un valor bien establecido, y el programa se comporta raro. Aunque el do while no exige que la variable esté inicializada "correctamente" para entrar, sí la necesita para evaluar la condición después de cada vuelta. Hay que asegurarse de que el cuerpo la deje con un valor válido.

5. Confundir do while con while al modificar código

Si tienes un while que funciona y lo cambias a do while (o al revés) sin entender la diferencia, es fácil que el programa haga una vuelta extra o una vuelta de menos. Las estructuras se parecen pero no son intercambiables. Si vas a cambiar una por otra, pregúntate primero qué pasa si la condición es falsa desde el principio.

Ciclos con if adentro (el momento del bajón)

Llegamos al punto del bloque que anuncié al principio. Aquí es donde empiezan a aparecer ciclos con decisiones adentro, y es donde muchas personas sienten que "se les olvidó todo lo anterior". Vamos a ver un par de ejemplos, y después te voy a decir por qué esta sensación es normal.

Ejemplo 1 — Contar los números pares del 1 al 20

int i = 1;
int pares = 0;

while (i <= 20) {
    if (i % 2 == 0) {
        pares = pares + 1;
    }
    i = i + 1;
}

System.out.println("Pares entre 1 y 20: " + pares);

Lee esto en español: "mientras i sea menor o igual a 20: si i es par, aumenta el contador de pares. Después, aumenta i en 1". Fíjate en la indentación: el if está dentro del while, y el i = i + 1 también está dentro del while, pero fuera del if. Esa distinción es importante: el i = i + 1 se ejecuta siempre, se cumpla o no el if.

Ejemplo 2 — Sumar solo los números que cumplan una condición

int i = 1;
int suma = 0;

while (i <= 100) {
    if (i % 3 == 0) {
        suma = suma + i;
    }
    i = i + 1;
}

System.out.println("Suma de múltiplos de 3 entre 1 y 100: " + suma);

Suma solo los múltiplos de 3. El patrón es el mismo que el ejemplo anterior: contador que avanza siempre, y un if que decide si el valor actual se acumula o no.

Ejemplo 3 — Con else dentro del ciclo

int i = 1;
int positivos = 0;
int negativos = 0;

// simulado: en la práctica leeríamos números del usuario
int[] numeros = {5, -3, 7, -1, 0, 4};

while (i < numeros.length) {
    int actual = numeros[i];

    if (actual > 0) {
        positivos = positivos + 1;
    } else if (actual < 0) {
        negativos = negativos + 1;
    }

    i = i + 1;
}

System.out.println("Positivos: " + positivos);
System.out.println("Negativos: " + negativos);

Este ejemplo usa arreglos (que verás en el Bloque 6), pero lo importante aquí es la estructura: dentro del while, hay un if / else if que decide qué contador aumentar según el valor actual. Si te resulta confuso, ignora la parte de arreglos y concentra la vista en: while que recorre algo + if/else if que clasifica cada elemento.

Este es exactamente el patrón que da la sensación de "se me olvidó todo". Porque hay que sostener al mismo tiempo: la variable del ciclo, la condición del ciclo, el valor actual del elemento, la decisión del if, y dos contadores que cambian según la decisión. Es mucha información junta, y la memoria de trabajo se llena. Es el mismo fenómeno del Bloque 1: cuatro o cinco piezas nuevas al mismo tiempo.

Si esto te está costando, aquí está la explicación

No se te olvidó while. No se te olvidó if. Lo que está pasando es que estás pidiéndole a tu mente que sostenga al mismo tiempo la lógica de la repetición y la lógica de la decisión, y esas dos cosas viven en "lugares" distintos cuando las aprendes por separado. Combinarlas requiere un reacomodo. Cuando lo logras, ya no vuelves atrás: escribes ciclos con decisiones como si nada. Pero el reacomodo se siente, durante un rato, como si hubieras perdido lo que sabías. Es la misma señal de aprendizaje que ya viviste en el Bloque 2, solo que ahora es más fuerte porque son más piezas.

Este es el momento perfecto para volver al protocolo del Bloque 1. Si el ejemplo se te hizo un nudo, haz lo que dice: aísla la pieza que no entiendes. Por ejemplo, escribe solo el while que recorre del 1 al 5 sin ningún if adentro. Después agrega el if que imprime solo los pares. Después agrega el contador. Cada paso es pequeño y verificable. Si todo junto no se entiende, sepáralo en piezas y vuelve a armarlo.

  3. Leer la opción del usuario (puedes simularlo con variables, o usar Scanner si ya lo conoces del Bloque 1).
  4. Ejecutar la acción correspondiente usando un switch.
  5. Si el usuario elige retirar, pedir el monto y verificar que sea múltiplo de 100 y que no exceda el saldo. Si no cumple, mostrar un mensaje de error y no modificar el saldo.
  6. Repetir todo hasta que el usuario elija salir.

El menú debe mostrarse al menos una vez, así que el ciclo principal debería ser un do while. Y las verificaciones del retiro van adentro, usando if o switch según convenga.

Antes de escribir el código, haz el análisis en español, como en la sección "Antes de programar" del Bloque 2. Escribe los pasos en tu idioma, después tradúcelos a Java. Y cuando lo tengas, prueba el programa con varias combinaciones:

  • Consultar saldo, después salir.
  • Retirar un monto válido (por ejemplo, 200) y ver cómo cambia el saldo.
  • Retirar un monto que no es múltiplo de 100 (por ejemplo, 250).
  • Retirar un monto mayor al saldo.
  • Elegir una opción no válida (por ejemplo, 5).
Ver una posible solución 
int saldo = 1000;
int opcion = 0;

do {
    System.out.println("\n--- CAJERO ---");
    System.out.println("1. Consultar saldo");
    System.out.println("2. Retirar");
    System.out.println("3. Salir");
    System.out.println("Elige una opción: ");

    // simulado: opcion = leer del usuario
    opcion = 2;   // cambiar según se quiera probar

    switch (opcion) {
        case 1:
            System.out.println("Tu saldo es: " + saldo);
            break;

        case 2:
            System.out.println("Monto a retirar (múltiplo de 100): ");
            // simulado: monto = leer del usuario
            int monto = 200;

            if (monto % 100 != 0) {
                System.out.println("Error: el monto debe ser múltiplo de 100");
            } else if (monto > saldo) {
                System.out.println("Error: saldo insuficiente");
            } else {
                saldo = saldo - monto;
                System.out.println("Retiro exitoso. Nuevo saldo: " + saldo);
            }
            break;

        case 3:
            System.out.println("Gracias por usar el cajero");
            break;

        default:
            System.out.println("Opción no válida");
    }
} while (opcion != 3);

Fíjate en la estructura: do while exterior que envuelve todo (para que el menú se muestre al menos una vez y se repita hasta "salir"), y dentro un switch que maneja la opción elegida. Dentro del case 2, hay un if / else if / else que valida el retiro antes de aplicarlo. Es la primera vez que en el manual ves tres niveles de estructuras anidadas: do while → switch → if / else if. Si te cuesta leerlo todo junto, sigue el protocolo: aísla cada estructura y verifica que hace lo que crees que hace, después vuelve al conjunto.

Lo que llevas construido

Al terminar este bloque, tienes estas piezas nuevas:

  • switch — elegir entre muchas opciones cuando se compara el mismo dato contra valores exactos.
  • break en switch — terminar un caso. Y la idea de fall through intencional para agrupar casos.
  • while — repetir mientras se cumple una condición, evaluada antes de cada vuelta.
  • do while — repetir al menos una vez, evaluando la condición después.
  • Contadores y acumuladores — los dos patrones más comunes en ciclos.
  • Bucles infinitos — cómo reconocerlos y cómo evitarlos.
  • Ciclos con decisiones dentro — el primer uso serio de combinar todo lo aprendido.

Y estas son las piezas que combinaste de bloques anteriores:

  • Variables, tipos, operadores, booleanos (Bloque 1).
  • if, else, else if, operadores lógicos, anidados (Bloque 2).

Si miras hacia atrás, desde el inicio del manual, ya tienes una cantidad enorme de piezas. Cuando empezaste, no sabías qué era una variable. Ahora escribes ciclos con decisiones dentro, y razonas sobre el orden de las condiciones en un else if anidado en un do while. Eso no es "haber avanzado un poco". Es haber construido una base real.

El siguiente bloque introduce for, que es la estructura de repetición más usada en Java, además de break y continue. Con esas piezas, tu arsenal básico de programación va a quedar completo. Y después viene Scanner como capítulo propio, y arreglos para cerrar.
