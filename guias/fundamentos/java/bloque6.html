Arreglos

Bloque 6 — Guardar varios valores del mismo tipo

Hasta ahora cada variable guardaba un dato. Aquí aprendes a guardar muchos.

Bienvenida al Bloque 6

Hasta este punto del manual, cada variable ha guardado un solo valor. Cuando escribiste int edad = 20; o String nombre = "Ana";, esa variable tenía un único dato dentro. Si querías guardar cinco edades, tenías que declarar cinco variables distintas: edad1, edad2, edad3, edad4, edad5. Y si querías guardar cien, te tocaba escribir cien variables. Eso no escala.

Este bloque introduce la pieza que resuelve eso: los arreglos. Un arreglo es una variable que guarda muchos valores del mismo tipo, uno tras otro, con un número (un índice) para acceder a cada uno. Es como pasar de tener "una caja" a tener "una fila de casilleros numerados".

Vas a aprender:

  • Cómo declarar, crear y recorrer arreglos.
  • El índice 0, que es el segundo obstáculo universal de Java para principiantes (junto con el buffer sucio del Bloque 5).
  • Las operaciones más comunes sobre arreglos: sumar, promediar, encontrar máximo y mínimo, buscar, contar.
  • Cómo combinar arreglos con for y con Scanner.
  • Los errores clásicos: el "uno de más", el acceso fuera de rango, olvidar el tamaño.

Al final del bloque vas a escribir un proyecto integrador que combina todo lo aprendido en el manual hasta aquí: leer datos con Scanner, guardarlos en un arreglo, recorrerlos con for, tomar decisiones con if, calcular resultados. Es la primera vez que vas a escribir un programa que se parece a algo real.

Y al cerrar el bloque vas a hacer algo distinto a lo de bloques anteriores: vas a mirar hacia atrás y contar las piezas que construiste. No como ejercicio motivacional, sino como observación concreta de todo lo que tienes en la mano ahora.

¿Qué problema resuelven los arreglos?

Antes de tocar sintaxis, quiero que sientas el problema. Supón que quieres guardar las notas de 5 estudiantes y después calcular el promedio. Con lo que sabes hasta ahora, escribirías algo así:

double nota1 = 8.5;
double nota2 = 7.0;
double nota3 = 9.2;
double nota4 = 6.5;
double nota5 = 8.0;

double promedio = (nota1 + nota2 + nota3 + nota4 + nota5) / 5;

Funciona. Pero ahora imagina que el profesor tiene 40 estudiantes. Tendrías que declarar 40 variables, y escribir una suma con 40 términos. Y si el número de estudiantes cambia cada semestre, tienes que reescribir todo. Eso no es una solución escalable.

La cosa empeora si los datos vienen del usuario. Si no sabes cuántos son hasta que el usuario te lo dice, no puedes declarar las variables de antemano. Necesitas algo que te permita guardar un número variable de datos del mismo tipo, sin tener que escribir una variable por cada uno.

Ese "algo" es el arreglo. En lugar de tener cinco variables separadas, tienes una sola variable que contiene cinco casilleros. En lugar de escribir nota1 + nota2 + nota3 + nota4 + nota5, escribes un for que recorra el arreglo y sume. En lugar de saber de antemano cuántos son, usas .length para saberlo cuando lo necesites.

Antes de Java (situación cotidiana)

Piensa en los casilleros de un gimnasio. Hay una fila de casilleros, todos del mismo tamaño, cada uno con un número (el índice). Tú abres el casillero 3 y encuentras lo que guardaste. Después abres el 5 y encuentras otra cosa. No importa qué haya dentro: lo importante es que hay un número único para cada casillero, y que todos los casilleros son iguales (mismo tamaño, mismo tipo de contenido).

Un arreglo es exactamente eso: una fila de casilleros numerados, todos del mismo tipo, con un índice para acceder a cada uno. El "tipo" es lo que le dice a Java cuánto espacio reservar y qué se puede guardar dentro. La "posición" es el índice, que va del 0 al tamaño menos uno.

La idea en español

Cuando necesites guardar muchos valores del mismo tipo, y el número no es enorme (no cientos de miles), probablemente quieras un arreglo. Si necesitas guardar valores de tipos distintos, o si el número cambia mucho durante la ejecución, los arreglos no son la herramienta adecuada (verías colecciones como ArrayList, que están fuera del alcance de esta primera parte del manual).

La idea central: un arreglo es una variable con muchos casilleros, todos del mismo tipo, accesibles por índice. Y esa estructura te permite recorrerlos, buscar en ellos, calcular cosas sobre ellos, etc., sin escribir código repetido por cada elemento.

Declarar y crear un arreglo

Un arreglo en Java se declara indicando el tipo de sus elementos seguido de corchetes [], y el nombre de la variable:

int[] edades;

Eso declara una variable llamada edades que puede guardar un arreglo de enteros. Pero todavía no tiene elementos: es solo la declaración. Para crearlo con un tamaño específico, se usa new:

int[] edades = new int[5];

Esta línea hace tres cosas a la vez:

  • Declara una variable edades que es un arreglo de int.
  • Crea un arreglo con espacio para 5 enteros.
  • Guarda la referencia al arreglo en la variable.

Al crearlo, los 5 casilleros se inicializan automáticamente con el valor por defecto del tipo:

  • int, long, short, byte → 0
  • double, float → 0.0
  • boolean → false
  • char → '\u0000' (carácter nulo)
  • Cualquier objeto (incluyendo String) → null

Un arreglo de 5 enteros recién creado se ve así:

[0]0
[1]0
[2]0
[3]0
[4]0

Cada casillero tiene un número, que va del 0 al 4. Y cada uno guarda un 0 mientras no le asignes otro valor.

Forma alternativa de declaración

Java también acepta los corchetes después del nombre, pero es menos común:

int[] edades;      // ← forma preferida
int edades[];      // ← funciona, pero menos común

En este manual usamos siempre la primera forma (int[]), porque es más clara: dice "el tipo es arreglo de int". La segunda forma sugiere que el tipo es int y que la variable es un arreglo, lo cual es confuso.

Acceder a un elemento con el índice

Para leer o modificar un elemento del arreglo, se usa el nombre del arreglo seguido del índice entre corchetes:

int[] edades = new int[5];

edades[0] = 20;   // guarda 20 en el primer casillero
edades[1] = 19;   // guarda 19 en el segundo
edades[2] = 21;

System.out.println(edades[0]);   // muestra 20
System.out.println(edades[2]);   // muestra 21

edades[0] = 25;               // cambia el primer casillero
System.out.println(edades[0]);   // ahora muestra 25

Fíjate en que el [] después del nombre no es un tipo: es un acceso por índice. edades[0] significa "el casillero en la posición 0 del arreglo edades". Funciona tanto para leer (asignándolo a otra variable o usándolo en una expresión) como para escribir (asignándole un valor).

Después de las tres asignaciones del ejemplo, el arreglo se ve así:

[0]20
[1]19
[2]21
[3]0
[4]0

Y después de la reasignación de edades[0] = 25:

[0]25
[1]19
[2]21
[3]0
[4]0

El índice empieza en 0 (el segundo obstáculo universal)

Aquí llegamos al detalle más importante del bloque, y al segundo obstáculo universal de Java para principiantes (después del buffer sucio del Bloque 5). El primer elemento de un arreglo está en el índice 0, no en el 1.

Esto contradice la forma en que contamos en la vida cotidiana. Cuando cuentas casilleros, empiezas en "el primero", que intuitivamente asignarías al número 1. Cuando cuentas pisos de un edificio, empiezas en "el primer piso" o "la planta baja". En casi toda la vida diaria, el primer elemento tiene número 1.

En Java (y en la mayoría de los lenguajes de programación), el primer elemento de un arreglo tiene índice 0. Un arreglo de tamaño 5 tiene elementos en las posiciones 0, 1, 2, 3 y 4. No hay posición 5.

Veamos un arreglo con valores concretos, para fijar la idea:

int[] numeros = new int[5];
numeros[0] = 10;
numeros[1] = 20;
numeros[2] = 30;
numeros[3] = 40;
numeros[4] = 50;
[0]10
[1]20
[2]30
[3]40
[4]50

El "primer elemento" es numeros[0], que vale 10. El "último elemento" es numeros[4], que vale 50. El tamaño es 5, y la última posición válida es 4 (tamaño - 1).

Antes de que te pase: este error lo va a cometer todo el mundo

Si estás pensando "¿por qué no empiezan en 1, no sería más simple?", la respuesta corta es: por razones históricas y matemáticas que no vale la pena discutir ahora. Lo que importa es que el índice empieza en 0, y eso hay que interiorizarlo. Que el primer elemento sea 0 y no 1 contradice un hábito de conteo que arrastramos desde la infancia, así que al principio vas a cometer errores de "uno de más" o "uno de menos". No es falta de atención: es literalmente el tipo de cosa que confunde al cerebro humano cuando se encuentra con una convención que contradice sus hábitos. A todos nos pasó. Con práctica, en algún momento deja de ser un problema. Mientras tanto, si te sale un error de índice fuera de rango, ya sabes por dónde buscar.

El detalle que se vuelve trampa: .length no es el último índice

.length (que veremos en la siguiente sección) te dice cuántos elementos hay, no cuál es el último índice. Si numeros.length es 5, entonces el último índice válido es 4, no 5. Esa diferencia de 1 es el origen de la mayoría de los errores con arreglos.

Si length = 5 → índices válidos: 0, 1, 2, 3, 4 → último índice: length - 1 = 4 Si length = 10 → índices válidos: 0 a 9 → último índice: length - 1 = 9 Si length = 100 → índices válidos: 0 a 99 → último índice: length - 1 = 99

Regla general: cuando recorras un arreglo con un for, la condición correcta casi siempre es i < arreglo.length, no i <= arreglo.length. Lo vas a ver en la sección de recorrido con más detalle.

El tamaño de un arreglo: .length

Todo arreglo en Java tiene un "atributo" llamado length que te dice cuántos elementos puede guardar. Se accede con un punto y sin paréntesis (importante: sin paréntesis, a diferencia de los métodos):

int[] numeros = new int[5];

System.out.println(numeros.length);   // 5

El .length es de solo lectura: no se puede cambiar. Una vez que un arreglo se crea con un tamaño, ese tamaño es fijo. Si necesitas uno más grande, tienes que crear un arreglo nuevo y copiar los valores.

// Esto NO compila: length es de solo lectura
numeros.length = 10;

Este detalle es importante: en Java, los arreglos son estáticos. Tienen un tamaño fijo desde que se crean. Si necesitas una estructura que crezca y se encoja dinámicamente, usarías ArrayList (que está fuera del alcance de esta primera parte del manual, pero mencionamos que existe).

Uso más común: recorrer con for

El .length aparece casi siempre en la condición de un for que recorre un arreglo:

for (int i = 0; i < numeros.length; i++) {
    System.out.println(numeros[i]);
}

Fíjate en la condición: i < numeros.length, con menor estricto, no <=. Como el último índice válido es length - 1, la condición i < length deja a i llegar hasta length - 1. Si pusieras <=, en la última vuelta intentarías acceder a numeros[length], que no existe, y Java lanzaría un error. Esta es la trampa más común con arreglos, y volveremos a ella varias veces.

Ventaja de usar .length en lugar de un número fijo: si cambias el tamaño del arreglo, el for se adapta automáticamente. Es más seguro y más flexible.

Inicialización directa (arreglos con valores concretos)

Cuando ya sabes cuáles son los valores del arreglo al crearlo, hay una forma más compacta de declararlos:

int[] numeros = {10, 20, 30, 40, 50};

Esta línea hace lo mismo que las 6 líneas de la sección anterior (declarar y llenar), pero en una sola. El tamaño del arreglo queda determinado por la cantidad de elementos que pusiste entre las llaves. En este caso, 5.

El arreglo que resulta es idéntico al de antes:

[0]10
[1]20
[2]30
[3]40
[4]50

La inicialización directa sirve también para otros tipos:

String[] nombres = {"Ana", "Luis", "Pedro"};
double[] precios = {19.99, 25.50, 9.75};
boolean[] estados = {true, false, true, false};
char[] letras = {'a', 'b', 'c'};

Los String van con comillas dobles, los char con comillas simples, los double con punto decimal. Las reglas son las mismas que para cualquier variable suelta.

Una nota importante: la inicialización directa solo se puede usar en la declaración. No puedes hacer esto más adelante:

int[] numeros;
numeros = {10, 20, 30};   // ← esto NO compila

// Pero esto sí:
int[] numeros;
numeros = new int[]{10, 20, 30};   // ← con new y el tipo

Es un detalle sintáctico que no vas a usar mucho, pero conviene saberlo por si te topas con él.

Recorrer un arreglo con for

El for del Bloque 4 y los arreglos están hechos el uno para el otro. La mayoría de las operaciones sobre arreglos se escriben con un for que recorre todos los elementos. El patrón básico es este:

int[] numeros = {10, 20, 30, 40, 50};

for (int i = 0; i < numeros.length; i++) {
    System.out.println(numeros[i]);
}

Imprime 10, 20, 30, 40, 50, cada uno en su propia línea. Las tres partes del for están calibradas para arreglos:

  • Inicio en 0: int i = 0. Porque el primer índice del arreglo es 0.
  • Condición con <: i < numeros.length. Porque el último índice válido es length - 1, entonces i puede llegar hasta length - 1 pero no más.
  • Incremento de 1 en 1: i++. Porque queremos recorrer todas las posiciones sin saltarnos ninguna.

Este patrón (for (int i = 0; i < arreglo.length; i++)) es tan común que tu ojo lo va a reconocer al instante después de verlo unas cuantas veces. Es el "recorrido estándar" de un arreglo.

Recorrido hacia atrás

También puedes recorrer un arreglo en orden inverso:

for (int i = numeros.length - 1; i >= 0; i--) {
    System.out.println(numeros[i]);
}

El inicio es numeros.length - 1 (el último índice válido), la condición es i >= 0 (mientras no llegue a cero), y el incremento es i-- (decremento). Imprime 50, 40, 30, 20, 10.

Fíjate en numeros.length - 1: es la forma estándar de referirse al último índice de un arreglo. Es un detalle pequeño pero importante, y lo vas a escribir muchas veces.

Recorrido parcial

No siempre recorres todo el arreglo. A veces solo los primeros N elementos, o desde una posición hasta otra:

// Solo los primeros 3
for (int i = 0; i < 3; i++) {
    System.out.println(numeros[i]);
}

// Desde la posición 2 hasta el final
for (int i = 2; i < numeros.length; i++) {
    System.out.println(numeros[i]);
}

El recorrido es la herramienta básica sobre arreglos. Casi todo lo que hagas con ellos va a pasar dentro de un for que los recorre.

Simulación paso a paso del recorrido

Vamos a ejecutar mentalmente el recorrido estándar con un arreglo concreto, para que veas cómo se mueve i y qué se imprime en cada vuelta. Esto es la mejor forma de entender cómo se combinan for y arreglos.

El programa

int[] numeros = {10, 20, 30, 40, 50};

for (int i = 0; i < numeros.length; i++) {
    System.out.println(numeros[i]);
}

Paso a paso

Fíjate en dos cosas:

  • i toma los valores 0, 1, 2, 3, 4 dentro del cuerpo del ciclo. Nunca llega a 5 dentro. La condición i < numeros.length permite que i sea hasta 4 (que es length - 1), pero cuando i vale 5, la condición falla y el cuerpo no se ejecuta.
  • Todas las posiciones del arreglo quedan cubiertas: 0, 1, 2, 3, 4. Ninguna se salta. Ninguna se sale del rango.

Qué pasaría si la condición fuera <=

Este es el error más común. Vamos a verlo porque vale la pena:

// MAL: la condición usa <=, va a fallar en la última vuelta
for (int i = 0; i <= numeros.length; i++) {
    System.out.println(numeros[i]);
}

Con esta condición, i va a llegar a 5 (numeros.length). Y numeros[5] no existe: el arreglo tiene elementos en las posiciones 0 a 4. Cuando Java intente acceder a numeros[5], va a lanzar un error ArrayIndexOutOfBoundsException, y el programa termina abruptamente.

10 20 30 40 50 Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 5 at Ejemplo.main(Ejemplo.java:4)

La lección: cuando recorres un arreglo, la condición correcta es i < arreglo.length, con menor estricto. Es la causa número uno de errores con arreglos, y es la razón por la que insistimos tanto en la diferencia entre .length (cantidad) y el último índice (cantidad - 1).

El for-each (opcional, para cuando lo veas)

Java tiene una forma abreviada de recorrer arreglos y colecciones, que se llama for-each. Su sintaxis es:

for (int valor : numeros) {
    System.out.println(valor);
}

Se lee: "para cada valor (de tipo int) en numeros, haz esto". El : significa "en". En cada vuelta, valor toma el valor de un elemento del arreglo, en orden. No hay que manejar índice.

Es más limpio cuando solo quieres leer los elementos y no necesitas saber en qué posición estás. Cuando necesitas el índice (por ejemplo, para modificar el arreglo o para imprimir la posición), tienes que usar el for clásico.

Comparación:

// for clásico: tienes el índice
for (int i = 0; i < numeros.length; i++) {
    System.out.println("Posición " + i + ": " + numeros[i]);
}

// for-each: solo el valor
for (int valor : numeros) {
    System.out.println(valor);
}

Ambos son válidos. En este manual usamos preferentemente el for clásico, porque el índice te da más información y te obliga a pensar en la posición. El for-each lo menciono porque lo vas a ver en código ajeno, y conviene reconocerlo. Cuando te sientas cómodo con el for clásico, puedes empezar a usar for-each en los casos donde el índice no importa.

Un detalle importante: el for-each no te permite modificar el arreglo (bueno, no directamente: valor es una copia del elemento, no una referencia). Si quieres cambiar los valores, tienes que usar el for clásico.

Sumar y promediar los elementos

Una de las operaciones más comunes sobre un arreglo es sumar sus elementos. Se hace con un acumulador (patrón del Bloque 3) y un for:

int[] numeros = {10, 20, 30, 40, 50};
int suma = 0;

for (int i = 0; i < numeros.length; i++) {
    suma += numeros[i];
}

System.out.println("Suma: " + suma);   // 150

El acumulador suma empieza en 0 y va sumando cada elemento. Al final del recorrido, tiene la suma total.

Para el promedio, solo hay que dividir entre la cantidad de elementos (que es numeros.length):

double promedio = (double) suma / numeros.length;
System.out.println("Promedio: " + promedio);   // 30.0

El cast (double) es importante para que la división no sea entera. Sin él, 150 / 5 daría 30 (que aquí casualmente coincide), pero 151 / 5 daría 30 en vez de 30.2. Es el mismo detalle de la división entera del Bloque 1.

Encontrar el máximo y el mínimo

Otro patrón muy útil: encontrar el valor más alto (o más bajo) de un arreglo.

int[] numeros = {45, 12, 78, 33, 60, 91, 5};

int mayor = numeros[0];   // suponemos que el primero es el mayor

for (int i = 1; i < numeros.length; i++) {
    if (numeros[i] > mayor) {
        mayor = numeros[i];
    }
}

System.out.println("El mayor es: " + mayor);   // 91

La idea: empiezas suponiendo que el primero es el mayor. Después recorres el resto, y si encuentras uno más grande, lo actualizas. Al terminar el recorrido, mayor tiene el valor máximo. Fíjate en que el for empieza en i = 1, no en 0, porque el elemento en 0 ya lo usamos como valor inicial.

Para el mínimo, es igual pero con el signo contrario:

int menor = numeros[0];

for (int i = 1; i < numeros.length; i++) {
    if (numeros[i] < menor) {
        menor = numeros[i];
    }
}

Un detalle: hay que asegurarse de que el arreglo no esté vacío. Si numeros.length es 0, numeros[0] lanza una excepción. En programas reales, se verifica primero:

if (numeros.length == 0) {
    System.out.println("El arreglo está vacío");
} else {
    // buscar máximo o mínimo
}

Por ahora, asume que los arreglos no están vacíos. Pero ten presente que, en código real, este tipo de chequeos son importantes.

Buscar un valor en el arreglo

Otro patrón clásico: buscar si un valor está en el arreglo, y en qué posición.

int[] numeros = {45, 12, 78, 33, 60, 91, 5};
int buscado = 33;
int posicion = -1;   // -1 = no encontrado

for (int i = 0; i < numeros.length; i++) {
    if (numeros[i] == buscado) {
        posicion = i;
        break;   // ya lo encontré, no sigo buscando
    }
}

if (posicion != -1) {
    System.out.println(buscado + " está en la posición " + posicion);
} else {
    System.out.println(buscado + " no está en el arreglo");
}

Es el mismo patrón de búsqueda que viste con arreglos en el Bloque 4, ahora aplicado directamente. Los detalles:

  • posicion = -1 como valor inicial significa "no encontrado". Como los índices válidos son 0 o más, -1 no puede ser una posición real.
  • El break sale del ciclo en cuanto se encuentra el valor. No tiene sentido seguir buscando.
  • Al final, se verifica posicion != -1 para saber si se encontró.

Si solo quieres saber si está (sin importar dónde), puedes usar un boolean:

boolean encontrado = false;

for (int i = 0; i < numeros.length; i++) {
    if (numeros[i] == buscado) {
        encontrado = true;
        break;
    }
}

Ambos patrones (con posicion o con boolean) son válidos, y dependen de si necesitas saber la ubicación o solo la existencia.

Contar elementos que cumplen una condición

Combinando for y if dentro del arreglo, puedes contar cuántos elementos cumplen algo:

int[] notas = {85, 45, 92, 78, 60, 30, 90};
int aprobados = 0;
int reprobados = 0;

for (int i = 0; i < notas.length; i++) {
    if (notas[i] >= 60) {
        aprobados++;
    } else {
        reprobados++;
    }
}

System.out.println("Aprobados: " + aprobados);       // 5
System.out.println("Reprobados: " + reprobados);     // 2

Fíjate en la estructura: es un for con un if / else adentro. Cada elemento del arreglo se clasifica, y los contadores llevan la cuenta. Este patrón aparece muchísimo en análisis de datos.

Otra variante: contar los que cumplen una condición específica, sin importar los que no:

int pares = 0;

for (int i = 0; i < numeros.length; i++) {
    if (numeros[i] % 2 == 0) {
        pares++;
    }
}

Este patrón —recorrer, verificar, contar— es el esqueleto de la mayoría de los análisis que vas a hacer con arreglos.

Invertir y copiar

Dos operaciones más que vale la pena conocer.

Invertir un arreglo

Para invertir los elementos de un arreglo (el primero pasa al final, el último al inicio), se recorre desde los dos extremos hacia el centro e intercambia:

int[] numeros = {10, 20, 30, 40, 50};

for (int i = 0; i < numeros.length / 2; i++) {
    int temp = numeros[i];
    numeros[i] = numeros[numeros.length - 1 - i];
    numeros[numeros.length - 1 - i] = temp;
}

Este patrón intercambia el elemento en i con el elemento en length - 1 - i. La variable temp es necesaria porque, si no, al asignar pierdes el valor original. El ciclo solo recorre la mitad del arreglo, porque cada iteración intercambia dos elementos a la vez.

Si te resulta complejo, no te preocupes: es un ejercicio avanzado. Lo incluimos porque saber que existe ayuda cuando lo veas en el futuro.

Copiar un arreglo

Si asignas un arreglo a otro con =, no estás copiando los valores: estás copiando la referencia. Los dos nombres apuntan al mismo arreglo, y modificar uno modifica el otro.

int[] a = {10, 20, 30};
int[] b = a;   // b y a apuntan al MISMO arreglo

b[0] = 99;
System.out.println(a[0]);   // imprime 99, porque a y b son el mismo arreglo

Para copiar de verdad los valores, hay que crear un arreglo nuevo y copiar uno por uno:

int[] a = {10, 20, 30};
int[] b = new int[a.length];

for (int i = 0; i < a.length; i++) {
    b[i] = a[i];
}

b[0] = 99;
System.out.println(a[0]);   // ahora sí imprime 10

Este es un concepto importante que a veces sorprende: en Java, los arreglos son objetos, y las variables guardan referencias a ellos, no los valores. Es un detalle que profundizaremos más adelante si seguimos ampliando el manual, pero conviene saberlo desde ahora.

El error del "uno de más": ArrayIndexOutOfBoundsException

El error más común con arreglos. Ya lo mencionamos al hablar del índice 0, pero conviene dedicarle su propia sección porque es el obstáculo con el que más se van a topar.

Se lanza cuando intentas acceder a un índice que no existe. Por ejemplo:

int[] numeros = {10, 20, 30, 40, 50};
System.out.println(numeros[5]);   // ← no existe, length es 5

El mensaje que muestra Java es:

Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 5 at Ejemplo.main(Ejemplo.java:2)

Se lee: "índice 5 fuera de los límites para un arreglo de longitud 5". El arreglo tiene 5 elementos (índices 0 a 4), y le pediste el 5. Ese índice no existe.

Causas típicas

  • Condición con <= en lugar de <: for (int i = 0; i <= numeros.length; i++). Ya lo vimos. Es la causa número uno.
  • Confundir .length con el último índice: si length es 5, el último índice válido es 4. Usar numeros[numeros.length] en vez de numeros[numeros.length - 1] da error.
  • Acceder a un índice negativo: numeros[-1]. Ocurre cuando un cálculo de índice sale mal (por ejemplo, si olvidas que i - 1 cuando i es 0 da -1).
  • Iterar sobre un arreglo cuyo tamaño no es el que creías: si declaras int[] a = new int[5] pero luego piensas que tiene más elementos, los accesos fuera de rango fallan.

El caso del "uno de más" en su forma más común

Mira este fragmento y predice qué pasa:

int[] numeros = {10, 20, 30};

for (int i = 0; i <= numeros.length; i++) {
    System.out.println(numeros[i]);
}
Ver respuesta

Imprime 10, 20, 30, y después lanza ArrayIndexOutOfBoundsException. Porque length es 3, y la condición i <= 3 permite que i llegue a 3. numeros[3] no existe (los índices válidos son 0, 1, 2).

El error es ese <= en la condición. Debería ser <: for (int i = 0; i < numeros.length; i++).

Este es el error del "uno de más". No es que el programa esté mal escrito: es que la condición usa el operador incorrecto. Y como se escribe rápido, es fácil de cometer. La buena noticia es que el mensaje de error dice exactamente el problema: "índice X fuera de límites para longitud Y". Es una de las pocas excepciones donde el mensaje es muy claro.

Cuando te salga este error

No significa que "no entiendas arreglos". Significa que un acceso específico está fuera de rango. Aplica el protocolo: mira el mensaje, ve a la línea que dice el error, verifica el valor del índice en esa línea y el tamaño del arreglo. Casi siempre es un <= donde iba <, o un length donde iba length - 1. Aislar la línea y pensar en esos dos detalles resuelve el 90% de los casos.

Otros errores comunes con arreglos

1. Olvidar el new al crear el arreglo

// MAL
int[] numeros;
numeros[0] = 10;   // ← no se ha creado el arreglo

// BIEN
int[] numeros = new int[5];
numeros[0] = 10;

Declarar un arreglo no lo crea. Hay que usar new int[tamaño] o la inicialización directa con {}. Si no lo haces, Java te da un error de "variable might not have been initialized".

2. Confundir el tamaño con el último índice

int[] numeros = new int[5];

// MAL: 5 no es un índice válido
numeros[5] = 100;

// BIEN: el último índice es 4
numeros[4] = 100;

Esta es la misma idea que ya vimos. El tamaño es cuántos elementos hay. El último índice es tamaño - 1. Si length es 5, los índices van de 0 a 4, no de 0 a 5.

3. Creer que .length es un método

// MAL
numeros.length()   // ← en arreglos NO lleva paréntesis

// BIEN
numeros.length

// OJO: para String SÍ lleva paréntesis
palabra.length()   // ← String.length() es método, sí lleva paréntesis

Este es un detalle que confunde. En los arreglos, length es un atributo, no un método. En los String, length() sí es un método, con paréntesis. Es inconsistente, y no hay nada que hacer: hay que memorizar que arreglos van sin paréntesis y Strings con paréntesis.

4. Modificar un arreglo mientras lo recorres de forma incorrecta

Si dentro del for modificas el tamaño del arreglo (lo cual no se puede directamente, porque el tamaño es fijo), o si modificas la variable i dentro del cuerpo, el recorrido puede comportarse raro. Regla: no modifiques i dentro del cuerpo del for, salvo en casos muy específicos.

5. Olvidar que los arreglos son fijos

Un arreglo tiene un tamaño fijo desde que se crea. No puedes agregar más elementos después. Si necesitas uno más grande, tienes que crear uno nuevo, copiar los elementos, y usar el nuevo:

int[] original = {10, 20, 30};
int[] masGrande = new int[5];

for (int i = 0; i < original.length; i++) {
    masGrande[i] = original[i];
}

masGrande[3] = 40;
masGrande[4] = 50;

Esto es incómodo, y es una de las razones por las que existe ArrayList, que sí crece dinámicamente. No lo vamos a ver en esta primera parte del manual porque tiene bastante sintaxis propia, pero conviene saber que existe.

6. Comparar arreglos con ==

Esto sorprende. a == b compara si son el mismo arreglo (misma referencia), no si tienen el mismo contenido.

int[] a = {1, 2, 3};
int[] b = {1, 2, 3};

System.out.println(a == b);   // false, son arreglos distintos

Aunque tienen el mismo contenido, a == b es false porque son dos objetos distintos en memoria. Para comparar contenido, tienes que recorrer y comparar elemento por elemento, o usar Arrays.equals(a, b) (que requiere import java.util.Arrays;).

Este detalle es el mismo tipo de cosa que la diferencia entre == y .equals en String que viste en el Bloque 1. Es un concepto recurrente en Java, y vale la pena tenerlo presente.

Arreglos y Scanner: leer N valores del usuario

Aquí es donde las piezas se combinan. La situación: el usuario te dice cuántos valores quiere ingresar, y tú los guardas todos en un arreglo para procesarlos después.

import java.util.Scanner;

public class LeerArreglo {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        System.out.print("¿Cuántos números quieres ingresar? ");
        int n = Integer.parseInt(scanner.nextLine());

        int[] numeros = new int[n];

        for (int i = 0; i < n; i++) {
            System.out.print("Número " + (i + 1) + ": ");
            numeros[i] = Integer.parseInt(scanner.nextLine());
        }

        // Mostrar los valores ingresados
        System.out.println("Ingresaste:");
        for (int i = 0; i < n; i++) {
            System.out.println(numeros[i]);
        }
    }
}

Fíjate en la estructura:

  • Se lee n (cuántos números).
  • Se crea un arreglo de tamaño n con new int[n].
  • Se recorre con un for, pidiendo y guardando cada valor en numeros[i].
  • Después, se recorre otra vez para mostrar los valores.

Nota el uso de Integer.parseInt(scanner.nextLine()) en lugar de scanner.nextInt(). Es el patrón que recomendamos en el Bloque 5: leer todo con nextLine y parsear. Evita el problema del buffer sucio y es consistente.

Un detalle de la impresión: i + 1

En el mensaje "Número " + (i + 1), se usa i + 1 en lugar de i para mostrar al usuario. Porque el índice i va de 0 a n - 1, pero al usuario le resulta más natural ver "Número 1", "Número 2", etc. Es un detalle pequeño de UX (experiencia de usuario): el índice es 0, pero el mensaje dice 1.

Esta es una decisión común: internamente los índices van de 0, pero en los mensajes al usuario, sumas 1. Lo vas a ver mucho en programas reales.

Leer con validación

El ejemplo anterior falla si el usuario escribe algo que no es un número. Para robustecerlo, se combina con el patrón de validación del Bloque 5:

import java.util.Scanner;

public class LeerArregloValidado {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        int n = 0;
        while (n < 1) {
            System.out.print("¿Cuántos números? (al menos 1): ");

            while (!scanner.hasNextInt()) {
                scanner.nextLine();
                System.out.print("Ingresa un número entero: ");
            }
            n = scanner.nextInt();
            scanner.nextLine();   // limpiar el buffer
        }

        int[] numeros = new int[n];

        for (int i = 0; i < n; i++) {
            System.out.print("Número " + (i + 1) + ": ");

            while (!scanner.hasNextInt()) {
                scanner.nextLine();
                System.out.print("Ingresa un número válido: ");
            }
            numeros[i] = scanner.nextInt();
            scanner.nextLine();
        }

        System.out.println("Ingresaste:");
        for (int i = 0; i < n; i++) {
            System.out.println(numeros[i]);
        }
    }
}

Este programa es más robusto. Si el usuario escribe algo que no es un entero, el while interno pide de nuevo. Fíjate en los dos niveles del patrón de validación: uno para n (el tamaño), y otro para cada elemento dentro del for.

Es un poco más de código, pero es el tipo de código que se usa en programas reales. Los usuarios se equivocan, y un programa que no maneja eso es un programa frágil.

Arreglos de String

Todo lo que has visto aplica también a arreglos de otros tipos. Veamos uno con String:

String[] nombres = {"Ana", "Luis", "Pedro", "María", "Sofía"};

for (int i = 0; i < nombres.length; i++) {
    System.out.println(nombres[i]);
}

Funciona exactamente igual que con int. Los detalles adicionales aparecen cuando empiezas a hacer operaciones sobre los Strings:

// Buscar un nombre en el arreglo
String buscado = "Pedro";
boolean encontrado = false;

for (int i = 0; i < nombres.length; i++) {
    if (nombres[i].equals(buscado)) {   // ← .equals, no ==
        encontrado = true;
        break;
    }
}

// Convertir todos a mayúsculas
for (int i = 0; i < nombres.length; i++) {
    nombres[i] = nombres[i].toUpperCase();
}

El detalle importante: .equals() para comparar Strings (nunca ==). Es el mismo detalle del Bloque 1, ahora aplicado a arreglos. Este tipo de "detalles recurrentes" son los que vale la pena tener siempre presentes.

Y otra cosa: los Strings son objetos, y los arreglos de Strings guardan referencias. Si un elemento del arreglo nunca se asigna, su valor es null, no "". Es una diferencia sutil pero importante cuando haces operaciones sobre ellos.

Arreglos bidimensionales (opcional)

Hasta ahora, todos los arreglos han sido de una dimensión: una fila de elementos. Java también permite arreglos de dos dimensiones (como una tabla con filas y columnas), que se declaran con doble corchete:

int[][] matriz = {
    {1, 2, 3},
    {4, 5, 6},
    {7, 8, 9}
};

Esta es una matriz de 3×3. Se accede a los elementos con dos índices:

System.out.println(matriz[1][2]);   // 6 (fila 1, columna 2)
System.out.println(matriz[0][0]);   // 1

Se recorren con dos for anidados, como en el Bloque 4:

for (int fila = 0; fila < matriz.length; fila++) {
    for (int col = 0; col < matriz[fila].length; col++) {
        System.out.print(matriz[fila][col] + " ");
    }
    System.out.println();
}

Fíjate en matriz[fila].length: cada fila es en sí misma un arreglo de una dimensión, y tiene su propio length. Esto permite que las filas tengan tamaños distintos (aunque en una matriz regular todas tienen el mismo tamaño).

Los arreglos bidimensionales son útiles para representar tablas, matrices matemáticas, tableros de juegos, etc. Los mencionamos aquí como opcional, porque van más allá de lo que se necesita para dominar los arreglos básicos. Cuando te sientas cómodo con arreglos de una dimensión, esto es un siguiente paso natural.

Ejemplos progresivos con arreglos

Ejemplo 1 — Crear y mostrar

int[] numeros = {10, 20, 30, 40, 50};

for (int i = 0; i < numeros.length; i++) {
    System.out.println("Posición " + i + ": " + numeros[i]);
}

El ejemplo más básico. Declara un arreglo con valores, lo recorre con el patrón estándar, e imprime cada elemento con su posición.

Ejemplo 2 — Suma y promedio

double[] notas = {8.5, 7.0, 9.2, 6.5, 8.0};
double suma = 0;

for (int i = 0; i < notas.length; i++) {
    suma += notas[i];
}

double promedio = suma / notas.length;

System.out.println("Suma: " + suma);
System.out.println("Promedio: " + promedio);

Suma total 39.2, promedio 7.84. Fíjate en que suma es double, porque los elementos son double. Si la hubieras declarado como int, se perderían los decimales en cada suma.

Ejemplo 3 — Encontrar el mayor

int[] numeros = {45, 12, 78, 33, 60, 91, 5};
int mayor = numeros[0];
int posicionMayor = 0;

for (int i = 1; i < numeros.length; i++) {
    if (numeros[i] > mayor) {
        mayor = numeros[i];
        posicionMayor = i;
    }
}

System.out.println("Mayor: " + mayor + " en posición " + posicionMayor);

Imprime "Mayor: 91 en posición 5". Aquí no solo guardamos el mayor, también dónde estaba. Es útil cuando quieres saber no solo cuál es el mayor, sino en qué posición del arreglo está.

Ejemplo 4 — Contar y clasificar

int[] calificaciones = {85, 45, 92, 78, 60, 30, 90, 55};

int excelentes = 0;   // >= 90
int buenos = 0;      // 80-89
int regulares = 0;   // 60-79
int reprobados = 0;  // < 60

for (int i = 0; i < calificaciones.length; i++) {
    int nota = calificaciones[i];

    if (nota >= 90) {
        excelentes++;
    } else if (nota >= 80) {
        buenos++;
    } else if (nota >= 60) {
        regulares++;
    } else {
        reprobados++;
    }
}

System.out.println("Excelentes: " + excelentes);
System.out.println("Buenos: " + buenos);
System.out.println("Regulares: " + regulares);
System.out.println("Reprobados: " + reprobados);

Recorrido + clasificación. Combina los patrones del Bloque 3 (contadores) con los arreglos. Es el patrón que vas a usar para casi cualquier análisis de datos.

Ejemplo 5 — Arreglo con entrada del usuario, análisis completo

import java.util.Scanner;

public class AnalisisNotas {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        System.out.print("¿Cuántas notas vas a ingresar? ");
        int n = Integer.parseInt(scanner.nextLine());

        double[] notas = new double[n];

        for (int i = 0; i < n; i++) {
            System.out.print("Nota " + (i + 1) + ": ");
            notas[i] = Double.parseDouble(scanner.nextLine());
        }

        // Cálculos
        double suma = 0;
        double mayor = notas[0];
        double menor = notas[0];
        int aprobadas = 0;

        for (int i = 0; i < n; i++) {
            suma += notas[i];

            if (notas[i] > mayor) mayor = notas[i];
            if (notas[i] < menor) menor = notas[i];
            if (notas[i] >= 6) aprobadas++;
        }

        double promedio = suma / n;

        System.out.println("\n--- Análisis ---");
        System.out.println("Cantidad: " + n);
        System.out.println("Promedio: " + promedio);
        System.out.println("Mayor: " + mayor);
        System.out.println("Menor: " + menor);
        System.out.println("Aprobadas: " + aprobadas + " de " + n);
    }
}

Este es el ejemplo más completo. Combina Scanner (Bloque 5), arreglos (este bloque), for (Bloque 4), if (Bloque 2), y todo lo demás. Es un mini-programa con entrada, procesamiento y salida. Todo lo que has aprendido hasta aquí está aquí.

Un detalle: los cálculos (suma, mayor, menor, aprobadas) se hacen en un solo for, no en varios. Cada vez que recorres un arreglo, si puedes aprovechar para hacer varios cálculos, mejor. Recorrer un arreglo múltiples veces es ineficiente, y es una cosa que los programadores experimentados evitan cuando pueden.

Ejercicios de arreglos

Reconocer

¿Qué imprime este programa?

int[] arr = {5, 10, 15, 20};

for (int i = 0; i < arr.length; i++) {
    System.out.println(arr[i] * 2);
}
Ver solución

Imprime 10, 20, 30, 40, cada uno en su línea. El for recorre el arreglo con el patrón estándar, y multiplica cada elemento por 2 antes de imprimirlo.

Completar

Completa el código para que cree un arreglo de 10 enteros y lo recorra mostrando cada elemento.

int[] numeros = ______________;

for (int i = 0; ______________; i++) {
    System.out.println(numeros[i]);
}
Ver solución

Primer espacio: new int[10]. Segundo espacio: i < numeros.length (o i < 10, aunque usar .length es más flexible).

Modificar

Este programa debería sumar todos los elementos del arreglo, pero siempre devuelve el último. Encuentra y corrige el error.

int[] numeros = {10, 20, 30, 40};
int suma = 0;

for (int i = 0; i < numeros.length; i++) {
    suma = 0;               // ← bug
    suma += numeros[i];
}

System.out.println("Suma: " + suma);
Ver solución

El bug es que suma = 0; está dentro del for. En cada vuelta, se reinicia suma a 0, y después suma el elemento. Al final solo queda la suma del último elemento (40).

int suma = 0;

for (int i = 0; i < numeros.length; i++) {
    suma += numeros[i];   // sin reiniciar suma
}

System.out.println("Suma: " + suma);   // 100

Regla: el acumulador se inicializa antes del ciclo, no dentro. Dentro del ciclo, solo se actualiza. Es el mismo patrón que viste con acumuladores en el Bloque 3.

Construir

Escribe un programa que tenga un arreglo de 8 números y muestre:

  • La suma de todos
  • El promedio
  • Cuántos son mayores al promedio
Ver solución 
int[] numeros = {45, 12, 78, 33, 60, 91, 5, 52};

int suma = 0;

for (int i = 0; i < numeros.length; i++) {
    suma += numeros[i];
}

double promedio = (double) suma / numeros.length;

int mayoresAlPromedio = 0;

for (int i = 0; i < numeros.length; i++) {
    if (numeros[i] > promedio) {
        mayoresAlPromedio++;
    }
}

System.out.println("Suma: " + suma);
System.out.println("Promedio: " + promedio);
System.out.println("Mayores al promedio: " + mayoresAlPromedio);

Aquí se recorren dos veces: una para la suma, y otra para contar los mayores al promedio. Técnicamente, se puede hacer en un solo recorrido si se guarda primero la suma, después el promedio, después se recorre otra vez. Es lo mismo. La versión de dos recorridos es más clara; la de un recorrido es más eficiente pero más difícil de leer.

Combinar

Escribe un programa que tenga un arreglo de String con nombres, y cuente cuántos empiezan con una letra específica (por ejemplo, 'A').

Ver solución 
String[] nombres = {"Ana", "Luis", "Alberto", "María", "Andrés", "Pedro"};
char letraBuscada = 'A';
int contador = 0;

for (int i = 0; i < nombres.length; i++) {
    if (nombres[i].charAt(0) == letraBuscada) {
        contador++;
    }
}

System.out.println("Nombres que empiezan con '" + letraBuscada + "': " + contador);

Imprime 3 (Ana, Alberto, Andrés). El detalle clave es nombres[i].charAt(0): accede al primer carácter de cada String (que es la letra inicial). Fíjate en el uso de charAt, que ya viste brevemente. El índice 0 es la primera posición del String, igual que en los arreglos.

Crear

Escribe un programa que lea N números del usuario, los guarde en un arreglo, y después:

  • Los muestre en el orden en que se ingresaron.
  • Los muestre en orden inverso.
  • Muestre cuántos son positivos, cuántos negativos, y cuántos ceros.
Ver solución 
import java.util.Scanner;

public class AnalizarNumeros {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        System.out.print("¿Cuántos números? ");
        int n = Integer.parseInt(scanner.nextLine());

        int[] numeros = new int[n];

        for (int i = 0; i < n; i++) {
            System.out.print("Número " + (i + 1) + ": ");
            numeros[i] = Integer.parseInt(scanner.nextLine());
        }

        System.out.println("\nEn orden:");
        for (int i = 0; i < n; i++) {
            System.out.println(numeros[i]);
        }

        System.out.println("\nEn orden inverso:");
        for (int i = n - 1; i >= 0; i--) {
            System.out.println(numeros[i]);
        }

        int positivos = 0, negativos = 0, ceros = 0;

        for (int i = 0; i < n; i++) {
            if (numeros[i] > 0) positivos++;
            else if (numeros[i] < 0) negativos++;
            else ceros++;
        }

        System.out.println("\nPositivos: " + positivos);
        System.out.println("Negativos: " + negativos);
        System.out.println("Ceros: " + ceros);
    }
}

Fíjate en el segundo for, el del recorrido inverso: empieza en n - 1 (el último índice válido), va mientras i >= 0, y decrece con i--. Es el patrón de recorrido inverso que viste antes, aplicado a un arreglo creado con datos del usuario.

Proyecto integrador

Este es el proyecto más completo del manual hasta ahora. Combina todo lo que has aprendido: Scanner, arreglos, for, if, while, contadores, acumuladores, validación, y más.

Proyecto: sistema de calificaciones

Escribe un programa que:

  1. Pregunte al usuario cuántos estudiantes hay (entre 1 y 50, validado).
  2. Para cada estudiante, pida:
    • Nombre (puede tener espacios).
    • Calificación (número entre 0 y 100, validado).
  3. Almacene todos los nombres en un arreglo de String, y todas las calificaciones en un arreglo de double.
  4. Al final, muestre:
    • El listado completo (nombre y calificación).
    • El promedio del grupo.
    • La calificación más alta y quién la obtuvo.
    • La calificación más baja y quién la obtuvo.
    • Cuántos aprobaron (≥ 60) y cuántos reprobaron.
    • El nombre del estudiante con mejor calificación.

Requisitos técnicos:

  • Usa el patrón de Scanner del Bloque 5 (leer con nextLine, parsear cuando haga falta).
  • Valida los datos: la cantidad, las calificaciones. Si algo no es válido, pide de nuevo.
  • Usa dos arreglos paralelos (uno para nombres, otro para calificaciones), coordinados por el mismo índice.
  • Recorre los arreglos con for para hacer los cálculos.

Antes de escribir el código, haz el análisis en español. ¿Qué datos necesitas guardar? ¿Cómo validas cada uno? ¿Cuáles son los cálculos? Divide el problema en subproblemas, y después intégralos.

import java.util.Scanner;

public class SistemaCalificaciones {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        // 1. Cantidad de estudiantes (validada)
        int cantidad = 0;
        while (cantidad < 1 || cantidad > 50) {
            System.out.print("¿Cuántos estudiantes? (1-50): ");

            while (!scanner.hasNextInt()) {
                scanner.nextLine();
                System.out.print("Ingresa un número entero: ");
            }
            cantidad = scanner.nextInt();
            scanner.nextLine();

            if (cantidad < 1 || cantidad > 50) {
                System.out.println("Debe estar entre 1 y 50");
            }
        }

        // 2. Arreglos paralelos
        String[] nombres = new String[cantidad];
        double[] notas = new double[cantidad];

        // 3. Leer datos
        for (int i = 0; i < cantidad; i++) {
            System.out.println("\n--- Estudiante " + (i + 1) + " ---");

            System.out.print("Nombre: ");
            nombres[i] = scanner.nextLine().trim();

            double nota = -1;
            while (nota < 0 || nota > 100) {
                System.out.print("Calificación (0-100): ");

                while (!scanner.hasNextDouble()) {
                    scanner.nextLine();
                    System.out.print("Ingresa un número: ");
                }
                nota = scanner.nextDouble();
                scanner.nextLine();

                if (nota < 0 || nota > 100) {
                    System.out.println("La calificación debe estar entre 0 y 100");
                }
            }
            notas[i] = nota;
        }

        // 4. Cálculos
        double suma = 0;
        double mayor = notas[0];
        double menor = notas[0];
        int posMayor = 0;
        int posMenor = 0;
        int aprobados = 0;
        int reprobados = 0;

        for (int i = 0; i < cantidad; i++) {
            suma += notas[i];

            if (notas[i] > mayor) {
                mayor = notas[i];
                posMayor = i;
            }
            if (notas[i] < menor) {
                menor = notas[i];
                posMenor = i;
            }
            if (notas[i] >= 60) {
                aprobados++;
            } else {
                reprobados++;
            }
        }

        double promedio = suma / cantidad;

        // 5. Reporte
        System.out.println("\n========== REPORTE ==========");
        System.out.println("Listado de estudiantes:");
        for (int i = 0; i < cantidad; i++) {
            System.out.println("  " + nombres[i] + " - " + notas[i]);
        }

        System.out.println("\nEstadísticas:");
        System.out.println("  Cantidad: " + cantidad);
        System.out.println("  Promedio: " + promedio);
        System.out.println("  Mayor: " + mayor + " (" + nombres[posMayor] + ")");
        System.out.println("  Menor: " + menor + " (" + nombres[posMenor] + ")");
        System.out.println("  Aprobados: " + aprobados);
        System.out.println("  Reprobados: " + reprobados);
        System.out.println("  Mejor estudiante: " + nombres[posMayor]);
    }
}

Lo que sigue

Este es el bloque 6, y con él se cierra la primera parte del manual. Pero no es el final: es el punto donde termina el recorrido por las piezas básicas de la programación, y desde donde se puede empezar a construir más.
