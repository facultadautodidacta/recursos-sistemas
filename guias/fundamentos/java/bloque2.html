Decisiones en Java

Bloque 2 — if, else, else if y operadores lógicos

Hasta ahora tu programa hacía siempre lo mismo. Aquí empieza a decidir.

Bienvenida al Bloque 2

En el Bloque 1 construiste las piezas básicas: variables, tipos, mostrar cosas en pantalla, operadores, comparaciones, booleanos. Tu programa ya puede guardar datos y mostrarlos. Pero hasta ahora, siempre hace exactamente lo mismo sin importar qué datos tenga. Corre las mismas líneas en el mismo orden, siempre.

En este bloque vas a agregar la primera pieza que le permite a tu programa tomar decisiones: hacer una cosa si se cumple algo, y otra cosa si no. Esa pieza se llama if, y es probablemente la estructura más importante de todo el lenguaje. Todo lo que sigue —ciclos, arreglos, métodos— se apoya, de una u otra manera, en la idea de que el programa puede decidir.

Vamos a ir pieza por pieza. Primero if solo. Después else. Después else if. Y al final, cómo combinar varias condiciones a la vez. No vamos a meter todo junto de entrada. Si ves la sintaxis de un else if antes de haber entendido bien un if solo, la mesa se te llena y no avanzas. Vamos paso a paso.

Antes de cada estructura vas a leer una situación cotidiana, después un análisis en español, después la pieza de Java, después una simulación manual, después ejemplos, y solo al final ejercicios. Ese orden es el mismo en todo el manual. No lo saltes.

Vas a combinar piezas por primera vez (léelo antes de que pase)

Este es el primer bloque del manual en el que vas a juntar dos piezas que hasta ahora usabas por separado: una variable y una decisión. Hasta ahora, una variable guardaba un valor y ya. Hasta ahora, un programa ejecutaba todas las líneas en orden sin preguntar nada. A partir de aquí, una variable va a alimentar una decisión: el programa va a mirar el valor guardado y va a elegir qué hacer con él.

Es muy probable que cuando empieces a escribir tus primeros if que usen variables, sientas algo raro. Tal vez sientas que "se te olvidó" cómo declarar una variable, o que ya no recuerdas cómo se compara, o que se te enredan las llaves. Eso va a pasar. No lo digo como consuelo: lo digo porque es un fenómeno predecible y tiene explicación.

Cuando tu mente guarda dos ideas por separado, las tiene en dos lugares. Cuando necesita usarlas juntas, tiene que reacomodarlas para que encajen. Ese reacomodo se siente, durante un rato, como confusión. Como si hubieras retrocedido. Como si lo que ya sabías se hubiera desarmado. No se desarmó: está reordenándose para aceptar la pieza nueva.

Anticipa esto antes de que te pase

Si en los primeros ejercicios con if + variables sientes que "no entiendes nada" o que "se te olvidó todo", no es que hayas perdido el Bloque 1. Es el reacomodo. Sigue escribiendo. Sigue ejecutando. Sigue mirando qué pasa. En un par de días vuelve a sentirse claro —y cuando se aclare, vas a saber más que antes, no lo mismo.

Este manual vuelve a hablar de esto una vez más, más adelante. Aquí solo quería que lo leyeras antes de vivirlo, no después. Cuando te pase, vas a reconocerlo ("ah, esto es lo que me habían dicho"), en lugar de interpretarlo como una señal de que no sirves.

"Antes de programar": el hábito que hace la diferencia

Antes de empezar con if, quiero enseñarte un hábito que vas a usar durante todo el manual y, en realidad, durante toda tu vida programando. Se llama "Antes de programar", y consiste en lo siguiente:

Antes de escribir una sola línea de código, escribe en español qué quieres que pase. No cómo lo harías en Java. Qué quieres que pase. Como si se lo estuvieras explicando a alguien que no sabe programar.

Suena simple, pero cambia todo. Si no puedes describir en español qué tiene que hacer tu programa, no vas a poder escribirlo en Java. Y si puedes describirlo, escribir el Java se convierte en traducir, no en inventar.

Veamos un ejemplo. Supón que te piden: "haz un programa que diga si una persona es mayor de edad". Antes de abrir VSCode, escribes en español:

1. Necesito la edad de la persona. 2. Necesito saber si esa edad es mayor o igual a 18. 3. Si lo es, muestro "mayor de edad". 4. Si no lo es, no muestro nada (o muestro "menor de edad", ya veremos).

Eso es el análisis. Es más útil que cualquier fragmento de código, porque describe la intención. Una vez que tienes esto, Java se vuelve casi mecánico: buscar la pieza que corresponde a cada paso.

En cada estructura de este bloque y de los siguientes vamos a hacer esto juntos. Al principio te lo voy a mostrar yo; al final del bloque vas a hacerlo tú antes de cada ejercicio.

Regla del manual: si no puedes escribirlo en español, no intentes escribirlo en Java. Vuelve al español. Casi siempre el problema está ahí, no en la sintaxis.

El if: la pieza que hace que tu programa pregunte algo

Antes de Java (situación cotidiana)

Piensa en un semáforo. Cuando llegas a un cruce, miras el color. Si está en verde, cruzas. Si no está en verde, no cruzas. No "cruzas un poco". No "cruzas más o menos". Cruzas o no cruzas, según una condición que puedes verificar en el momento.

Piensa ahora en un cajero automático. Le pides 500 pesos. Antes de dártelos, el cajero mira tu saldo. Si tienes al menos 500, te los da. Si no, te muestra un mensaje diciendo que no alcanza. La decisión del cajero depende de una condición verificable: ¿tu saldo es mayor o igual a lo que pediste?

En ambos casos hay una estructura común: hay una condición, y una acción que se hace si esa condición es verdadera. Si la condición no es verdadera, la acción simplemente no se hace. Esa estructura es exactamente la del if.

La idea en español

Un if significa: "si se cumple esto, haz aquello". Nada más. La condición va entre paréntesis. La acción va entre llaves. Si la condición es verdadera (true), Java ejecuta lo que está entre llaves. Si es falsa (false), Java se salta todo lo que está entre llaves y sigue con la siguiente instrucción.

La nueva pieza

La sintaxis mínima de un if es esta:

if (condición) {
    // esto se ejecuta solo si la condición es true
}

Un ejemplo concreto:

int edad = 20;

if (edad >= 18) {
    System.out.println("Eres mayor de edad");
}

Lee eso en español: "si la edad es mayor o igual a 18, muestra 'Eres mayor de edad'". Si edad fuera 15, la condición 15 >= 18 daría false, y la línea del println no se ejecutaría. El programa terminaría sin mostrar nada.

Anatomía de un if

Vamos a nombrar cada parte, porque las vas a ver una y otra vez:

if (condición) {
    acciones
}
  • if — la palabra clave. Siempre en minúscula. Siempre seguida de un paréntesis.
  • (condición) — cualquier expresión que dé como resultado un boolean (ya viste cómo construirlas en el Bloque 1). Puede ser una comparación simple (edad >= 18) o una expresión lógica más compleja (edad >= 18 && tieneIdentificacion).
  • { ... } — las llaves encierran las acciones que se ejecutan solo si la condición es verdadera. Todo lo que esté entre las llaves forma el "cuerpo" del if.

Una nota sobre las llaves: si el cuerpo del if tiene una sola instrucción, técnicamente Java permite omitirlas. Pero no las omitas. Siempre llaves, incluso con una sola línea. Es una regla de estilo que te va a evitar errores cuando el cuerpo crezca, y que además hace que el código se lea más fácil. Los programadores experimentados casi siempre las ponen.

El flujo de ejecución, con un diagrama

┌─────────────────────────┐ │ evaluar la condición │ │ (edad >= 18) │ └───────────┬─────────────┘ │ ┌────────┴────────┐ │ │ true │ │ false ▼ ▼ ┌────────────────┐ ┌────────────────┐ │ ejecutar el │ │ saltar el │ │ cuerpo del if │ │ cuerpo del if │ └────────┬───────┘ └────────┬───────┘ │ │ └────────┬───────────┘ ▼ ┌────────────────┐ │ seguir con la │ │ siguiente │ │ instrucción │ └────────────────┘

No importa qué tan complicado sea el código dentro del if: el programa siempre evalúa primero la condición, y después va por uno de los dos caminos. Nunca por los dos.

Ejemplos progresivos con if

Cinco ejemplos que van subiendo de dificultad. El primero es casi el mismo que ya viste. El último combina varias cosas. Después de cada uno, pregúntate: ¿qué pasa si cambio este valor? ¿Qué pasa si lo pongo al límite exacto?

Ejemplo 1 — El más simple

Mostrar un mensaje si un número es positivo.

int n = 7;

if (n > 0) {
    System.out.println("El número es positivo");
}

Si n fuera -3, no se imprimiría nada. Si fuera 0, tampoco, porque 0 > 0 es false. Este último detalle importa: muchas veces el error está en el borde (¿es > o >=?). Siempre prueba los casos límite.

Ejemplo 2 — Comparación con texto

Saludar de forma especial si el usuario se llama "Ana".

String nombre = "Ana";

if (nombre.equals("Ana")) {
    System.out.println("¡Hola de nuevo, Ana!");
}

Recuerda del Bloque 1: para comparar texto se usa .equals(), no ==. Si escribieras nombre == "Ana", a veces funcionaría y a veces no, y no tendrías idea de por qué.

Ejemplo 3 — Condición con operador lógico

Permitir el acceso solo a mayores de edad con identificación.

int edad = 22;
boolean tieneIdentificacion = true;

if (edad >= 18 && tieneIdentificacion) {
    System.out.println("Acceso permitido");
}

La condición edad >= 18 && tieneIdentificacion es true solo si las dos partes son verdaderas. Si la edad es 22 pero no hay identificación, no entra. Si hay identificación pero la edad es 15, tampoco. Aunque no lo parezca, ya estás empezando a construir condiciones "reales", de las que se usan en programas de verdad.

Ejemplo 4 — if con varias instrucciones adentro

Si un número es par, mostrar dos mensajes diferentes.

int n = 8;

if (n % 2 == 0) {
    System.out.println("El número es par");
    System.out.println("Y además es divisible por 2");
}

Fíjate en la condición: n % 2 == 0. El % da el resto. Si el resto de dividir entre 2 es 0, el número es par. Este patrón se usa mucho y vale la pena reconocerlo de un vistazo.

Ejemplo 5 — Combinando todo lo del Bloque 1

Un programa que calcule el precio final de una compra aplicando un descuento del 10% solo si el total supera los 100.

double subtotal = 120.0;
double descuento = 0.10;
double total = subtotal;

if (subtotal > 100) {
    total = subtotal - (subtotal * descuento);
}

System.out.println("Total a pagar: " + total);

Hay algo importante en este ejemplo: total se declara antes del if con el valor de subtotal, y dentro del if se modifica. Si el if no se cumple, total conserva el valor original. Si se cumple, se aplica el descuento. Después del if, en ambos casos, total tiene un valor válido y se muestra.

Este patrón —declarar fuera, modificar dentro— va a aparecer constantemente en el manual. Reconocerlo ahora te va a ahorrar tiempo después.

Errores comunes con if

Estos son los errores que comete casi todo el mundo la primera vez. Léelos antes de escribir tus primeros if, no después. Así, cuando te aparezcan, los vas a reconocer.

1. Poner ; después del paréntesis del if

if (edad >= 18);   // ← ese ; es un error
{
    System.out.println("Mayor");
}

Ese punto y coma le dice a Java "el cuerpo del if es una instrucción vacía". Entonces el bloque de llaves de abajo se ejecuta siempre, sin importar la condición. Es un error muy silencioso: el código compila, corre, pero se comporta mal. Si tu if parece "no hacer nada", revisa si tiene un ; escondido después del paréntesis.

2. Usar = en vez de ==

if (edad = 18) {   // ← error: asignación, no comparación
    ...
}

Java espera un boolean entre los paréntesis del if. Una asignación no es un boolean. Así que este error sí lo detecta el compilador y el programa no arranca. Es una de las pocas bondades de Java sobre otros lenguajes: aquí el error se ve rápido.

3. Confundir la lógica con el orden de las palabras

// Quiero: "si la edad está entre 18 y 30"
if (18 <= edad <= 30) {   // ← error de sintaxis
    ...
}

Java no acepta comparaciones encadenadas como en matemáticas. Hay que partir la condición en dos y unirlas con &&:

if (edad >= 18 && edad <= 30) {
    ...
}

4. Olvidar las llaves y que solo una línea quede dentro

if (edad >= 18)
    System.out.println("Mayor");
    System.out.println("Puede votar");   // ← esto NO está dentro del if

Sin llaves, solo la primera línea después del if queda dentro. La segunda se ejecuta siempre. Este es el motivo por el que en este manual siempre usamos llaves: para no depender de la indentación, que es frágil y fácil de romper al mover líneas.

5. Creer que un if "no entró" cuando en realidad la condición era falsa

Esto no es un error de sintaxis, es un error de razonamiento. A veces uno escribe un if pensando que la condición va a dar true, y no entra. Antes de asumir que Java está mal, haz esto: muestra la condición por pantalla.

System.out.println("La condición vale: " + (edad >= 18));

if (edad >= 18) {
    ...
}

Este truco lo vas a usar cien veces. Cuando algo no se comporta como esperas, imprime la condición. Casi siempre descubres que el problema no estaba en el if, sino en el valor que creías que tenía la variable.

Si después de leer esto igual te atoras

Recuerda el protocolo del Bloque 1: nombra lo que sientes → pregúntate si es hecho o interpretación → busca la pieza específica → aísla esa pieza y revísala sola. Casi siempre el problema no está en "el if" entero, sino en una sola palabra del código: un ; de más, un = de menos, un .equals olvidado. Aísla esa línea y mírala sola.

Ejercicios de if

Como en el Bloque 1, hay seis niveles. Intenta cada uno antes de mirar la solución. Y cuando termines cada ejercicio, léelo mentalmente línea por línea, como hicimos en la simulación. Esa parte es tan importante como resolver el ejercicio.

Reconocer

Mira este fragmento. Sin ejecutarlo, dime si se imprime algo y qué.

int x = 10;

if (x > 5) {
    System.out.println("A");
}

if (x > 15) {
    System.out.println("B");
}
Ver solución

Solo se imprime A. La primera condición (10 > 5) es verdadera. La segunda (10 > 15) es falsa y el cuerpo se salta. Dos if separados son independientes: uno puede ejecutarse y el otro no, o los dos, o ninguno. No se excluyen mutuamente.

Completar

Completa la condición para que el mensaje se muestre solo cuando la temperatura sea mayor a 30.

int temperatura = 35;

if (_______________) {
    System.out.println("Hace calor");
}
Ver solución

temperatura > 30. También podrías haber escrito temperatura >= 31 si consideras que 31 ya es "calor", pero la consigna pedía "mayor a 30", así que la primera es la correcta. Fíjate en la diferencia entre > y >=: el borde importa.

Modificar

Este programa dice si una persona puede votar, pero solo si tiene exactamente 18 años. Cámbialo para que funcione con cualquier edad mayor o igual a 18.

int edad = 25;

if (edad == 18) {
    System.out.println("Puede votar");
}
Ver solución 
int edad = 25;

if (edad >= 18) {
    System.out.println("Puede votar");
}

Este es un ejemplo clarísimo de "error de borde". El código original no era inválido —compilaba y corría—, pero solo funcionaba para 18 exactos. Los errores de lógica no dan error de compilación: se descubren probando. Por eso en este manual vas a probar varios valores cada vez que escribas un if.

Construir

Escribe un programa que guarde en una variable un número y muestre "El número es divisible por 5" solo si lo es. Recuerda que el operador % te da el resto.

Ver una posible solución 
int n = 35;

if (n % 5 == 0) {
    System.out.println("El número es divisible por 5");
}

Prueba con n = 35 (debe imprimir), n = 12 (no debe imprimir), y n = 0 (técnicamente es divisible: 0 % 5 == 0, así que sí imprime). Los casos de borde como el 0 a veces revelan que tu lógica no cubre todo lo que creías.

Combinar

Escribe un programa que muestre "Apto para el descuento" solo si:

  • El cliente tiene más de 60 años, o
  • Es socio del club (una variable boolean).
Ver solución 
int edad = 45;
boolean esSocio = true;

if (edad > 60 || esSocio) {
    System.out.println("Apto para el descuento");
}

Usé || porque basta con una de las dos condiciones. Aquí sí importa entender la diferencia entre && y ||: si hubiera usado &&, solo se aplicaría el descuento a quienes cumplieran ambas cosas, y eso es otra regla distinta. Antes de escribir la condición, piensa en español qué quieres: "mayores de 60 O socios" → ||. "mayores de 60 Y socios" → &&.

Crear

Escribe un programa que, dado un año en una variable, determine si es bisiesto. Un año es bisiesto si es divisible por 4, excepto los que son divisibles por 100 pero no por 400.

Antes de escribir código, haz el análisis en español, como en la sección "Antes de programar":

Ver análisis y solución

Análisis en español:

  • Un año es bisiesto si (divisible por 4) Y (no divisible por 100, salvo si es divisible por 400).
  • Eso se puede escribir como: (año % 4 == 0) Y ((año % 100 != 0) O (año % 400 == 0))
int año = 2024;

if (año % 4 == 0 && (año % 100 != 0 || año % 400 == 0)) {
    System.out.println(año + " es bisiesto");
}

Fíjate en los paréntesis. Sin ellos, la precedencia cambiaría el significado completamente. Cuando tu condición tenga && y || mezclados, usa paréntesis. No es obligatorio, pero es una buena costumbre: no solo funciona igual, se lee mucho mejor, y te obliga a pensar bien qué estás diciendo.

else: y si no, entonces…

Antes de Java (situación cotidiana)

Volvamos al cajero. Si tienes saldo suficiente, te da el dinero. Si no tienes, te muestra un mensaje de error. No es que a veces no pase nada: siempre pasa una de las dos cosas. Una o la otra. Nunca las dos, nunca ninguna.

Eso es exactamente lo que agrega el else al if: un camino alternativo que se ejecuta cuando la condición del if es falsa. No es "otra cosa que también podría pasar". Es "lo que pasa cuando la condición no se cumplió".

La idea en español

"Si se cumple esto, haz A. Y si no, haz B." El else es "y si no". Su cuerpo se ejecuta exactamente cuando la condición del if fue falsa. Ni más ni menos.

La nueva pieza

if (condición) {
    // se ejecuta si la condición es true
} else {
    // se ejecuta si la condición es false
}

Un ejemplo concreto:

int edad = 15;

if (edad >= 18) {
    System.out.println("Eres mayor de edad");
} else {
    System.out.println("Eres menor de edad");
}

Con edad = 15, la condición es falsa, así que se ejecuta el bloque del else y se imprime "Eres menor de edad". Con edad = 20, la condición es verdadera, se ejecuta el bloque del if y el else se salta por completo.

Lo que else no es

Este es un malentendido muy común que conviene desarmar antes de que ocurra:

else no significa "lo contrario de la condición". Significa "cualquier caso en el que la condición fue falsa". La diferencia es sutil pero real, y se ve cuando la condición es compuesta.

Por ejemplo:

int edad = 17;
boolean tienePermiso = false;

if (edad >= 18 || tienePermiso) {
    System.out.println("Puede entrar");
} else {
    System.out.println("No puede entrar");
}

El else aquí no significa "tiene menos de 18 y no tiene permiso". Significa "no se cumplió la condición compuesta", que puede ser porque falló una parte, o las dos, o cualquier combinación. Es un error frecuente pensar que el else invierte cada condición individual. No lo hace: el else solo mira si la condición del if fue falsa como un todo.

Ejemplos progresivos con if / else

Ejemplo 1 — Par o impar

int n = 7;

if (n % 2 == 0) {
    System.out.println("Es par");
} else {
    System.out.println("Es impar");
}

Con n = 7, 7 % 2 da 1, así que la condición es falsa y va por el else. Con n = 8, 8 % 2 da 0, la condición es verdadera y va por el if.

Ejemplo 2 — Aprobado o reprobado

double calificacion = 5.8;

if (calificacion >= 6.0) {
    System.out.println("Aprobado");
} else {
    System.out.println("Reprobado");
}

Con 5.8, es reprobado. Con 6.0 exacto, aprueba (porque la condición es >=, no >). Aquí el borde importa muchísimo: un alumno con 5.99 reprueba, uno con 6.00 aprueba. Siempre piensa dónde quieres poner el límite.

Ejemplo 3 — Saludo personalizado con equals

String usuario = "admin";

if (usuario.equals("admin")) {
    System.out.println("Bienvenido, administrador");
} else {
    System.out.println("Bienvenido, usuario");
}

Recuerda: .equals para textos, no ==. Y ojo, .equals distingue mayúsculas: "Admin" no es igual a "admin". Si quisieras ignorar mayúsculas, existe .equalsIgnoreCase(), que ves aquí de paso pero no vamos a profundizar todavía.

Ejemplo 4 — Condición con operador lógico

int edad = 70;
boolean esSocio = false;

if (edad > 60 || esSocio) {
    System.out.println("Descuento aplicado");
} else {
    System.out.println("Sin descuento");
}

Con edad = 70, la primera parte de la condición es verdadera y entra al if. Fíjate en algo importante: aunque esSocio sea false, la condición completa es verdadera, porque usamos ||. Con || basta con que una parte sea verdadera.

Ejemplo 5 — Combinando variables y decisiones en un caso real

double saldo = 300.0;
double retiro = 500.0;

if (retiro <= saldo) {
    saldo = saldo - retiro;
    System.out.println("Retiro exitoso. Saldo restante: " + saldo);
} else {
    System.out.println("Fondos insuficientes. Saldo actual: " + saldo);
}

Con retiro = 500 y saldo = 300, la condición es falsa. Se imprime "Fondos insuficientes. Saldo actual: 300.0". Fíjate que saldo no cambió, porque la resta solo ocurre dentro del if, y no entró. Esta es la primera vez en el manual que ves un else con estado: la variable saldo termina con valores distintos según qué rama se haya ejecutado. Esa es la esencia de lo que hace útil a un if.

Errores comunes con else

1. Poner punto y coma antes de else

if (x > 0) {
    ...
};   // ← el ; después de la llave está mal
else {
    ...
}

El else tiene que ir inmediatamente después de la llave de cierre del if. Nada de punto y coma en medio. Java lo detecta como error de sintaxis, así que no es silencioso, pero pasa mucho.

2. Poner un else sin if

else {   // ← error: else siempre necesita un if antes
    ...
}

El else no existe solo. Siempre acompaña a un if. Si lo escribes sin uno arriba, Java se queja. Es la misma idea que "no puede haber un 'sino' sin un 'si' antes".

3. Creer que else invierte la condición

Ya lo mencionamos antes, pero vale repetirlo. Si tienes:

if (a > 0 && b > 0) {
    ...
} else {
    ...
}

el else no significa "a <= 0 o b <= 0". Significa "no se cumple (a > 0 && b > 0)", lo cual puede pasar por varias razones. Si necesitas razonar sobre qué pasa en el else, piensa en la condición completa negada, no en cada parte invertida.

4. Poner else if cuando bastaba con else

Si solo tienes dos casos posibles, else es lo correcto. Poner else if (condición contraria) funciona, pero es más código de lo necesario y más propenso a errores:

// Funciona, pero es innecesario
if (edad >= 18) {
    System.out.println("Mayor");
} else if (edad < 18) {
    System.out.println("Menor");
}

// Mejor
if (edad >= 18) {
    System.out.println("Mayor");
} else {
    System.out.println("Menor");
}

La segunda versión es más clara. Cuando solo hay dos caminos, el else es tu amigo. El else if lo vas a usar cuando haya tres o más posibilidades, en la siguiente sección.

5. Anidar innecesariamente cuando else if era mejor

Esto se va a ver clarísimo cuando lleguemos a else if. Por ahora quédate con la idea: si te encuentras escribiendo un else que dentro tiene otro if, probablemente puedas usar else if y ahorrarte un nivel de indentación.

else if: cuando hay más de dos caminos

Antes de Java (situación cotidiana)

Piensa en un sistema de calificaciones: 9 o más es "excelente", 7 u 8 es "bien", 5 o 6 es "suficiente", menos de 5 es "insuficiente". No son dos caminos, son cuatro. Cada uno excluye a los demás: una calificación no puede ser a la vez "bien" y "suficiente".

Con lo que sabes hasta ahora, podrías escribirlo con if y else anidados, pero como acabaste de ver, se va hacia la derecha y se vuelve difícil de leer. Java tiene una forma más directa para esta situación: else if.

La idea en español

"Si se cumple A, haz esto. Y si no, pero se cumple B, haz esto otro. Y si no, pero se cumple C, haz esto otro. Y si no se cumple nada, haz esto último."

Es una cadena. Java va probando condiciones en orden, y se detiene en la primera que sea verdadera. Las siguientes ya no las evalúa.

La nueva pieza

if (condición1) {
    // se ejecuta si condición1 es true
} else if (condición2) {
    // se ejecuta si condición1 es false Y condición2 es true
} else if (condición3) {
    // se ejecuta si las anteriores fueron false Y condición3 es true
} else {
    // se ejecuta si todas las anteriores fueron false
}

Un ejemplo con las calificaciones:

int nota = 8;

if (nota >= 9) {
    System.out.println("Excelente");
} else if (nota >= 7) {
    System.out.println("Bien");
} else if (nota >= 5) {
    System.out.println("Suficiente");
} else {
    System.out.println("Insuficiente");
}

Con nota = 8: se evalúa la primera condición (8 >= 9), es falsa. Se pasa a la segunda (8 >= 7), es verdadera. Se ejecuta "Bien" y se ignora el resto de la cadena. Nunca se llega a evaluar la condición nota >= 5, aunque también sería verdadera. Esto es fundamental entenderlo.

El orden importa (muchísimo)

Cuando usas else if, el orden de las condiciones cambia el comportamiento. Si en el ejemplo anterior pusieras primero nota >= 5 y después nota >= 9, todas las notas mayores o iguales a 5 caerían en la primera rama, y las notas altas nunca llegarían a la rama "Excelente". Porque cuando Java encuentra la primera condición verdadera, ya no sigue revisando.

// ESTO ESTÁ MAL (orden incorrecto)
if (nota >= 5) {
    System.out.println("Suficiente");   // se ejecuta también con nota 10
} else if (nota >= 7) {
    System.out.println("Bien");        // nunca se llega
} else if (nota >= 9) {
    System.out.println("Excelente");   // nunca se llega
}

Regla práctica: cuando las condiciones son rangos del mismo dato, pon las más restrictivas primero. O piensa en "qué es más específico" y ordénalo de más a menos específico.

Simulación: cómo se recorren las ramas

Esta es la parte más importante de la sección. Vamos a ejecutar paso a paso el ejemplo de las calificaciones, con tres valores distintos, para que veas exactamente cómo se recorre la cadena.

Caso 1: nota = 10

Salida: Excelente.

Caso 2: nota = 7

—El resto no se evalúa—

Detente un momento y piensa

La idea central: una cadena de else if para en la primera condición verdadera. Todas las siguientes, aunque también fueran verdaderas, se ignoran. Por eso el orden importa, y por eso hay que pensar bien en qué orden van las condiciones.

Ejemplos progresivos con else if

Ejemplo 1 — Categorías por edad

    System.out.println("Niño");
} else if (edad < 18) {
    System.out.println("Adolescente");
} else if (edad < 65) {
    System.out.println("Adulto");
} else {
    System.out.println("Adulto mayor");
}

Con edad = 30 → "Adulto". Con edad = 12 → "Niño". Con edad = 70 → "Adulto mayor". Fíjate que las condiciones van en orden creciente de edad, pero cada una sola compara contra un límite. Java no necesita saber que la anterior fue falsa para evaluar la siguiente —el else if ya garantiza que solo se llega aquí si las anteriores fueron falsas.

Ejemplo 2 — Clasificación de temperatura

int temp = 15;

if (temp < 0) {
    System.out.println("Bajo cero");
} else if (temp < 10) {

} else if (temp < 25) {
    System.out.println("Templado");
} else {
    System.out.println("Caluroso");
}

Con 15 → "Templado". Con 30 → "Caluroso". Con -5 → "Bajo cero". Nota cómo las condiciones cubren rangos sin necesitar comparaciones dobles: temp < 10 después de temp < 0 cubre el rango 0-9, porque ya sabemos que no cayó en "menos de 0".

Ejemplo 3 — Clasificación de IMC (parcial)

double peso = 70.0;
double altura = 1.75;

System.out.println("Tu IMC es: " + imc);

if (imc < 18.5) {

}

Este ejemplo combina varias piezas del Bloque 1: variables, cálculo, concatenación, y ahora decisiones. Es exactamente el tipo de programa que ya puedes escribir sin ayuda. Si te sientes cómodo escribiendo esto de cero, vas bien.

Ejemplo 4 — Descuentos por monto

double compra = 250.0;

    descuento = 0.20;
} else if (compra >= 200) {
    descuento = 0.10;

String tipoCliente = "VIP";

En un programa real, ese else probablemente termine el programa o pida datos de nuevo. Por ahora basta con que muestre el aviso.

Errores comunes con else if

1. Orden incorrecto de las condiciones

Ya lo mencionamos, pero es el error más frecuente con else if. Si pones las condiciones más amplias primero, las más específicas nunca se van a evaluar. El caso clásico: poner >= 5 antes que >= 9 en el ejemplo de las calificaciones.

Regla: condiciones específicas primero, o de lo más restrictivo a lo más amplio.

2. Poner un else entre medio de la cadena

if (a > 10) {
    ...
} else {                 // ← esto no debería ir aquí si quieres seguir con else if
    ...
} else if (b > 5) {       // ← error: ya terminó la cadena
    ...
}

El else cierra la cadena. Después de un else, ya no puede venir un else if. Si lo intentas, Java te da error. Las cadenas de else if terminan con un else final, o simplemente terminan sin nada más.

3. Repetir la condición del if dentro del else if

// Está mal, es redundante
if (x < 10) {
    ...
} else if (x >= 10) {   // ← esta condición siempre es verdadera aquí
    ...
}

Cuando escribes un else if, ya sabes que la condición anterior fue falsa. No hace falta que la vuelvas a verificar. Basta con comparar contra el siguiente límite. En este ejemplo, la segunda condición siempre va a ser verdadera (porque si x no es menor que 10, entonces x >= 10 seguro), así que podría ser simplemente un else.

4. Creer que todos los if se evalúan

Este es el error de razonamiento más importante de la sección. Una cadena de else if no es un conjunto de if independientes. Es una cadena: en cuanto una condición se cumple, las demás se ignoran. Si quieres que varias condiciones se evalúen, y que varias ramas puedan ejecutarse, tienes que usar if separados, no else if.

// Con else if: SOLO UNA rama se ejecuta
if (a > 0) { System.out.println("A"); }
else if (b > 0) { System.out.println("B"); }

// Con if separados: VARIAS pueden ejecutarse
if (a > 0) { System.out.println("A"); }
if (b > 0) { System.out.println("B"); }

Si a = 5 y b = 5: el primer bloque imprime solo "A", el segundo imprime "A" y "B". Dos formas válidas para problemas distintos. La pregunta "¿quiero que solo una se ejecute, o que se puedan ejecutar varias?" te dice cuál usar.

Crear

Escribe un programa que, dado un mes en una variable int mes (1 a 12), diga cuántos días tiene. Ten en cuenta que febrero tiene 28 o 29 días según el año. Asume que tienes dos variables: mes y año. Usa la regla de bisiesto que viste en la sección de if.

System.out.println("El mes " + mes + " tiene " + dias + " días");

Aparecen dos cosas nuevas aquí: el operador ternario condición ? valorSiTrue : valorSiFalse, y el uso de || para agrupar varios meses en una sola condición. Siempre prefiere la versión que entiendas. El código más corto no siempre es el mejor: el mejor es el que tú puedes leer y explicar.

Si te hubieran mostrado todo esto en una sola sesión, la mesa se te habría llenado y no hubieras podido sostener nada.

Esta es la segunda vez en el manual que aparece la idea que viste en la introducción. Va a volver una tercera vez, cerca del final, cuando termines los arreglos. Cada vez que la ves, va con una lista de piezas más larga. Y eso es, en el fondo, la respuesta a la pregunta que sí sirve: ¿qué piezas me faltan construir? Cada vez menos. Cada vez más complejas. Pero todas se construyen igual: una, después de otra, con práctica.

Si en este punto sientes que las decisiones "ya no te dan miedo", ese es el resultado concreto de haber construido piezas. Y si todavía te dan miedo, no pasa nada: vuelve a los ejercicios de if sin else, resuélvelos otra vez, y después vuelve a intentar else if. Nada de lo que has hecho está "perdido".

Operadores lógicos aplicados

Ya viste los operadores &&, || y ! en el Bloque 1, cuando hablamos de valores booleanos. En esa sección eran piezas sueltas. Aquí se convierten en herramientas reales: van a ser la forma de escribir condiciones complejas dentro de un if.

Antes de Java (situación cotidiana)

Imagina una puerta con dos cerraduras. Necesitas abrir las dos para entrar. Eso es &&: ambas condiciones deben cumplirse. Ahora imagina una puerta con dos cerraduras donde basta con abrir una. Eso es ||. Y ahora imagina una alarma que suena cuando NO hay nadie en casa. Eso es !.

La idea en español

  • A && B es verdadero solo si ambas son verdaderas. Si una sola es falsa, todo es falso.
  • A || B es verdadero si al menos una es verdadera. Solo es falso si las dos son falsas.
  • !A invierte: si A es true, !A es false, y viceversa.

Estas tres reglas son simples pero muy fáciles de confundir cuando las condiciones se vuelven largas. La clave es irlas leyendo como en español, parte por parte.

Ejemplos de cada uno dentro de un if

// &&: ambas condiciones deben cumplirse
if (edad >= 18 && tieneIdentificacion) {
    System.out.println("Puede entrar");
}

// ||: basta con una
if (esEstudiante || esProfesor) {
    System.out.println("Acceso al campus");
}

// !: negación
if (!estaBloqueado) {
    System.out.println("Puede intentar iniciar sesión");
}

Negar una condición compuesta

Cuando quieras negar una condición compuesta, conviene saber las leyes de De Morgan, que son dos reglas sencillas:

  • !(A && B) es lo mismo que !A || !B
  • !(A || B) es lo mismo que !A && !B

No hace falta memorizarlas. Lo que importa es entender la idea: negar una condición compuesta cambia también el operador interno. Cuando tengas una condición larga con ! afuera, piensa primero en español qué estás negando, y después escribe la negación.

// "Si NO es cierto que (edad >= 18 Y tiene identificación)"
// es lo mismo que "si edad < 18 O no tiene identificación"

if (!(edad >= 18 && tieneIdentificacion)) { ... }

// es equivalente a

if (edad < 18 || !tieneIdentificacion) { ... }

Las dos formas dan el mismo resultado. La primera se lee "no es cierto que ambas cosas sean verdaderas", la segunda "o la edad es menor, o no tiene identificación". Para el caso de arriba, la segunda suele ser más fácil de razonar.

Cómo los evalúa Java (cortocircuito)

Esta es una parte que sorprende a mucha gente y conviene entenderla bien: && y || en Java no evalúan siempre ambos lados. Esto se llama cortocircuito (short-circuit), y funciona así:

  • En A && B, si A es false, Java ya no evalúa B. Total, el resultado va a ser false de todas formas, así que se ahorra el trabajo.
  • En A || B, si A es true, Java ya no evalúa B. Total, el resultado ya es true.

Esto suena a optimización, y lo es. Pero también importa por otra razón: si B tuviera un efecto secundario (por ejemplo, modificar una variable, o hacer una llamada a un método), ese efecto no ocurriría si Java se salta la evaluación. Vas a ver esto más claro cuando llegues a métodos, pero por ahora vale con saber que && y || pueden "cortar" la evaluación antes de tiempo.

Un caso muy común donde esto importa: evitar errores al comparar con posibles valores nulos o al acceder a índices que podrían no existir. Es lo que se llama un guarda: poner la condición más propensa a fallar después del &&, para que no se evalúe si la primera ya dijo "no".

// Supón que no estamos seguros de si "usuario" puede ser null
// Este orden protege contra un error:
if (usuario != null && usuario.equals("admin")) {
    ...
}

// Este orden puede dar error si usuario es null:
if (usuario.equals("admin") && usuario != null) {
    ...
}

En el primer caso, si usuario es null, Java ve usuario != null, da false, y ya no evalúa usuario.equals("admin"). Evita un error. En el segundo caso, Java primero evalúa usuario.equals("admin"), y si usuario es null, eso lanza un error antes de llegar a la segunda parte. El orden importa cuando hay condiciones que pueden fallar.

No te preocupes si el concepto de null todavía no te es familiar: va a aparecer más adelante. Lo que quiero que te lleves ahora es la idea del cortocircuito. Es una de esas cosas que uno aprende mejor cuando le pasa, no cuando las lee. Pero al menos ahora sabrás que existen.

Ejemplos progresivos con operadores lógicos

Ejemplo 1 — Rango con &&

int edad = 25;

if (edad >= 18 && edad <= 30) {
    System.out.println("Edad entre 18 y 30");
}

El caso clásico de rango. La condición se lee en español así: "mayor o igual a 18 Y menor o igual a 30". Los dos límites incluidos, porque usamos >= y <=. Si quisiéramos excluir un límite, cambiaríamos a > o <.

Ejemplo 2 — Descuento por cumplir una de dos condiciones

int edad = 68;
boolean esSocio = false;

if (edad > 65 || esSocio) {
    System.out.println("Descuento aplicado");
} else {
    System.out.println("Sin descuento");
}

Aquí la lógica en español es: "mayor de 65 O socio". Basta con una. La diferencia entre && y || no es solo sintáctica: cambia por completo a quién se le aplica el descuento. Este es un buen ejemplo para pensar cómo se escribe la misma regla con el operador contrario, y qué pasaría.

Ejemplo 3 — Negación de un booleano

boolean sistemaBloqueado = false;

if (!sistemaBloqueado) {
    System.out.println("Acceso permitido");
}

Fíjate en la diferencia de estilo. Podrías escribir if (sistemaBloqueado == false), pero se considera redundante: si sistemaBloqueado ya es un boolean, basta con negarlo con !. La forma == false funciona, pero es ruido. Los programadores experimentados la evitan.

Ejemplo 4 — Condición con texto y número

String rol = "admin";
int intentos = 0;

if (rol.equals("admin") && intentos < 3) {
    System.out.println("Acceso concedido");
} else {
    System.out.println("Acceso denegado");
}

Aquí combinamos una comparación de texto (con .equals) y una comparación numérica. Es exactamente lo que se hace en un sistema de login real: se verifica que el rol sea el correcto Y que no se haya pasado del límite de intentos. Ambas condiciones deben cumplirse, por eso &&.

Ejemplo 5 — Combinación con paréntesis y negación

int edad = 20;
boolean tieneIdentificacion = true;
boolean estaEnListaNegra = false;

if (edad >= 18 && (tieneIdentificacion || !estaEnListaNegra)) {
    System.out.println("Puede pasar");
} else {
    System.out.println("No puede pasar");
}

Aquí hay dos cosas importantes. Primero, los paréntesis alrededor de (tieneIdentificacion || !estaEnListaNegra) son indispensables: sin ellos, Java evaluaría && antes que || (por precedencia) y el resultado sería distinto. Segundo, esta condición se puede leer en español: "si es mayor de edad Y (tiene identificación o no está en la lista negra)". Cuando una condición es compleja, léela en español primero, y después verifica que el código diga lo mismo.

Detente un momento y piensa

Con los valores del ejemplo, ¿qué imprime? Y si cambiaras estaEnListaNegra a true y tieneIdentificacion a false, ¿qué imprimiría? La primera parte de la condición (mayor de edad) sigue siendo verdadera, pero la segunda (identificación o no en lista negra) pasa a ser (false || false), o sea false. Entonces la condición completa es true && false = false. Imprime "No puede pasar". Antes de leer esto, deberías haberlo predicho.

Errores comunes con operadores lógicos

1. Usar && cuando querías || (y viceversa)

El error más común. La causa casi siempre es que no pensaste bien la regla en español. Truco: antes de escribir la condición, di en voz alta qué quieres:

  • "Debe cumplir A y B" → &&
  • "Debe cumplir A o B" → ||

Si tienes problemas para decidir, prueba mentalmente un caso que cumpla solo una de las dos condiciones. ¿Debería entrar? Si sí, ||. Si no, &&. Casi siempre la respuesta se vuelve obvia con un ejemplo concreto.

2. Olvidar los paréntesis cuando se mezclan

// ¿Qué significa esta condición?
if (a > 0 || b > 0 && c > 0) { ... }

// Java la interpreta así (por precedencia de && sobre ||):
if (a > 0 || (b > 0 && c > 0)) { ... }

// Pero ¿quizás lo que querías era esto otro?
if ((a > 0 || b > 0) && c > 0) { ... }

&& tiene mayor precedencia que ||. Es decir, se evalúa primero. Esto es correcto pero peligroso, porque quien lee el código no siempre lo recuerda. Siempre pon paréntesis cuando mezcles && y ||. No porque sea obligatorio, sino porque hace que el código diga exactamente lo que quieres y cualquiera lo lea bien.

3. Usar ! al inicio cuando querías comparar

// Esto dice: "si NO es cierto que x es igual a 5"
if (!(x == 5)) { ... }

// Esto también dice lo mismo, pero más claro:
if (x != 5) { ... }

Siempre prefiere la forma más directa. La primera versión funciona, pero requiere que quien la lea entienda la doble negación. La segunda se lee sin esfuerzo. Claridad sobre elegancia: el código no tiene que verse complicado para ser bueno.

4. Confundir cortocircuito con "Java evalúa todo"

Ya lo vimos en la sección de cortocircuito, pero es un error que sorprende a muchos principiantes cuando empiezan a escribir funciones con efectos secundarios. Por ahora solo asegúrate de recordar que && y || pueden no evaluar el segundo lado. Eso va a importar más adelante.

Ejercicios con operadores lógicos

Reconocer

Con a = 5, b = 10, c = 0, ¿cuál es el valor de cada expresión?

a > 0 && b > 0
a > 0 || c > 0
!(a > 0)
a > 0 && c > 0
a > 0 || c > 0 && b > 0
Ver respuestas
  • true — ambas partes son verdaderas.
  • true — a > 0 es verdadero, con || basta.
  • false — niega un verdadero.
  • false — c > 0 es falso, con && todo es falso.
  • true — por precedencia es a > 0 || (c > 0 && b > 0) = true || (false && true) = true || false = true. Fíjate en cómo se complica cuando no hay paréntesis: leer esto sin saber la precedencia es una trampa.

Completar

Completa la condición para que el mensaje se muestre a personas entre 18 y 65 años (ambos inclusive).

int edad = 40;

if (_______________) {
    System.out.println("En rango de edad laboral");
}
Ver solución

edad >= 18 && edad <= 65. Los dos límites incluidos, por eso >= y <=.

Modificar

Este programa debería mostrar el mensaje a menores de 18 o mayores de 65, pero no lo hace. Encuentra el error y arréglalo.

int edad = 70;

if (edad < 18 && edad > 65) {
    System.out.println("Tarifa reducida");
}
Ver solución

Dos errores: debería ser || en lugar de &&, y las condiciones están invertidas respecto a los operadores. La versión correcta:

if (edad < 18 || edad > 65) {
    System.out.println("Tarifa reducida");
}

El error original era &&: con &&, se requiere que ambas condiciones sean verdaderas, y eso es imposible (nadie es a la vez menor de 18 y mayor de 65). El cuerpo nunca se ejecutaba. Este tipo de error —una condición lógicamente imposible— es una señal clásica de que confundiste && con ||. Cuando un if "nunca entra" sin importar qué valores pruebes, sospecha de esto.

Construir

Escribe un programa que determine si una persona puede obtener una licencia de conducir. Los requisitos son:

  • Tener al menos 18 años.
  • Haber aprobado el examen teórico (variable boolean).
  • Haber aprobado el examen práctico (variable boolean).

Si cumple todo, mostrar "Licencia otorgada". Si no, mostrar qué requisito falta (al menos uno).

Ver solución 
int edad = 20;
boolean aprobóTeórico = true;
boolean aprobóPráctico = false;

if (edad >= 18 && aprobóTeórico && aprobóPráctico) {
    System.out.println("Licencia otorgada");
} else if (edad < 18) {
    System.out.println("Falta: ser mayor de edad");
} else if (!aprobóTeórico) {
    System.out.println("Falta: aprobar el examen teórico");
} else {
    System.out.println("Falta: aprobar el examen práctico");
}

Fíjate en dos cosas. Primero, la condición principal usa tres &&: todas deben cumplirse. Segundo, el else final no necesita condición: si llegamos ahí, es porque las anteriores fueron falsas, y la única que queda es que aprobóPráctico sea falso. Aprovechar esa información implícita es una de las cosas que separa a quien escribe mucho código de quien escribe buen código.

Combinar

Escribe un programa que valide si un año (variable int) es bisiesto, pero ahora con más requisitos adicionales: el año debe estar entre 1900 y 2100, y no debe ser múltiplo de 100 salvo que sea de 400. Muestra "Bisiesto", "No bisiesto" o "Año fuera de rango" según corresponda.

Ver solución 
int año = 2024;

if (año < 1900 || año > 2100) {
    System.out.println("Año fuera de rango");
} else if ((año % 4 == 0) && ((año % 100 != 0) || (año % 400 == 0))) {
    System.out.println("Bisiesto");
} else {
    System.out.println("No bisiesto");
}

Fíjate en el orden: primero verificamos que el año esté en rango, y solo después nos preocupamos por bisiesto. Esa es una regla muy útil: valida primero lo básico y solo después lo específico. Si el año está fuera de rango, no tiene sentido verificar si es bisiesto. Y fíjate también en cómo los paréntesis hacen legible la condición larga. Sin ellos, sería una sopa difícil de revisar.

Crear

Escribe un programa que determine si un usuario puede hacer una compra en línea. Reglas:

  • Debe estar registrado.
  • Debe tener tarjeta válida, o tener saldo en la cuenta virtual.
  • No debe estar bloqueado.
  • El monto de la compra no debe superar el límite (digamos, 5000).

Muestra "Compra aprobada" o, si no, un mensaje específico sobre qué falta.

Ver una posible solución 
boolean registrado = true;
boolean tarjetaValida = false;
boolean tieneSaldo = true;
boolean bloqueado = false;
double monto = 1200.0;
double limite = 5000.0;

if (!registrado) {
    System.out.println("Debes registrarte primero");
} else if (bloqueado) {
    System.out.println("Tu cuenta está bloqueada");
} else if (monto > limite) {
    System.out.println("El monto supera tu límite");
} else if (!(tarjetaValida || tieneSaldo)) {
    System.out.println("Necesitas tarjeta válida o saldo disponible");
} else {
    System.out.println("Compra aprobada");
}

Hay una decisión interesante aquí: ¿en qué orden pongo los chequeos? Cualquier orden funciona, pero algunos son más útiles. Por ejemplo, verificar primero si el usuario ni siquiera está registrado probablemente es mejor que verificar el monto primero: si no está registrado, ni siquiera tiene sentido hablarle del monto. Aprender a decidir el orden de las validaciones es parte del oficio. Y fíjate en !(tarjetaValida || tieneSaldo): negar un || equivale (por De Morgan) a !tarjetaValida && !tieneSaldo. Las dos formas funcionan; prefiere la que se lea más cerca del español.

Un if dentro de otro

Ya mencioné varias veces los if anidados, pero no los hemos visto en detalle. Vale la pena dedicarles un apartado porque, aunque en teoría son simples, en la práctica se vuelven la fuente número uno de confusión cuando el código crece.

Un if anidado es simplemente un if que está dentro de otro if. Sucede cuando la decisión de "hacer algo" depende de dos condiciones que no se pueden combinar con un simple &&, o que se leen mejor por separado.

if (usuarioRegistrado) {
    if (contraseñaCorrecta) {
        System.out.println("Bienvenido");
    } else {
        System.out.println("Contraseña incorrecta");
    }
} else {
    System.out.println("Usuario no encontrado");
}

Este programa muestra tres mensajes distintos según el caso. Si lo hubieras escrito con &&, no podrías distinguir "usuario no registrado" de "contraseña incorrecta": ambos casos son "no se cumple". Los anidados te permiten descomponer una decisión en pasos, cada uno mostrando un mensaje específico.

Cuándo usar anidados (y cuándo no)

Los if anidados son útiles cuando quieres distinguir distintos motivos de fracaso, o cuando una decisión solo tiene sentido si la anterior se cumplió. Pero se vuelven difíciles de leer si pasas de dos o tres niveles. Regla práctica:

  • Más de 3 niveles de anidado: probablemente puedas reescribirlo con else if, o extrayendo el bloque interno a un método (lo verás más adelante).
  • Si puedes combinar las condiciones con && o || sin perder claridad: prefiere eso.
  • Si el anidado te permite dar mensajes más específicos: vale la pena, aunque agregues niveles.

Los anidados se vuelven indispensables cuando llegues a ciclos (Bloque 3), porque vas a querer tomar decisiones dentro de una repetición, y esas decisiones a veces tendrán sus propias decisiones. Por ahora solo reconócelos, y aprende a leerlos.

Cómo leer un if anidado

Lee siempre de afuera hacia adentro, y en cada nivel pregúntate: ¿este if es verdadero o falso en este caso? Después entra (o no) al siguiente nivel.

nivel 1: ¿usuarioRegistrado? ├── true ──► nivel 2: ¿contraseñaCorrecta? │ ├── true ──► "Bienvenido" │ └── false ─► "Contraseña incorrecta" └── false ─► "Usuario no encontrado"

Es útil dibujarlo así cuando tienes anidados, porque te obliga a considerar todos los caminos posibles. Muchos errores de lógica se detectan simplemente dibujando el árbol: aparecen ramas que nunca se ejecutan, o casos que se te olvidó cubrir.

Reto: cajero automático

Escribe un programa que simule un cajero. Tienes las siguientes variables ya definidas:

double saldo = 1500.0;
boolean tarjetaValida = true;
int intentosFallidos = 0;
double montoARetirar = 800.0;

El programa debe mostrar por pantalla uno de estos mensajes, según el caso:

  • "Tarjeta no válida" — si tarjetaValida es false.
  • "Tarjeta bloqueada. Contacta a tu banco" — si intentosFallidos es mayor o igual a 3.
  • "El monto debe ser múltiplo de 100" — si montoARetirar no es múltiplo de 100.
  • "Saldo insuficiente" — si el monto es mayor al saldo.
  • "Retiro exitoso. Nuevo saldo: X" — si todo está bien. (No te preocupes por modificar saldo, solo mostrar el mensaje.)

Intenta resolverlo antes de mirar la solución. Y cuando lo hayas escrito, pruébalo con distintos valores:

  • tarjetaValida = false
  • intentosFallidos = 3
  • montoARetirar = 850 (no múltiplo de 100)
  • montoARetirar = 5000 (más que el saldo)
  • Todo bien con montoARetirar = 500
Ver solución 
if (!tarjetaValida) {
    System.out.println("Tarjeta no válida");
} else if (intentosFallidos >= 3) {
    System.out.println("Tarjeta bloqueada. Contacta a tu banco");
} else if (montoARetirar % 100 != 0) {
    System.out.println("El monto debe ser múltiplo de 100");
} else if (montoARetirar > saldo) {
    System.out.println("Saldo insuficiente");
} else {
    double nuevoSaldo = saldo - montoARetirar;
    System.out.println("Retiro exitoso. Nuevo saldo: " + nuevoSaldo);
}

Fíjate en el orden que elegí: primero valido lo más "externo" (¿la tarjeta funciona? ¿no está bloqueada?), y después lo específico (¿el monto es válido? ¿hay saldo suficiente?). Si hubiera puesto primero montoARetirar > saldo, un usuario con tarjeta inválida escucharía "saldo insuficiente", que es técnicamente cierto pero no dice la verdadera razón. El orden de las validaciones comunica información. Pon las más generales primero, y las más específicas al final, para que el usuario reciba el mensaje que corresponde al problema real.
